Bootstrap plugin planning documents for milestones, tool resolution, and stable-channel design.

This is the planning home for the bootstrap plugin, the engine that installs and configures the plugin set at every session start. It holds one running milestone log plus design documents for the two long-running workstreams: how bootstrap finds, resolves, and records external tools, and the stable-channel proposal for version updates. Designs here are written ahead of, or alongside, implementation, so a document may describe shipped behavior, in-flight work, or a proposal not yet built. The milestone log records state and discoveries as they happened; each workstream carries its own design document, and the tool workstream adds a status document for the in-flight publish. Everything is maintained prose, nothing is generated.

Where to start

Open MILESTONES.md for the shipped state: milestones 1 to 4 and 6 in file order, the capability audit last, with the 25-test baseline and the open manual verifications. If you are resuming the in-flight tool work, start at path-reachability-STATUS.md instead; its publish-resume checklist says what is committed, what has not reached master, and what is left.

Routes

  • Tool resolution, in the order it happened: tool-resolution-redesign.md (recorded absolute paths replace PATH lookups) -> path-reachability-check.md (a tool on disk but off PATH counts as installed; names the redesign as the larger separate work) -> path-reachability-STATUS.md (what shipped, and the publish-resume checklist).
  • Stable channel, from its precondition: MILESTONES.md (milestone 6: bootstrap manages marketplaces and plugins through the CLI) -> stable-channel-design.md (the proposal built on bootstrap as the sole updater, qualifying versions by age or explicit flag).

Milestone record

  • MILESTONES.md - The running log: the plugin foundation, the test-plugin port, the local-review-kit and unreal-kit ports, the update01 marketplace seed, marketplace and plugin lifecycle through the CLI, and the capability audit that closed all seven gaps. Open it for the state of a feature or the deficiencies a milestone found along the way.

Tool resolution workstream

  • tool-resolution-redesign.md - The design contract for recording absolute tool paths during bootstrap so plugins stop depending on PATH lookups; phases 1 to 3 are marked shipped, with the open items at the end.
  • path-reachability-check.md - The design that makes a tool present on disk but absent from PATH count as installed: a list-form installPath field, an optional check command, and the engine linking the tool's directory onto PATH itself, with no restart asked of the user.
  • path-reachability-STATUS.md - Status and resume document for that work: the changed files, the eight pre-existing suite failures proven unrelated, the interleaved WIP not to touch, and the publish-resume checklist from dev-tree check through master merge and the downstream re-lock.

Stable channel

  • stable-channel-design.md - The design proposal, not yet implemented, for a per-plugin stable channel: an append-only publish ledger as the data plane, consumer-side qualification by age or explicit flag, and bootstrap as the sole updater in place of the per-marketplace auto-update. Open it before changing update cadence or the ledger it would add.
