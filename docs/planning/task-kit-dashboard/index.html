The planning documents for the task-kit dashboard: architecture design, databench integration plan, and iterative detail-view mockups.

This is the planning body for the task-kit dashboard, and it reads as a design-review-prototype cycle rather than a pile of loose notes. A spine design carries the load-bearing decisions; a cross-check review rules on it; a dated plan records where the direction moved after the 2026-10-22 rulings; and a stack of HTML mockups, run through several rounds, is where the actual screen gets argued out. Each file names the one it answers, so you can trace any verdict back to the design or ruling it reacts to. Nothing here is code: the folder holds design, review, and mockup only.

Where to start

Open docs/planning/task-kit-dashboard/architecture.md first: its ten load-bearing decisions shape every other document here. To see where the direction moved, follow it into docs/planning/task-kit-dashboard/databench-integration-plan.md, which supersedes the design's first decision.

    2. docs/planning/task-kit-dashboard/architecture-review.md -- the cross-check that returns REVISE with four blocking defects.
  • The cutover: review, then the staged plan
    1. docs/planning/task-kit-dashboard/databench-integration-review.md -- the read-only review that maps where task-kit and databench overlap and poses the host decision.
    2. docs/planning/task-kit-dashboard/databench-integration-plan.md -- the plan that records the 2026-10-22 rulings and stages the move as M1 to M7.
  • The detail view: pitch, concepts, rounds
    1. docs/planning/task-kit-dashboard/detail-view/index.html -- the pitch for the four task-detail concepts and the data each needs.
    2. docs/planning/task-kit-dashboard/detail-view/a-views.html, docs/planning/task-kit-dashboard/detail-view/b-brief.html, docs/planning/task-kit-dashboard/detail-view/c-situation.html, docs/planning/task-kit-dashboard/detail-view/d-timeline.html -- the four first-round options side by side.
