Task detail mockups - Round 2

Questions are the schema. Answers are the view.

These concepts make orientation a durable set of declared questions answered by cheap models: local Qwen first, Luna or Haiku as fallback. Every answer carries its source revision, model, time, and freshness; stale, unanswered, and failed questions remain visible instead of silently disappearing.

Shared metadata model

A task schema declares questions, not fixed prose fields. A refresh asks only questions invalidated by changed evidence. The durable record keeps the last usable answer and its provenance.

Declared question->Evidence bundle->Qwen, then Luna/Haiku->Durable answer + provenance->View

Shared display rules

  • Fresh answers read as content, not AI output.
  • Provenance is quiet but always available.
  • Stale answers stay visible and marked.
  • Failures never erase the prior good answer.
  • Run controls do not lead the default view.
Three concepts
Concept A

Answer board

A prioritized board where each card is one declared question and its current answer. Purpose, standing, next action, and waiting-on-you dominate the first screen.

Strengths

  • Most literal, inspectable expression of the metadata model.
  • Missing and stale answers degrade independently.
  • Easy to reorder questions by task type.

Costs

  • Can become card-heavy as the registry grows.
  • Reads less like a human hand-off.
  • Question wording becomes visible product copy.

Judge: Should the default task view expose the question model this directly, or should it read more like a single brief?

Questions assumed

  • Purpose; current standing; next action.
  • Waiting on me, with defaults; blockers.
  • Associated commits; remaining size.
  • Related tasks; stale or abandoned.

Concept B

Cited briefing

A compact hand-off note assembled from current answers. Numbered question citations connect the narrative to a complete answer ledger and its provenance.

Strengths

  • Fastest to read after time away.
  • Feels like one coherent orientation, not a database.
  • Ledger preserves inspectability and failure states.

Costs

  • Composition rules can hide answer boundaries.
  • Stale paragraphs are harder to isolate visually.
  • More risk that the brief feels over-generated.

Judge: Is the primary object a readable brief, with the question system one layer beneath it?

Questions assumed

  • Purpose; current standing; next action.
  • Waiting on me, with defaults; remaining size.
  • Associated commits; blockers.
  • Changes since last session; related tasks; staleness.
Open concept B
Concept C

Question lenses

Orient, Decide, and Trace are separate task views. Each is a versioned set of questions, with only the controls that make sense for that intent.

Strengths

  • Strongest realization of view-specific information and controls.
  • Keeps decisions and evidence out of the reading path.
  • Question sets can evolve without redesigning every card.

Costs

  • Answers repeat across lenses.
  • Important evidence may sit behind another view.
  • Requires a clear contract for lens membership.

Judge: Are Orient / Decide / Trace the right stable views, and should views be defined as named question sets?

Questions assumed

  • Orient: purpose, standing, next, waiting, size, staleness.
  • Decide: pending choices, defaults, consequences.
  • Trace: commits, changes since last session, related tasks, answer health.
