Planning documents that design, measure, and validate the md-domain coverage and generation lanes inside the skills-kit md-domain skill. The coverage verb audits whether a code subtree's hazards are carried by the agent instruction files that actually load for it; the generation chain that writes those files is measured the same way. The coverage verb shipped in skills-kit 0.62.0, so this folder is as much a measurement archive as a design one, holding the design specs, the test designs, the end-to-end regeneration runs, an independent keep/revert adjudication, and a documentation-on/off review experiment. Read it as the paper trail for one central design decision, that md-domain is not a code-review tool but ensures the document informs review, and for the numbers that tested that premise against real corpora. The shipped criteria and lane procedures live in the md-domain skill; these planning files do not ship to consumers.

Where to start

Open docs/planning/md-domain-coverage-lane/README.md first: it states the scope correction (md-domain is not a code-review tool) and the reasons the obvious hazard-sweep version was rejected. Then read docs/planning/md-domain-coverage-lane/coverage-lane-spec.md for the settled design of the coverage verb itself.
