plugins-kit maintainer reference for design rationale, standards, publish procedure, test guidance, and terminology records.

This directory holds the maintainer-facing reference documents for the plugins marketplace: the working behind the one-line rules, standards, and procedures the repo root points at instead of carrying inline. Each document exists because its rule needed room for the rationale, the verdicts, and the evidence that survive outside a session transcript. They are grouped by the job they do - standards shipped text must meet, rationale that re-derives a decision before you re-propose it, publish and test procedure, dated measurement records, and lookup tables. One habit separates the useful reads: the dated records and incident logs are frozen against the tree they measured, so open them as evidence, never as live guidance.

Where to start

Open plugin-opinion-razor.md first. Most of the questions this directory answers - will this opinion earn a seam, will this shipped text stand - resolve through its scenario test, and it sets the evidentiary posture the rest of the reference assumes.

Routes

  • Screen a new model-task adapter: adapters.md for the ground rule and admission bar, then adapters-negative-results.md to check the candidate against everything that already did not pay.
  • Trace how a term was settled: terminology/terminology-audit.md for the divergence table, then terminology/rename-spec.md for the packets that convert the decisions into edits.

Standards shipped text must meet

  • plugin-opinion-razor.md - the scenario test that decides whether a workflow opinion earns a config seam, with detection greps and worked examples in both directions. Open before shipping an opinion, or when asked why one is hardcoded.
  • agent-directive-standards.md - the true, checkable, non-suppressive test for instructions plugins ship into a consumer's session, plus the sweep verdicts. Open when authoring hook output, skill instructions, or subagent prompts.

Design rationale and boundaries

  • first-run-experience.md - the preset-plus-interview pattern for capturing first-run settings, and why the count settles at two presets. Open when adding a first-run question or a new preset.
  • orchestrate-codex-boundaries.md - the standing rationale behind the two root one-line rules on orchestrate's capabilities record and silent codex dispatch failures. Read before re-proposing either design.
  • shared-lib-architecture.md - six review findings on the bootstrap shared-library mechanism, each with a status line that outlives this summary. Open when touching that code.
  • task-folders.md - why the tasks root is a link into the private task repository, the guard that keeps git from staging private content, and the CLI misreporting bug. Open for missing task folders or odd task CLI results.
  • code-review-mechanical-surface.md - which reviewer-lane criteria a script can answer at full recall and which genuinely need a model. Open when deciding how far the deterministic code-review scan should extend.

Publish procedure

  • publish-reconcile.md - the publish flow, the partial-release projection, the master-only-content reconciliation, and the safe-publish gotcha explanations. Open when publishing or clearing a refusal; the flow is scripted, so the doc cannot drift from what runs.

Test guidance

  • testing.md - the parallelism measurements behind the explicit -n rule, the load-failure patterns, and the containment limits of the test harness. Open for pytest worker choices or failures that appear only under load.
  • vacuous-checks.md - the three shapes of tests and guards that pass without checking anything, and the revert check that exposes them. Open when a green result feels unearned, or before trusting a new drift guard.

Model-task adapters

  • adapters.md - the provisional reference for building model-task adapters: the corpus-independence ground rule, the empirical admission bar, the artifact contract, and the enforcement seam. Open before building or admitting an adapter.
  • adapters-negative-results.md - the catalog of adapter candidates that did not pay, each entry naming which of the four meanings applies. Open before spending a run on a candidate that feels new.

Dated records and worked incidents

  • md-audit-lane-precision-2026-09-03.md - a dated precision measurement of the audit lane, frozen against the 2026-09-03 tree. Open as the before-picture when re-measuring after a criteria change; its citations are not to be repointed.
  • shared-tree-git-discipline.md - worked incidents from concurrent sessions touching the shared tree's index and branches, with the staging exception worked out. Open when a staging or merge refusal looks like another session's work.

Lookup tables

  • claude-code-plugin-platform.md - static platform facts: the hook JSON contract, the attended-session variables, the on-disk plugin cache and registry layout. Open when you need a shape without reading code; the upstream docs win on conflict.
  • reusable-libraries.md - the index of the bootstrap shared libraries, their entry points, and when to consume one. Open before building project-local machinery, to pick an existing library first.

Terminology records

  • terminology/rename-spec.md - executable packets that convert the ratified terminology decisions into token-level edits, keyed on tokens rather than line numbers. Open to apply or verify the rename; a second application is a no-op.
  • terminology/terminology-audit.md - the divergence table the spec executes, with path and line evidence against the pre-rename tree. Open to see why a term was settled the way it was.

Plugin maintenance notes

  • unreal-kit-maintenance.md - the vendored-helper rule for unreal-kit runtime files: keep the copies byte-identical to their bootstrap originals, and how to extend the redirector filter. Open when a vendored helper changes.
