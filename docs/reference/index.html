plugins-kit maintainer reference: standards, design records, procedures, platform facts, and dated measurements

This is the maintainer-facing reference for plugins-kit: the standing standards that bind authors, the signed-off design records, the shipping procedures, the static platform facts, and the dated measurements. Each document is a self-contained destination you open for a specific question, not a sequence you read end to end. What holds the shelf together is the split between material that is current and binding, a standard or procedure you must follow, and material that is a point-in-time record, a measurement or audit you read for what it found. Date-stamped files keep their original citations on purpose, so treat them as snapshots to supersede rather than edit in place.

Where to start

There is no single entry; this is a lookup shelf, so open the file that matches the task in front of you. Keep the standards pair - docs/reference/plugin-opinion-razor.md and docs/reference/agent-directive-standards.md - in view first, because they bind every opinion and instruction this repo ships.

Standards that bind authors

  • docs/reference/agent-directive-standards.md - criteria for any text this repo ships that instructs Claude in a consumer's session; open before writing hook output, skill instructions, or subagent prompts.
  • docs/reference/plugin-opinion-razor.md - the scenario test for whether a plugin may impose a workflow opinion; open before adding or removing a configuration seam.
  • docs/reference/deprecation-policy.md - the two-minor-version shim window for public names; open before renaming or removing a public API.
  • docs/reference/testing.md - the repository's testing standard; open before writing or reviewing a plugin's test suite.
  • docs/reference/vacuous-checks.md - the criteria for spotting a check that passes without testing anything; open before adding or trimming a mechanical check.
