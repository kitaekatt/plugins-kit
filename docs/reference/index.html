plugins-kit maintainer reference: standards, design records, procedures, platform facts, and dated measurements

This directory is the maintainer reference layer for plugins-kit: the detail that one-line rules at the repository root point to on demand. Most records expand a single governing rule and say at the top which trigger sends a reader to them. A few set standards for new work; others are dated measurements and audit records, which describe the tree as it stood on their date and are superseded rather than edited. Nothing here is copied into a consumer's plugin cache, and that boundary is why maintainer material lives here instead of inside published plugins. When a record and a root rule disagree, the rule governs and the record is the evidence behind it.

Where to start

Start with docs/reference/plugin-opinion-razor.md when the question is whether an opinion should ship at all, and with docs/reference/publish-reconcile.md when a release is in front of you. Every record names the rule it expands and the trigger to read it on, so a phrase from a session usually picks the file for you.

Routes

  • Ship a release
    1. Read the range and hold-back rules in docs/reference/publish-reconcile.md
    2. Perform the dry-run check; when shipping one plugin, hold the rest at master's content.
    3. A bare run re-projects and verifies master; a master-only refusal routes to the back-port procedure in the same file.
  • Evaluate an adapter
    1. Read the ground rule and admission bar in docs/reference/adapters.md
    2. Check docs/reference/adapters-negative-results.md first; a closed or disqualified candidate stays closed without a new measurement.
    3. Admit only after two control and two candidate arms clear the controls' own spread.
  • Audit agent-facing text
    1. docs/reference/agent-directive-standards.md -- enumerate the shipped agent-facing text and apply the five criteria site by site.
    2. Quote each finding verbatim and verify every citation the directive makes.
    3. The pre-commit directive check blocks on-sight phrases; the criterion with no keyword still needs a human read.
  • Consume a shared library
    1. docs/reference/reusable-libraries.md -- pick the package and read its entry points.
    2. Declare the package in the consuming plugin's shared-lib imports.
    3. Check the library's public-surface listing before assuming a name is stable, per docs/reference/deprecation-policy.md.
