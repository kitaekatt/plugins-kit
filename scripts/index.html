Commit and publish gates, isolated dev testing, code-review skill rendering, and reviewer-model benchmarking for the plugins-kit marketplace

This is the tooling that keeps the plugins-kit marketplace honest between a local edit and the moment a consumer installs it. The files do four jobs: gate commits and publishes, let you test plugins against the working copy instead of the published cache, render the code-review skills from a single template, and validate and benchmark the reviewer models those skills dispatch. The idea that organizes the commit-time checks is that they judge the staged index, not the shared working tree; several sessions edit this tree at once, so a check that read the worktree would fail on edits that are not in the commit.

Where to start

Open scripts/publish.py first; its header states the whole release contract and every refusal, so it re-anchors what a publish actually does. For the commit side, scripts/pre-commit-version-check.sh is the one file that runs the staged checks in order.

Routes

  • Gate a commit that ships plugin changes
    1. scripts/pre-commit-version-check.sh - the hook entry; it runs the rest in order.
    2. scripts/regen_marketplace.py --check --staged
    3. scripts/check-staged-version-bump.sh
    4. scripts/check_pyproject_sync.py --staged
    5. scripts/check_bootstrap_dependency.py --staged
    6. scripts/check_agent_directives.py --staged
  • Publish a release
    1. scripts/publish.py --check runs preflight only, no writes.
    2. scripts/publish.py - the four-step release: rebuild the manifest, push dev, fast-forward master, verify.
    3. scripts/regen_marketplace.py - the manifest rebuild publish runs.
    4. scripts/_packages.py - the consumer-target validation inside preflight.
  • Test plugin changes before publishing
    1. scripts/dev-tree.py dev repoints the machine registry at the working copy.
    2. scripts/claude_plugin_test.py - or launch an isolated session that leaves the registry untouched.
    3. scripts/dev-tree.py normal restores the registry from its backup.

Commit-time gates

  • scripts/pre-commit-version-check.sh - the chain that runs the staged-index checks in order; wire it up as the pre-commit hook.
  • scripts/check-staged-version-bump.sh - refuses a commit that changes a plugin without bumping its version since the last publish.
  • scripts/check_pyproject_sync.py - refuses a packaging version that has drifted from the plugin manifest it mirrors.
  • scripts/check_bootstrap_dependency.py - refuses a plugin that does not declare the bootstrap dependency.
  • scripts/check_agent_directives.py - refuses banned agent-directive phrases about to ship into the plugins tree.
  • scripts/precommit_guard.py - the unforgiving leak guard that blocks project-derived or machine-generated data from staged commits.
  • scripts/_gitindex.py - the shared staged-index helpers the gates import instead of each re-implementing git.

Publish flow

  • scripts/publish.py - the source of truth for a publish: preflight, the four-step release, and verify; --check runs preflight only.
  • scripts/regen_marketplace.py - rebuilds the marketplace manifest from the plugin manifests; --check --staged is what the commit gate calls.
  • scripts/_packages.py - consumer-target validation and private-index git helpers; publish imports it and it never releases a package.
  • scripts/import_package_targets.py - imports verified library releases into the offline target artifact that publish validates against.

Isolated dev testing

  • scripts/dev-tree.py - repoints the machine registry at the working copy so a session tests manifests, not the cache; restore is lossless.
  • scripts/claude_plugin_test.py - launches an isolated session from the working copy under a redirected data root, leaving the registry untouched.
  • scripts/claudx_plugin_dirs.py - prints the working-copy plugin directories a claudx session should load.

Drift diagnosis

  • scripts/plugin-versions.sh - dumps local, marketplace, installed, and cache versions side by side to spot drift.
  • scripts/cache_status.py - diffs local source against the installed plugin cache, file by file.

Renderers with drift guards

  • scripts/gen_code_review_skills.py - one template renders both code-review skills; --check asserts the committed output matches.
  • scripts/llm_kit_repoint.py - rebuilds the re-pointed llm-kit test mirror from a name map; check asserts the mirror agrees with the trees.

Model validation and reviewer benchmarking

  • scripts/check_model_dispatch.py - validates the orchestration policy model identifiers and config keys by real dispatch; a tool, not a gate.
  • review-bakeoff - a benchmark harness whose corpus holds 24 review scenarios, each a diff paired with its definition, used to compare reviewer models.
