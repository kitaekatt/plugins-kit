Commit and publish gates, isolated dev testing, code-review skill rendering, and reviewer-model benchmarking for the plugins-kit marketplace

This is operational tooling for the plugins-kit marketplace: commit gates, the publish flow, isolated working-copy launchers, code-review skill rendering, and reviewer-model benchmarking. The scripts split by lifecycle stage. Most checks judge the staged Git index, not the shared working tree, because concurrent agent sessions edit the same checkout. The index reads live in one shared helper, and on-demand diagnostics and benchmark data sit beside the gates.

Where to start

Start with scripts/publish.py: its header states the four-step release, the preflight, and the invariants the commit gates also enforce. For commit failures, open scripts/pre-commit-version-check.sh.

Routes

  • Commit gates
    1. scripts/pre-commit-version-check.sh - pre-commit consistency chain; collects every failure, then reports them together.
    2. scripts/regen_marketplace.py --check --staged - the marketplace manifest matches the staged plugin sources.
    3. scripts/check-staged-version-bump.sh - every staged plugin is bumped since the last publish.
    4. scripts/check_pyproject_sync.py - each staged pyproject agrees with its plugin.json.
    5. scripts/check_bootstrap_dependency.py - each staged plugin declares the bootstrap dependency.
    6. scripts/check_agent_directives.py - no banned phrasing ships to a consumer's session.
  • Publish
    1. Bump a plugin's version in its manifest, run scripts/regen_marketplace.py to rebuild the derived manifest.
    2. scripts/publish.py - preflight, project master, or hold back a partial --only release; verify.
  • Dev tree
    1. scripts/dev-tree.py dev - rewrite the plugins-kit registry to this working copy and clear cooldown stamps.
    2. Start a claude session; it loads plugin skills, hooks, and manifests from disk.
    3. scripts/dev-tree.py normal - restore the registry from backup and clear cooldown stamps again.
  • Bakeoff
    1. scripts/review-bakeoff/run_bakeoff.py - run, prompts, ingest, and score against the corpus.
    2. scripts/review-bakeoff/run_bakeoff.py - ingest after each arm returns its raw issue array.
    3. scripts/review-bakeoff/run_bakeoff.py - score precision, recall, and the decoy false-positive rate per arm.

Other scripts

  • scripts/precommit_guard.py - separate leak guard, with its own hook; blocks generated and project-derived data from a staged commit.
  • scripts/_gitindex.py - stdlib-only Git-index helpers every index-aware check imports; the index-versus-worktree semantics live here.
  • scripts/cache_status.py - content-diffs the installed plugin cache against local source.
  • scripts/plugin-versions.sh - dumps version strings across the local repo, marketplace clone, installed registry, and cache.
  • scripts/check_model_dispatch.py - validates the model identifiers in the orchestrate policy by real dispatch; on demand only.
  • scripts/claude_plugin_test.py - isolated session that loads skills, hooks, and manifests from disk via a dev layout and redirected data root.
  • scripts/claudx_plugin_dirs.py - prints the --plugin-dir list a claudx session should load, filtered by enablement.
  • scripts/gen_code_review_skills.py --check - renders the git-kit and p4-kit code-review skills and shared references; fails on drift.
  • scripts/llm_kit_repoint.py check - regenerates the re-pointed legacy test mirror for the llm-kit differential; asserts it agrees with the legacy trees.
  • scripts/review-bakeoff/README.md - four-step runbook for the endpoint and claude-harness arms.
  • scripts/review-bakeoff/SPEC.md - on-disk contract: corpus layout, mechanical scoring rule, and arms.
  • scripts/review-bakeoff/corpus - 24 planted-bug and decoy cases; each case.yaml plus the chunk.diff a reviewer lane receives.
