Repo-level scripts that run plugins-kit commit gates, marketplace publishing, development tests, sync diagnostics, code-review skill rendering, and the reviewer_b bakeoff

    This is the maintenance machinery around the plugins-kit marketplace: what a commit, a release, or a dev session passes through before it reaches a consumer. Nearly every tool here judges the git index, not the working tree, because the tree is shared with concurrent sessions. The pieces fall into jobs: commit gates, the publish pipeline, working-copy test harnesses, drift diagnostics, a template renderer for the code-review skills, and a bakeoff measuring one reviewer lane. When a gate blocks you, that script's header carries the reasoning, the escape hatch, and the degraded-mode behavior.

    Where to start

    Open pre-commit-version-check.sh first: it chains the consistency checks that run at commit time, and its header states the layering rule -- escapable advice at commit time, unbypassable preflight at publish time -- that organizes the directory. For a release, go straight to publish.py, the source of truth for the four-step release flow.

    Routes

    • Commit gate chain: pre-commit-version-check.sh runs, in order, regen_marketplace.py, check-staged-version-bump.sh, check_pyproject_sync.py, check_bootstrap_dependency.py, and check_agent_directives.py against the staged index.
    • Ship a publish: stage the version bump, then regen_marketplace.py -> publish.py (preflight, regenerate, push dev, fast-forward master, verify).
    • Point the machine at the working copy: dev-tree.py dev, run a session, dev-tree.py normal; status says which mode is active, and restore is lossless.
    • Bakeoff the reviewer lane: review-bakeoff/run_bakeoff.py run for endpoint arms, prompts then ingest for Agent arms, then score.

    Commit-time gates

    • _gitindex.py -- the shared helper the Python gates import: index-aware, commit-scoped git reads, with a loud worktree fallback instead of a silent pass.
    • pre-commit-version-check.sh -- the chain that runs the marketplace regen and the four consistency checks against the staged index; reports every failure at once, not one per attempt.
    • check-staged-version-bump.sh -- blocks a commit leaving a plugin's version equal to the value at the last publish point; it asks about the end state, not this commit's diff.
    • check_pyproject_sync.py -- blocks a stated pyproject version that disagrees with the authoritative plugin manifest; the gate that closed a five-release drift.
    • check_bootstrap_dependency.py -- blocks a plugin manifest missing the bootstrap dependency; the rule is universal so the whole fleet can rely on bootstrap.
    • check_agent_directives.py -- greps shipped plugin text for phrasings the agent-directive standards forbid; a line that quotes a banned phrase to prohibit it carries an inline allow marker.
    • precommit_guard.py -- the separate, unforgiving leak guard wired to every commit outside this chain: refuses project-derived or machine-emitted data, oversized blobs, and bootstrap write targets that escape the plugin root.

    Publishing

    • publish.py -- the four-step release: unbypassable preflight, regenerate derived artifacts, push dev, fast-forward master (a projection when partial or dev-only plugins are in play), verify; also the publish-point oracle the bump check calls.
    • regen_marketplace.py -- rebuilds the marketplace manifest from the per-plugin manifests; --check --staged feeds the pre-commit chain, and --only commits one entry without sweeping other sessions' bumps.

    Running plugins from the working copy

    • claude_plugin_test.py -- launches a Claude Code session on this working copy without rewriting the machine-global registry; --print previews where a run would write, and the header names three observed escapes to read before deleting its data root.
    • claudx_plugin_dirs.py -- prints the plugin directories the current project has enabled, one per line on stdout.
    • dev-tree.py -- the machine-global switch: dev repoints the install registry at this working copy, normal restores from its backup, status reports the mode.

    Sync diagnostics

    • cache_status.py -- file-content diff between local source and plugin cache per installed plugin; differs is expected on a dev branch, and --detailed lists the divergent files.
    • plugin-versions.sh -- one report lining up version strings across local repo, marketplace clone, install registry, and cache.

    Code-review skill rendering

    • gen_code_review_skills.py -- renders the git-kit and p4-kit code-review skills and their agents from one template; --check is the drift guard the test suite pins.

    On-demand model validation

    • check_model_dispatch.py -- proves the orchestration policy's model ids and config keys actually dispatch via live CLI calls; on demand by design, so nothing runs it automatically.

    reviewer_b bakeoff

    • review-bakeoff/README.md -- the runbook: run for endpoint arms, prompts and ingest for Agent arms, then score; results are untracked scratch output.
    • review-bakeoff/SPEC.md -- the on-disk contract: corpus layout, the one-planted-bug matching rule, four metrics; the decoy false-positive rate is the headline.
    • review-bakeoff/run_bakeoff.py -- the runner and scorer; endpoint arms dispatch through the git-kit lane runner, Agent arms go out as prompts and back in as issue arrays.
    • review-bakeoff/corpus -- 24 self-contained cases, each a YAML spec plus the exact diff the lane receives; positives plant one bug, decoys must not elicit anything.
