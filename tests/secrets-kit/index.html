• secrets-kit plugin The code under test: the plugin these tests import and drive, one level up.

Test suite for the secrets-kit plugin covering convergence, destination safety, pre-commit guard, repository operations, manifest validation, and cross-process locking

This directory is the pytest suite for the secrets-kit plugin. It checks the guarantees the plugin makes to a machine: the convergence pass (what plaintext lands on disk and when it stays silent), the destination-safety guards that keep plaintext out of a tracked repo, the pre-commit guard on the secrets repo itself, seeding and cross-process locking, and the crypto and permission boundaries underneath. The suite replaces real age crypto with a reversible stand-in and builds real git trees once per process, so it exercises the actual convergence logic and guard behavior without ever touching a real secret. The groups below are named for the job each module tests, not for file names.

Where to start

Start with tests/secrets-kit/conftest.py: it defines the reversible age stand-in and the seeded fleet that most modules build on, so it is the model for the whole suite. Open tests/secrets-kit/sk_testlib.py next to see why each test still gets its own independent git tree.

Shared fixtures and helpers

  • tests/secrets-kit/conftest.py The fixtures every test stands on: the reversible age stand-in, the seeded fleet, and the owner-only temporary home. Read it first to learn what converge means here.
  • tests/secrets-kit/sk_testlib.py Builds an expensive git tree once per process and hands out independent copies, so each test gets its own real git repo and the suite stays fast and isolated.
  • tests/secrets-kit/sk_publish.py Two publish helpers: an ordinary add, commit, and push for fixture setup, and the exact owned-path calls production uses when a test asserts a security property.

Convergence

  • tests/secrets-kit/test_converge.py The core pass: what gets written, what stays silent, and how each failure is classified as locked, config, or destination.

Destination safety

  • tests/secrets-kit/test_dest_guard.py The tracked-tree guard: the exposure predicate, the add-time refusal, and the convergence re-check that keep plaintext out of a consumer repo.
  • tests/secrets-kit/test_destination_leaf.py Destination slots that are symlinks: an exposed leaf refuses before any read, and a matching leaf replaces the slot without touching the referent.
  • tests/secrets-kit/test_destination_ownership.py Who owns a slot: collisions refuse both orderings, a failed move reserves the prior slot, and unselected orphans are owned conservatively.
  • tests/secrets-kit/test_destination_retirement.py Ownership moves and durable retirements: a move publishes the new slot, retires the old one, and checkpoints a failed unlink for a later retry.

Pre-commit guard

  • tests/secrets-kit/test_guard.py Drives the real shell hook through real git commits: installation is idempotent, a foreign hook is never clobbered, and plaintext is refused by content, not just path.

Seeding and operation lock

  • tests/secrets-kit/test_init.py Seeding is the one irreversible verb. These pin that it checks whether the remote is already seeded and rolls back when the seed cannot publish.
  • tests/secrets-kit/test_operation_lock.py Whole operations contend across real independent processes: a second process refuses before any protected work, then retries cleanly.

Recovery and retry

  • tests/secrets-kit/test_entry_recovery.py Entry add, update, and remove faults preserve the owned epoch before a clean retry; foreign work is refused before any sync or crypto.
  • tests/secrets-kit/test_orphan_retry.py A failed orphan cleanup is persisted rather than lost; a later independent pass retries only the failed row.

Crypto and permission boundaries

  • tests/secrets-kit/test_agefile.py The process boundary around the age CLI: only a completed nonzero exit is a DecryptError; a missing binary, a spawn fault, and a timeout are their own faults.
  • tests/secrets-kit/test_perms.py ACL tightening on Windows and chmod on POSIX, including the regression where non-inheritable ACEs left pre-existing files with an empty DACL.
  • tests/secrets-kit/test_permission_drift.py Matching-content permission checks through the public consumers: a widened mode is repaired once, and a fault retains the row.

Repository operations, manifest validation, and bootstrap

Eleven further modules round out the suite but are not named here. They cover repository operations and clone binding, manifest validation, seeding recovery, and the bootstrap consumer path that the public commands drive. Open one when a test imports a helper you do not recognize, since most of the shared helpers live in this group.
