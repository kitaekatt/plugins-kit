Secrets-kit plugin test suite for convergence, destination safety, pre-commit guards, repository operations, manifest validation, and operation locks

    This is the full test suite for the secrets-kit plugin, the code that converges an encrypted fleet secrets repo onto each machine's local files. The tests never run real age and never touch a real remote; a reversible stand-in for age and a stubbed network leave the decision logic as the behavior under test: what gets written, what stays silent, and how a failure is classified. Git setup is paid once per process and copied out cheaply, so the suite drives real commits and real subprocesses. One file pins one behavior area, grouped below by the job the file does.

    Where to start

    Start with conftest.py: its fleet fixture is the machine every destination test stands on, and its fake age defines what decryption means here. Open test_converge.py next for the behavior at the center of the suite.

    Routes

    • Trace a secret end to end: conftest.py → test_converge.py → test_orphan_retry.py
    • Follow the ownership ledger: test_destination_ownership.py → test_destination_retirement.py
    • Chase an authoring fault: test_seed_recovery.py → test_entry_recovery.py
    • See a contender lose the lock: test_operation_lock.py → test_repo_binding.py → test_sync_view.py

    Suite plumbing

    • conftest.py Shared fixtures: a reversible fake age, a seeded fleet machine, an isolated user home. Read it to know what every test assumes.
    • sk_testlib.py Copies a prebuilt git tree into a fresh, independent repo in milliseconds and repoints the absolute paths inside it.
    • sk_publish.py Two publish helpers kept separate on purpose: an ordinary producer push for fixtures, and the owned path production calls.

    Convergence and destination safety

    • test_converge.py The center of the suite: what gets written, what stays silent, what fails, and how each failure class is reported.
    • test_agefile.py The age subprocess boundary: a completed nonzero exit means a bad identity; a missing binary, spawn fault, or timeout is a dependency fault.
    • test_dest_guard.py The tracked-tree guard: the exposure predicate, parsing of noisy git output, and the add-time refusal.
    • test_destination_leaf.py Destination slots that are symlinks: exposed, matching, and permitted leaves, driven through the real consumers.
    • test_destination_ownership.py Two entries claiming one slot, failed moves that reserve the prior slot, and conservative orphan ownership.
    • test_destination_retirement.py Ownership moves and durable retirements, including unlink failures checkpointed and retried after a process restart.
    • test_orphan_retry.py When orphan cleanup fails: the row persists, the failure names the file, a later pass finishes the removal.
    • test_permission_drift.py Permission repair on matching content: observed mode drift, cached modes, and the Windows ACL boundary.
    • test_perms.py The perms module itself: the mode and ACL helpers the pass calls.

    Guard and seeding

    • test_guard.py The pre-commit hook: installation, plus real git commits proving it actually refuses plaintext.
    • test_init.py The one irreversible verb: seeding decided from the remote, and full rollback when a seed cannot publish.

    Authoring and manifest

    • test_manifest.py Declaration loading, validation, and variable expansion: the placeholder rules, cycles, stalls, per-machine variables.
    • test_entry_recovery.py Add, update, and remove faults that leave the owned epoch untouched, then succeed on a clean retry.
    • test_seed_recovery.py The seed's own recovery path, and the fixtures the entry tests build on.
    • test_update_metadata.py Metadata-only updates that must not republish or rewrite the encrypted blob.
    • test_rotation_recovery.py Identity rotation left half-finished, and the path back to a working unlock.

    Repository operations and locks

    • test_repo.py The repo module: clone, refresh, and the owned commit and publish calls.
    • test_repo_binding.py Confirms a clone is bound to the repo its config declares; also the lock tests' snapshot and adapter helpers.
    • test_repo_display_cli.py What the CLI prints about the repo.
    • test_sync_view.py The git and authoring fixtures the lock and entry tests share.
    • test_operation_lock.py Whole operations contending across real processes: one owner proceeds, every other caller refuses first.
    • test_private_output.py What may be printed about private state: the rendering rules for notes and messages.
    • test_secrets_bootstrap.py The bootstrap adapter's test surface, including the context fake the consumer tests reuse.
    • test_terminal.py The terminal-bound verbs and their tty behavior.
