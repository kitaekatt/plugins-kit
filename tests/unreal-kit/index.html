Unreal Kit plugin test suite: script runner, redirector cleanup, bootstrap, config, hooks, and MCP client

    Tests for the unreal-kit plugin live here, and they run on a machine with no Unreal Editor and no Perforce server. One module pins one shipped component: the script runner's transports, the redirector cleanup pipeline, the bootstrap boundary, per-project config, the editor hooks, and the MCP bridge client. The modules drive the real entry points through runpy, subprocess, and injected fake modules, so each pass is a statement about the shipped scripts, not about a copy. When a plugin behavior looks wrong in the field, this suite is where you re-derive it before changing anything.

    Where to start

    Open conftest.py first: it sets the one environment guard that keeps the plugin venv re-exec from firing while pytest imports the runner scripts. Then open the module named after the component you touched; in this suite the file name is the map.

    Routes

    • Read the redirector cleanup in phase order: test_code_refs.py -> test_classify_safety.py -> test_filter_safe_by_code_refs.py -> test_apply_fixups.py, with the fake boundary in _redirector_fakes.py behind the last stage.
    • Follow the runner's auto mode: project resolution, then remote with opt-in fallback, then commandlet detection and result correlation: test_resolve_project.py -> test_remote_fallback.py -> test_commandlet_error_detection.py -> test_commandlet_result.py.
    • Regress a hook: the registration contract first, then the shipped hooks driven in a subprocess: test_hook_commands.py -> test_console_cmd_hook.py -> test_editor_stale_hook.py.
    • Regress the bootstrap boundary: manifest contract, then consumer outcome logging, then the version-probe messages: test_bootstrap_contract.py -> test_custom_bootstrap.py -> test_search_stub_bootstrap_messages.py.

    Suite mechanics

    • conftest.py - sets the re-exec guard before pytest imports the runner scripts; read first when collection misbehaves.
    • __init__.py - empty package marker; lets the suite import _redirector_fakes.py by bare name.

    Script runner

    • test_resolve_project.py - project selection priority: flag, cwd, script path, then config; the wrong-project regressions.
    • test_remote_fallback.py - when a remote failure falls back to the commandlet and when it refuses; the opt-in boundary.
    • test_commandlet_error_detection.py - catches LogPython error blocks in commandlet output that name your script; the whitelist regression.
    • test_commandlet_result.py - completion correlation through the generated wrapper: exit codes, stale tokens, timeout budgets.
    • test_ue_env.py - readiness probes on a fake clock: connection budget, no probe past the deadline.
    • test_setup.py - what the setup flag writes and what it must not copy from bootstrap; the static guards included.

    Redirector cleanup

    • _redirector_fakes.py - fake unreal and p4cli modules with event logs; the boundary behind the apply tests.
    • test_apply_fixups.py - drives the real apply entry point through the fakes: phase order, manifest, delete outcomes.
    • test_classify_safety.py - blocks ambiguous depot identities and opened-file conflicts before they reach the safe list.
    • test_code_refs.py - the source scanner: mount discovery, utf-16 input, fail-closed on any stat or read error.
    • test_filter_safe_by_code_refs.py - cache provenance and the phase-3.5 filter; runs the real classifier and filter back to back.
    • test_p4cli.py - P4 helper timeouts, delete batching, and per-file where-records identity.

    Bootstrap and consumer boundary

    • test_bootstrap_contract.py - the manifest boundary: project scope survives merge, p4 stays an opt-in requirement.
    • test_custom_bootstrap.py - outcome logging of the shipped consumer bootstrap: one honest line, deferred work recorded.
    • test_search_stub_bootstrap_messages.py - absent and too-old bootstrap library messages stay distinct and point at the right fix.
    • test_unreal_stub.py - durable enriched and stock API stubs: refresh, search order, read-only destinations.
    • test_consumer_contracts.py - asserts the shipped README and skill docs say what the shipped code actually does.

    Config and ini files

    • test_project_config.py - config discovery and layering: per-project beats global beats defaults; atomic writes.
    • test_config_cli.py - a malformed config stops the runner and env CLI before discovery or dispatch.
    • test_ue_ini.py - comment-preserving ini updates; a failed replace leaves the old file intact.

    Editor hooks

    • test_hook_commands.py - every command in the shipped hooks manifest survives a spaced plugin root as one argument.
    • test_console_cmd_hook.py - the console-command hook self-disables when the MCP server is not configured.
    • test_editor_stale_hook.py - the stale-editor detector, the config resolution it must share, and the wrapper's interpreter policy.

    MCP client

    • test_mcp_client.py - handshake, request and response, ping-pong, and timeout budgets against a fake websocket.
