Tests that verify llm-kit replaces the legacy plugins with differential parity, cross-state compatibility, and migration activation checks.

This directory is the test suite that proves the llm-kit package can replace three legacy plugins with one installable package. The suites are organized by the kind of proof they give rather than by the module under test. Nearly every test runs two sides at once, the frozen legacy plugins and the final llm-kit, over the same inputs and compares the outcomes, so the shared notion of a side and a ledger of deliberately-different wording are the connective tissue. The committed data the suites drive with lives in a separate tree, and the machine-checkable gates that clear the migration for activation sit beside the parity suites.

Where to start

Start with the differential parity suites, and open tests/llm-kit/test_adapters_parity.py first: it runs the frozen legacy modules and the final llm-kit over the same inputs and asserts the outcomes match, the technique the whole directory is built on. The shared normalizer that keeps the two sides comparable is tests/llm-kit/final_wording.py.

Routes

  • Trace a parity mismatch
    1. Open the failing suite, for example tests/llm-kit/test_cli_parity.py
    2. Read the sides and normalization in tests/llm-kit/test_cli_harness.py
    3. Check whether the gap is a declared rename in tests/llm-kit/final_wording.py
  • Run the differential by hand
    1. Run the on-demand differential from tests/llm-kit/repoint.py
    2. It loads tests/llm-kit/repoint-map.json plus the per-suite disposition ledger
    3. It diffs the legacy run against the mirror run and reports the problems
  • Record a late legacy edit
    1. A legacy module edited after the map recorded it must be added to tests/llm-kit/porting-ledger.json
    2. tests/llm-kit/test_copy_inventory.py refuses to run until the edit is ported or rejected
  • Chase a cross-version break
    1. tests/llm-kit/test_cross_state_parity.py drives each side in its own interpreter
    2. It hands persisted state across using the worker and committed documents under the fixtures tree

Differential parity

  • tests/llm-kit/test_adapters_parity.py llm_kit.adapters versus the legacy adapter modules; identical scenarios on both sides, no network or real CLI.
  • tests/llm-kit/test_cli_parity.py the three frozen legacy CLIs versus llm_kit.cli, verb by verb, over the same fake environment.
  • tests/llm-kit/test_completion_parity.py llm_kit.completion versus the legacy neutral completion slice, module surface and behavior.
  • tests/llm-kit/test_cli_groups.py the legacy CLI verbs keep their homes in the final CLI groups.
  • tests/llm-kit/test_adapters_slices.py the adapter split holds: the error classes and usage readers are one object across the final names.
  • tests/llm-kit/test_completion_slices.py the completion facade table: every legacy export has a final home that resolves to the same object.

Cross-state compatibility

  • tests/llm-kit/test_cross_state_parity.py persisted state written by one side and read by the other, in both directions, each stretch in its own interpreter.

Activation and rollback gates

  • tests/llm-kit/test_activation_checks.py the machine-checkable activation conditions: the persist-name tripwire and the rollback guard that keeps the legacy trees independent of llm-kit.

Copy inventory and accounting

  • tests/llm-kit/test_copy_inventory.py every legacy file, module, and test is accounted for; the ledger rows sum to the collected test count.
  • tests/llm-kit/repoint-map.json where each legacy module's code lives in the final package, or why it has no home.
  • tests/llm-kit/porting-ledger.json legacy edits made after the map recorded a module, each ported or rejected with evidence.
  • tests/llm-kit/repoint.py runs the legacy-versus-mirror differential and the on-demand compare CLI.
  • tests/llm-kit/final_wording.py the ledger of named deliberate wording differences the parity suites normalize before comparing.

Consumer contract and bootstrap

  • tests/llm-kit/test_consumer_contract.py the public-surface checker and its listing agree with the code, per the repoint map.
  • tests/llm-kit/test_custom_bootstrap.py the OpenRouter credential check, reported as a deferred requirement, never a fix-all entry.

Shared harness

  • tests/llm-kit/conftest.py per-test environment isolation and the bootstrap re-exec skip that keeps pytest out of the plugin venv.
  • tests/llm-kit/test_cli_harness.py the fake environment and the two sides the CLI parity suites share.

Test data

  • The fixtures tree: data the parity and cross-state suites drive with, including codex_json, cross_state, job_schema, pipeline_schema, and spend_schema, several with legacy and llm-kit variants.
  • The goldens tree: committed expected CLI output, kept under a cli subdirectory.
  • The repoint-dispositions directory: one disposition ledger per legacy suite, each classifying a legacy test file and its declared differences.
