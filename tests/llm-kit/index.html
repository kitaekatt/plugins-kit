Tests that verify llm-kit behavioral parity with the legacy plugins and validate the repoint map, disposition ledgers, and schema fixtures.

This directory holds the differential test suite for llm-kit. It proves that the final package behaves like the three frozen legacy plugins, that persisted state can be handed between them, and that the migration bookkeeping still matches the trees. The tests avoid network calls and real model backends, so they can run in an isolated HOME. Deliberate wording and layout differences are named, and the comparison is by normalized outcomes rather than source text.

Where to start

Start with tests/llm-kit/repoint.py to run or inspect the old-versus-final differential for one suite. Open tests/llm-kit/conftest.py when the import isolation between the legacy and final sides is the question.

Routes

  • Run a suite differential
    1. uv run --extra dev python tests/llm-kit/repoint.py compare job-kit
    2. The helper reads the suite ledger, builds the mirror through the repository generator, and compares the legacy and mirrored pytest runs by normalized node id.
  • Trace a wording difference
    1. tests/llm-kit/final_wording.py names the deliberate legacy-to-final rename or version floor.
    2. tests/llm-kit/test_final_messages.py proves that rename against the live sources before a parity test treats it as expected.
  • Check a persisted-state handover
    1. tests/llm-kit/test_cross_state_parity.py starts one side at a time through tests/llm-kit/fixtures/cross_state/cross_state_worker.py
    2. The committed tests/llm-kit/fixtures/cross_state/job_resolution_document.json anchors the byte-level interrupt resolution check.

CLI behavior

  • tests/llm-kit/test_cli_parity.py verb-by-verb CLI parity between the frozen legacy CLIs and the final grouped CLI; open when output text, exit codes, or flags differ.
  • tests/llm-kit/test_cli_groups.py the final CLI's routing, verb map, composition, and pinned runtime messages; open when the command shape changes.
  • tests/llm-kit/test_cli_harness.py the shared fake environment and two-sided loader for the CLI tests; open when fixture setup or isolation misbehaves.
  • tests/llm-kit/test_launchers.py and tests/llm-kit/test_local_launchers.py cover console and local launcher behavior; open when the venv re-exec or launcher entry points change.

Module and pipeline parity

  • tests/llm-kit/test_adapters_parity.py covers adapters, backends, swapper, and usage readers; the largest adapter-side comparison.
  • tests/llm-kit/test_completion_parity.py covers completion contracts, capabilities, halt behavior, and skill context; open when completion behavior changes.
  • tests/llm-kit/test_jobs_parity.py covers job-ledger parity; open when job run, resume, storage, or interrupt behavior changes.
  • tests/llm-kit/test_execution_parity.py covers execution behavior; the pipeline parity files alongside it cover the pipeline's analysis, artifacts, core, execution, and runtime layers.
  • tests/llm-kit/test_schema_parity.py and the storage, registry, dispatch, frontdoor, and scaffold parity files cover the remaining persisted formats and public seams; open the file named for the area you changed.

Cross-state and schema fixtures

  • tests/llm-kit/test_cross_state_parity.py resumes state written by the other side in both directions; open when a ledger, store, spend entry, or interrupt document cannot be handed over.
  • tests/llm-kit/fixtures/cross_state/cross_state_worker.py keeps each side in its own interpreter and reports leaks; open when a worker imports the wrong package or misses HOME setup.
  • tests/llm-kit/test_spend_ledger_guard.py guards the spend-ledger schema and fresh-database shape; open when spend storage changes.
  • tests/llm-kit/fixtures/job_schema/legacy/fresh.json pins the legacy job-ledger schema baseline; the matching llm-kit copy and the pipeline_schema and spend_schema sets sit beside it.

Repoint bookkeeping

  • tests/llm-kit/repoint-map.json maps every legacy module, facade, and test edit to its final home; open when a legacy module needs a destination.
  • tests/llm-kit/porting-ledger.json records legacy edits made after the map recorded a module; open when a legacy tree changes and the map must not drift.
  • tests/llm-kit/repoint-dispositions/job-kit.json classifies the legacy test files for one suite; the other two suite ledgers sit beside it.
  • tests/llm-kit/test_copy_inventory.py reconciles the map, ledgers, and collection counts without running the suites; open before trusting a repoint change.
  • tests/llm-kit/test_repointed_suites.py runs the actual legacy-versus-mirror differential; open when the comparison itself reports problems.
  • tests/llm-kit/test_repoint_generator.py covers the generator that builds the mirror and alias tree; open when mirror generation breaks.

Activation, bootstrap, and consumer contracts

  • tests/llm-kit/test_activation_checks.py guards against persistable old registration names and protects rollback; open before retiring the legacy plugins.
  • tests/llm-kit/test_custom_bootstrap.py covers the plugin's credential bootstrap under a fake network; open when the OpenRouter key check or deferred requirement changes.
  • tests/llm-kit/test_consumer_contract.py checks the consumer-contract checker and public-surface listing; open when a public name is removed or deprecated.
  • tests/llm-kit/test_import_graph.py enforces the allowed import edges between final package layers; open when a module starts importing the wrong layer.
  • tests/llm-kit/test_manifest.py and tests/llm-kit/test_registrations.py cover packaging metadata and registrations; open them when plugin metadata changes.
  • tests/llm-kit/test_plugin_docs.py covers the documentation surface; open when a doc names a missing command or flag.
