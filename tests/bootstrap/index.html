Test suite for the bootstrap plugin: engine, installation backends, CLI, environment checks, marketplace lifecycle, and the code review pipeline

This is the pytest suite for the bootstrap plugin: the engine that provisions a machine, installs CLIs and tools, manages marketplaces and plugin manifests, and repairs the environment on every session start. The suite is flat, one file per plugin module, so the test you need usually shares its name with the module you touched; the one nested directory sets the review pipeline tests apart. Everything runs hermetic: subprocess is mocked or pointed at throwaway repos, HOME and the data root are redirected, and symlink tests skip on unprivileged Windows. Re-entry is a name lookup: open the module, open the matching test, read what it pins.

Where to start

Open tests/bootstrap/test_engine.py first: it covers the pass every session start runs. For anything else, open the test that shares its name with the module you changed.

Routes

  • Trace a backend through the engine
    1. tests/bootstrap/test_brew.py - what the backend does on its own: install, ordering, failure messages.
    2. tests/bootstrap/test_brew_dispatch.py - how the dispatch table consumes it and the failure shape it emits.
    3. tests/bootstrap/test_brew_cask_elevation.py - where a sudo-needing cask routes to the queue instead of attempting.
  • The agent skills link, two halves
    1. tests/bootstrap/test_agent_skills_check.py - the check-and-fix half: the sentinel, git scoping, bounded cleanup.
    2. tests/bootstrap/test_agent_skills_vcs.py - the VCS half: real disposable git repos, recorded p4 output.
  • The terminal pass, end to end
    1. tests/bootstrap/test_engine_personal.py - builds the isolated world: a minimal plugin root, a fake HOME.
    2. tests/bootstrap/test_bootstrap_run_pass.py - runs the shell shim against it and pins the same pass the hooks run.

Harness plumbing (2)

  • tests/bootstrap/__init__.py - puts the plugin's lib and engine on sys.path.
  • tests/bootstrap/link_compat.py - hermetic link_tree: symlink, junction, then copy; symlink tests skip on unprivileged Windows.

The engine pass (19)

  • tests/bootstrap/test_engine.py - the pass itself; open it before any sibling.
  • The 18 engine siblings pin one aspect each: locking, crash, multi-plugin, output modes, profiles, sync.

Install backends (10)

  • tests/bootstrap/test_brew.py - the brew backend: tap-qualified installs, detect-only ensure.
  • tests/bootstrap/test_apt.py - the apt backend: privilege probes, the once-per-pass update.
  • tests/bootstrap/test_install_strategy_dispatch.py - where each strategy sits in the dispatch table.

Elevation and the fix queue (4)

  • tests/bootstrap/test_brew_cask_elevation.py - a sudo-needing cask, from detection to the runner's briefing.
  • tests/bootstrap/test_fix_queue.py - failures becoming tasks: cost, elevation, briefing text.
  • tests/bootstrap/test_fix_runner.py - prints briefings, holds before anything runs, offers an abort.

The CLI lever and hooks (8)

  • tests/bootstrap/test_bootstrap_cli.py - the read-only status probe; run refuses a running pass.
  • tests/bootstrap/test_bootstrap_run_pass.py - the shell shim's run against an isolated world.
  • The hook tests install and strip the session, shell, and Codex hooks; the presence guard test pins the check the lever runs first.

Marketplaces and plugins (19)

  • tests/bootstrap/test_marketplace_lifecycle.py - clone, update, pin, and remove; the largest file in the suite.
  • tests/bootstrap/test_claude_cli_precondition.py - one stand-down line when the claude CLI is missing.
  • The plugin files cover resolve, snapshot, registry repair, and project detection.

Environment checks (27)

  • tests/bootstrap/test_env_checks.py - the main check suite; the env_ siblings cover features and variables.
  • tests/bootstrap/test_venv_check.py - venv creation and the shared imports.
  • One file per probe: PATH, git, npm, pypi, font, ini, json, settings-writable.

Session, interpreter, and state (24)

  • tests/bootstrap/test_session_cooldown.py - when a pass stands down, and for how long.
  • tests/bootstrap/test_shared_lib.py - the venv shared library: install and exposed imports.
  • The siblings pin the interpreter env, process lock, stamps, and log filters.

Manifests and config (18)

  • tests/bootstrap/test_project_config.py - how project layers merge over the user and plugin layers.
  • tests/bootstrap/test_config.py - the schema migration, v0 to current, and the atomic save.
  • The siblings cover merge, lint, profiles, normalization, autodetect, and self-setup.

Display, events, and outcomes (10)

  • tests/bootstrap/test_execution_event.py - the event format every emitter must produce.
  • tests/bootstrap/test_interrupt_contract.py - the interrupt contract and its consumers.
  • The siblings cover display relay, harvest, and the transient import retry.

External CLIs and agent integration (6)

  • tests/bootstrap/test_codex.py - Codex detection and argv building; the binary is never invoked.
  • tests/bootstrap/test_bootstrap_guard.py - pins every vendored guard copy byte-identical to the canonical one.
  • The agent skills link, check and VCS halves, and the skill material tests round out the group.

The code review pipeline (30)

  • The code_review directory holds 28 files. tests/bootstrap/code_review/test_pipeline.py runs the pipeline end to end; tests/bootstrap/code_review/test_lane_prompts.py pins each lane's prompts.
  • The 26 siblings cover chunking, effort, retry prose, triviality, the ledger, and mechanical config.
  • tests/bootstrap/test_review_consumer_closure.py and tests/bootstrap/test_run_review_lane_drift.py are the flat siblings: consumer closure and lane drift.

  • conftest.py The conftest shared by every suite under the tests tree.
