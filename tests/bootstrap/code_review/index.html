Tests for the shared code-review pipeline, reviewer lanes, mechanical checks, and generated git and p4 skill contracts

This directory is the pytest suite for the code-review pipeline shared by the git and p4 code-review skills. Every test builds synthetic diff sections or temporary on-disk workspaces instead of parsing real VCS output, so the suite pins the shared half of the pipeline while each kit's front-half stays in its own test suite. The tests split by job: building the review bundle, what a reviewer lane receives and returns, the deterministic checks that run before any lane launches, and the exact prose the rendered skill files carry. Where a test reaches into the plugin trees it is checking generated output against the generator that renders it. Shared fixtures and the shipped-profile pin sit beside the tests, not under a data directory.

Where to start

Open test_skill_drift.py first: its module docstring is the map of the whole suite -- what the two kits share, what the generator renders, and why the byte-identity guard lives here.

Routes

  • Tune a shipped profile: shipped_review_profiles.yaml -> test_review_profiles.py -- the yaml is the byte-pinned shipped projection the test re-renders and compares.
  • Make a personal convention reach the lanes: conftest.py -> test_mechanical_config.py -- the conftest fixture writes the isolated home the config tests target.
  • Change what a lane is told: test_lane_prompts.py -> test_skill_drift.py -- prompt text flows into the rendered skills, and the drift guard re-checks both.
  • Trace a diff into its chunk: test_pipeline.py -> test_chunking.py -- the pipeline packs diff sections through the chunker the second file pins.

Building the review bundle

  • test_pipeline.py -- the bundle builder: VCS runs, section splitting, claim matching, and which file lands in which chunk.
  • test_chunking.py -- byte-balanced chunking with group-aware close rules; open when a chunk boundary looks wrong.

What a reviewer lane sees and returns

  • test_lane_prompts.py -- prompt assembly, model-alias versus endpoint classification, and which lanes may run where; open when a lane gets the wrong context.
  • test_lane_output.py -- the lane-output parser and citation verification against the bundle; open when a finding lacks a verified citation.
  • test_review_profiles.py -- profile resolution across shipped, user, and project layers plus model priority; open when a reviewer ends up on the wrong model.
  • shipped_review_profiles.yaml -- the byte-pinned shipped projection the profile tests render and compare.
  • test_effort_agents.py -- the frontmatter contract for the generated effort-agent files in both plugin kits.

The deterministic pre-scan

  • test_mechanical_config.py -- check configuration across the shipped, user, and project layers, built-in versus personal conventions, and the findings a lane is told about.
  • test_mechanical_repository.py -- the scan framework itself: declared requests, the snapshot overlay, and the target and content limits.
  • test_local_link_targets.py -- the markdown broken-link check, including anchor names and what counts as in scope.
  • test_python_syntax.py -- the Python grammar check keyed to each file's version mapping, and when unavailable grammar must read as uncovered.
  • test_structured_parse.py -- whole-post-image parse failures for JSON, YAML, and TOML, and how a parser with no line number stays out of findings.
  • test_triviality.py -- the triviality profile and its disqualifiers, plus the added-lines-only findings form the lanes receive.
  • test_machine_emitted.py -- banner detection for machine-emitted artifacts, and why instructional prose is not a banner.
  • test_machine_emitted_paths.py -- detection by declared generated paths, the axis that catches bannerless stubs.

The rendered skill contracts

  • test_skill_drift.py -- the byte-identity guard for both rendered skills; open first when one kit looks out of step.
  • test_lane_retry_prose.py -- the launch-correction and failed-lane policy prose, kept identical in both kits.
  • test_submit_gate_prose.py -- the submit-gate evaluation prose: evidence over memory, and when the skill may ask the user for a fact.
  • test_review_persistence_prose.py -- the disk-artifact and no-PR-comment prose in both skills' gotchas and scope.
  • test_md_dimension_dispatch.py -- the dimension classifier the skill references call, and the fallback when it is unavailable.
  • test_temporal_prose.py -- keeps time-relative wording out of the generator, the prepare scripts, and the rendered references.

Shared primitives and fixtures

  • test_claude_mds.py -- the ancestor walk that collects each changed file's governing rule files, plus submit-gate parsing and scope matching.
  • test_ledger.py -- the declined-findings ledger: key normalization, baseline invalidation, and the never-collapsed serious findings.
  • conftest.py -- the autouse fixture that isolates the mechanical-config home; open when a test starts reading a real user config.
