The orchestrate skill that delegates implementation units to background agents: its procedure, shipped routing policy, the per-machine policy renderer, and the dispatch and configuration references

The orchestrate skill delegates implementation work to background agents so the main agent keeps coordination, judgment, verification, and synthesis in its own context. Its procedure, the bundled routing policy, the policy renderer, and the dispatch and configuration references sit at one level beside the scripts that carry them. The routing policy is per-machine, so the live lineup, dispatch backends, and usage capacity exist only in the renderer output that the skill consults before routing.

Where to start

  • plugins/awesome-kit/skills/orchestrate/SKILL.md is the skill entry: the orchestrator's procedure in numbered steps, from decomposing the invoked task through routing each unit to the ruling that binds it.
  • The routing policy is per-machine, so the live model lineup, dispatch backends, and usage capacity exist only in the output of plugins/awesome-kit/skills/orchestrate/scripts/orchestration_guidance.py; open that output before judging any routing question.

Procedure and policy

  • plugins/awesome-kit/skills/orchestrate/SKILL.md The orchestrator's procedure: main-thread coordination, every implementation unit delegated, and the four autonomy edges that stop the procedure. The entry to open first.
  • plugins/awesome-kit/skills/orchestrate/defaults/orchestration.yaml The bundled routing policy: the decision half (lexicon, shape, ordered routing rows) and the machine half (dispatch backends, usage capacity). Replaced on every update, so it is overridden by sparse machine, user, and project files rather than edited.

Policy and tuning

  • plugins/awesome-kit/skills/orchestrate/references/configuration.md The full schema: the two policy halves, the four configuration layers, every top-level key, and how a routing row's menu and its consult seats render.
  • plugins/awesome-kit/skills/orchestrate/references/lexicon.md The controlled vocabulary: the tests and glosses behind every routing-row term, the anti-terms that feel like criteria but are not, and the one-line announcement form.
  • plugins/awesome-kit/skills/orchestrate/references/tuning-selection.md The ranked knobs for a routing row that fires more or less often than you want, with the announcement line as the measuring instrument.
  • plugins/awesome-kit/skills/orchestrate/references/why-delegate.md The economics behind the procedure and its anti-pattern catalogue. Context for a change, not needed to run the skill.

Backend launch mechanics

  • plugins/awesome-kit/skills/orchestrate/references/codex-dispatch.md Codex CLI launch: the flag catalog, the absolute-path rule, exit-0-is-not-success, sandbox limits, and the custom-provider predicate.
  • plugins/awesome-kit/skills/orchestrate/references/opencode-dispatch.md OpenCode CLI launch: the one invocation, entry resolution through the model registry, monitoring, and its boundary-free sandbox.

Scripts

  • plugins/awesome-kit/skills/orchestrate/scripts/orchestration_guidance.py The policy renderer: merges the four configuration layers, detects the dispatch backends on this machine, and prints the resolved routing policy; --explain and --paths inspect the layering.
  • plugins/awesome-kit/skills/orchestrate/scripts/dispatch.py Launches a Codex unit through the shared argv builder and keeps a content-addressed cache of completed dispatches.
  • plugins/awesome-kit/skills/orchestrate/scripts/bootstrap_guard.py Checks that the bootstrap plugin provisioned this one, and re-executes the process under its venv. A vendored copy lives beside every script that needs it.
  • plugins/awesome-kit/skills/orchestrate/scripts/presence_probe.py Prints a few lines only when the sibling presence plugin is installed and current, otherwise nothing. Standard library only, so it runs standalone.
