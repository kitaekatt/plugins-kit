The orchestrate skill that delegates implementation units to background agents: its procedure, shipped routing policy, the per-machine policy renderer, and the dispatch and configuration references

This is the orchestrate skill. It puts the main agent in the orchestrator role and delegates every implementation unit to background agents, so the main context holds coordination, judgment, and conclusions rather than raw work product. Two halves define its shape: the durable half is a fixed procedure (render the policy, decompose the work, route each unit to a model and a backend, launch, verify, and synthesize), and the variable half is configuration, because the model lineup, the available dispatch backends, and the remaining usage capacity differ from machine to machine and user to user. That difference is why the directory splits a stable procedure from rendered configuration and per-backend launch mechanics instead of writing the whole policy inline.

Where to start

Start with plugins/awesome-kit/skills/orchestrate/SKILL.md - it is the entry point and the whole procedure, and it names the policy renderer to run first and the reference to load at each step, so every other file here is reached from it.

Routes

  • Render and route a unit
    1. plugins/awesome-kit/skills/orchestrate/SKILL.md - the procedure; step 2 runs the renderer once, inline, before decomposing.
    2. plugins/awesome-kit/skills/orchestrate/scripts/orchestration_guidance.py - prints the resolved policy: the routing rows, the detected backends, and usage capacity.
    3. plugins/awesome-kit/skills/orchestrate/defaults/orchestration.yaml - the shipped rows and lexicon the renderer merges and renders.
  • Launch a Codex unit
    1. plugins/awesome-kit/skills/orchestrate/references/codex-dispatch.md - the flag shape, the absolute-path rule, and the sandbox bounds.
    2. plugins/awesome-kit/skills/orchestrate/scripts/dispatch.py - builds the argv through the shared builder, resolves the model through llm-scripting-kit, and caches the run.
    3. plugins/awesome-kit/skills/orchestrate/scripts/bootstrap_guard.py - re-execs the script under the plugin's bootstrap venv first.
  • Tune which row fires
    1. plugins/awesome-kit/skills/orchestrate/references/tuning-selection.md - which keys change a row's frequency, ranked by travel per risk.
    2. plugins/awesome-kit/skills/orchestrate/references/configuration.md - the full schema, the four layers, and the merge rules the edits must follow.
  • Understand why it is shaped this way
    1. plugins/awesome-kit/skills/orchestrate/references/why-delegate.md - the economics and the anti-pattern catalogue.
    2. plugins/awesome-kit/skills/orchestrate/references/lexicon.md - the shape terms the routing rows and announcements use.

The procedure

plugins/awesome-kit/skills/orchestrate/SKILL.md - the orchestrator procedure, end to end: render the policy, decompose, route each unit, launch, verify, and synthesize. Run it to orchestrate; edit it to change the durable rules.

Policy and configuration

plugins/awesome-kit/skills/orchestrate/defaults/orchestration.yaml - the shipped policy (routing rows, the lexicon, and backend records), the lowest of four config layers. Open it to see what the rendered policy defaults to before an override changes it.

plugins/awesome-kit/skills/orchestrate/references/configuration.md - the full configuration schema: the two halves, the four layers, and the merge rules. Open it before you write an override file.

plugins/awesome-kit/skills/orchestrate/references/tuning-selection.md - which keys change how often a routing row fires, ranked by travel per risk. Open it when a row is matching too much or too little.

Renderer and dispatch

plugins/awesome-kit/skills/orchestrate/scripts/orchestration_guidance.py - renders the resolved policy (routing rows, detected backends, usage capacity) from the four layers. Run it once, inline, before decomposing.

plugins/awesome-kit/skills/orchestrate/scripts/dispatch.py - runs a Codex unit through the model registry and the shared argv builder, with a content-addressed cache. Open it to inspect dispatch or to list cached runs.

plugins/awesome-kit/skills/orchestrate/scripts/bootstrap_guard.py - the vendored guard that checks whether bootstrap provisioned the plugin and re-execs the scripts under its venv. Open it when a script fails to find a dependency.

Rationale and vocabulary

plugins/awesome-kit/skills/orchestrate/references/why-delegate.md - the economics and the anti-pattern catalogue behind the procedure. Open it to understand or argue a design choice, not to run the skill.

plugins/awesome-kit/skills/orchestrate/references/lexicon.md - the controlled vocabulary: the shape terms the routing rows and dispatch announcements use, with tests and glosses. Open it to learn a term or check an announcement.

Backend launch mechanics

plugins/awesome-kit/skills/orchestrate/references/codex-dispatch.md - the exact Codex CLI flags, the absolute-path rule, the sandbox bounds, and custom-provider mechanics. Load it after you have chosen Codex and before you compose the launch.

plugins/awesome-kit/skills/orchestrate/references/opencode-dispatch.md - the exact OpenCode CLI flags and the no-sandbox caveat. Load it after you have chosen OpenCode.
