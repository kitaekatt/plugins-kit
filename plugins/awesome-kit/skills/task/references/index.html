Task skill reference documents for communication, hand-off authoring, and triage

Four Markdown documents set the task skill's working agreements for work that outlives a single session: a canonical glossary the others cite instead of redefining, an authoring contract for the folders the skill scaffolds, with a worked example of the file those folders auto-load, and an audit protocol for the tasks those folders track. None of them is code; they are the text a task's agents are held to, so a change here changes what every later session of a task does before it touches a tool. The dependency runs one way: the glossary feeds the authoring contract, and the contract feeds both the example and the triage protocol. The contracts are checked, not just read: the task CLI's validate verb enforces the template's line budgets, and the triage protocol audits task folders against live repository state.

Where to start

Open plugins/awesome-kit/skills/task/references/communication-framework.md first: it defines the small set of terms (work-unit, the auto-loaded versus on-demand gates, State A and State B, the hand-off baton) that the other three documents use without redefining. With those terms in hand, the template reads as a contract and the example as its worked proof.

Routes

  • Author or rotate a task folder
    1. plugins/awesome-kit/skills/task/references/communication-framework.md - read once for the terms; every document downstream assumes them.
    2. plugins/awesome-kit/skills/task/references/handoff-template.md - the section-by-section contract for the folder's three documents, including the line budgets the validator enforces and the rotation fix for a document that has outgrown them.
    3. plugins/awesome-kit/skills/task/references/example-claude-md.md - when a section of the contract feels abstract, this is the populated shape to imitate.
  • Triage the open tasks
    1. plugins/awesome-kit/skills/task/references/task-triage-protocol.md - select every open and deferred task, audit each against live repository state, and present one recommendation at a time.
    2. plugins/awesome-kit/skills/task/references/handoff-template.md - the update and merge rulings rotate the folder per this guide before the CLI verb runs.

The shared vocabulary

  • plugins/awesome-kit/skills/task/references/communication-framework.md - the canonical glossary: work-unit, the auto-loaded versus on-demand gates, the three-part end-of-turn template, State A and State B, the hand-off baton, and the provenance triad. Open it whenever a term in a task folder, a skill, or one of the documents here needs its definition.

Authoring a task folder

  • plugins/awesome-kit/skills/task/references/handoff-template.md - how to fill in and keep healthy the folder's three live documents, with the required section shape and the enforced line budgets. Open it when scaffolding a folder or rotating one that has grown.
  • plugins/awesome-kit/skills/task/references/example-claude-md.md - a generalized, fully populated example of the folder's auto-loaded file, with project specifics replaced by placeholders. Open it when a template section feels abstract.

Triage and disposition

  • plugins/awesome-kit/skills/task/references/task-triage-protocol.md - the agent-side protocol, which has no CLI verb, for auditing open and deferred tasks and applying the user's ruling: archive, close, defer, update, merge, or reviewed-keep. Open it when a project's task list needs cleaning up.
  • skills awesome-kit skills: session-interaction skills (debug-context, recap, verbose-updates), the task-folder system with its 14-verb CLI and design diagrams, and the plugin-ecosystem poster generator
  • SKILL.md The task skill definition one level up: the CLI verbs and the skill's own pointers into these documents.
