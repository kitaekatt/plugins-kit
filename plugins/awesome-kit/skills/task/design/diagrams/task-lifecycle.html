Task Lifecycle — Operations as Inputs

Operations feed the lifecycle: each shows the state it acts on and the state it produces; validate classifies Active / Invalid / Remote; read ops (list, status) resolve through validate

Operations are inputs

  • • Each operation shows the state it acts on and the state it produces.
  • • An Abstract task must go through init to become Active — the only way in.
  • • work auto-inits; update refreshes + re-validates.
  • • reopen (left of close) returns to Active only while the folder still exists.

validate classifies; reads resolve through it

  • • validate is the gate on work; errors AND warnings block.
  • • Outcomes: Active (valid), Invalid (fix forward), Remote (tmp + host mismatch).
  • • list and status are read ops; they resolve a task's current classification via validate.

archive, and not shown

  • • archive applies only to an Active task: Active → archive → Archived.
  • • close keeps the folder (Closed); delete removes it (Gone) from Archived.
  • • move (relocate + rewrite refs) is omitted; so are Blocked / Orphaned (in the spec).
