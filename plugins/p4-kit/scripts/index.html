p4-kit plugin scripts for bootstrap guarding, legacy-config cleanup, and Perforce code-review preparation, dispatch, and profile rendering.

These are the runnable entry points of the p4-kit plugin, the Perforce side of the shared code-review machinery. Every script here starts from the same two facts: a shared review library that the bootstrap plugin provisions into a per-plugin virtual environment, and a guard that fails fast with an actionable install message when that provisioning never happened. The scripts split into three jobs: keeping that guard canonical, sweeping a dead legacy config file, and preparing, dispatching, and rendering reviews of Perforce changelists. The pipeline a review runs on lives in the bootstrap plugin; what sits here is the surface that knows how Perforce behaves.

Where to start

Open prepare_review.py first: its docstring documents the bundle schema every later review stage reads, so it is the fastest way back into the whole flow. When a script exits 3 or runs under the wrong interpreter, open bootstrap_guard.py instead, because the guard is the only place that exit code and the re-exec logic live.

Routes

  • Review a changelist: prepare_review.py on the change number writes the JSON bundle and the diff chunks to disk; run_review_lane.py dispatches each configured endpoint lane against that bundle; parse_review_lane.py parses one native lane's JSON output; and a final prepare_review.py run in its cleanup mode deletes the auto-shelf only while its fingerprint still matches.
  • Cold start: every entry script here calls bootstrap_guard.py before its first shared-library import, so the process re-execs under the plugin's provisioned interpreter; when bootstrap never ran for the plugin the import fails and the guard exits with code 3 and the install message.
  • Show the active profiles: render_review_profiles.py with a project root renders the resolved profile table; resolution, merging, and rendering live in the shared library, so a change to profile shape goes there rather than here.

Bootstrap guarding

bootstrap_guard.py
The canonical source for the guard every plugin vendors byte-for-byte. Open it to change the provisioning check, the exit-3 install message, or the re-exec that puts a script under the plugin's interpreter.

The guard must stay stdlib-only and must never import the shared library. It is the code that runs precisely when that library is absent, and a byte-identical vendored copy sits inside every plugin, so a change here is a change everywhere it is vendored.

Legacy-config cleanup

cleanup_legacy_config.py
A bootstrap-invoked cleanup that deletes the per-project config files earlier releases wrote and nothing consumed. It is a no-op when nothing is present, so it can stay installed until the last legacy file is swept up.

Review preparation

prepare_review.py
Describes the changelist, chunks its diff, collects the ancestor guidance files, runs the workspace hygiene scans, and writes the JSON bundle the reviewers read. Open it to change what a review sees or to add a bundle key.

Lane dispatch and output parsing

run_review_lane.py
Dispatches one configured endpoint review lane. It probes the installed scripting kit for every flag it will pass and exits 2 with an update message when one is missing, so a stale kit reads as a fixable error instead of a silent empty review.
parse_review_lane.py
Parses one native code-review lane's JSON output. Thin entry: re-exec under the plugin interpreter, then delegate to the shared lane-output reader.

Profile rendering

render_review_profiles.py
Renders the resolved code-review profile table for a project root. Thin entry: re-exec under the plugin interpreter, then delegate to the shared resolver that owns the CLI contract.
