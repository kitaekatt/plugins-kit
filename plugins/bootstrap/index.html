The bootstrap plugin's session hooks, bootstrap CLI, and shell Python resolvers that provision user machines, alongside the cross-plugin contracts for dependencies, execution events, interrupts, and model declarations.

This is the bootstrap plugin: it provisions plugin tools, Python venvs, git dependencies, and per-user config at session start. This directory holds wiring around the pass, not the pass: the pass runs in the shared library below. Session hooks launch it in the background; terminal levers inspect or force it; shell resolvers keep project Python visible. It also ships cross-plugin contracts: dependency branches, model declarations, execution events, and interrupts. Healthy bootstrap is silent: quiet session start means checks passed.

Where to start

Start with plugins/bootstrap/README.md: it states pass scope, command surface, and writes. Hooks are thin launchers.

Routes

  • Session start
    1. plugins/bootstrap/hooks/hooks.json wires SessionStart and UserPromptSubmit to hook scripts.
    2. plugins/bootstrap/hooks/sessionstart/session-bootstrap.sh resolves interpreter, applies cooldown, delegates to engine.
  • Terminal levers
    1. plugins/bootstrap/scripts/bootstrap.sh locates plugin tree and interpreter.
    2. plugins/bootstrap/scripts/bootstrap_cli.py holds status, run, codex-hook, install-hook.
    3. plugins/bootstrap/scripts/bootstrap-reset-cooldown.sh clears cooldown.
  • Onboard
    1. plugins/bootstrap/scripts/install_bootstrap_hook.py renders plugins/bootstrap/templates/ensure-bootstrap.sh into project hooks and merges settings.
    2. After that, project SessionStart installs or updates bootstrap first.
