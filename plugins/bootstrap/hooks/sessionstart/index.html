SessionStart hook that starts the bootstrap engine and prepares Windows command shims for extensionless bash levers

This is the SessionStart hook of the bootstrap plugin, and it has one job: turn Claude Code's session-start event into a bootstrap engine pass, and on Windows make sure the levers that pass leaves behind still work. Two bash files do that. One is a thin wrapper that guards the run (session dedup, a per-project cooldown, an alert bypass, and the interpreter names every session needs) and then delegates to the engine. The other is a Windows-only shim library that defines functions to render a .cmd twin beside each extensionless bash lever, because cmd.exe and PowerShell 5.1 cannot run an extensionless file on their own. The two split cleanly: the wrapper runs on every platform, the shim is sourced only on Windows. Everything the engine itself does lives one level up.

Where to start

Open plugins/bootstrap/hooks/sessionstart/session-bootstrap.sh first: the guard logic, cooldown, and env-file writes decide whether a session runs, skips, or re-runs a pass, and the Windows branch that sources the shim starts here too. plugins/bootstrap/hooks/sessionstart/lever-cmd-shim.sh is only reachable once you are already debugging the Windows lever problem.

Routes

  • A background SessionStart pass
    1. Claude Code fires SessionStart and runs the wrapper with no arguments.
    2. plugins/bootstrap/hooks/sessionstart/session-bootstrap.sh reads the hook stdin, applies the session-id and per-project cooldown gates (bypassing them on an unresolved alert or a newer plugin registry), then delegates to the Python engine, whose stdout becomes the JSON hook response.
  • Windows lever shim refresh
    1. plugins/bootstrap/hooks/sessionstart/session-bootstrap.sh sources the shim library on Windows at session start.
    2. plugins/bootstrap/hooks/sessionstart/lever-cmd-shim.sh provides the three functions that resolve the Git-for-Windows bash, render the .cmd text, and write the lever's .cmd twin only when its content changed.

The SessionStart handler

plugins/bootstrap/hooks/sessionstart/session-bootstrap.sh The thin bash wrapper that is the actual SessionStart handler. It parses the few flags the hook can carry, applies the session and cooldown gates, writes the interpreter names into the session env file, and delegates to the engine. Open it to understand why a session runs, skips, or re-runs.

The Windows shim library

plugins/bootstrap/hooks/sessionstart/lever-cmd-shim.sh A sourced function library, inert on its own, that exists only on Windows. It resolves the Git-for-Windows bash, renders a .cmd twin for each extensionless bash lever, and writes the twin only when it changed. Open it when a lever works in Git Bash but not in cmd.exe or PowerShell.
