Reference for the bootstrap engine's behavior, the bootstrap.json manifest, the bootstrap CLI, and the patterns for managing plugin dependencies and their lifecycle

This is the reference skill for the bootstrap engine. It covers the full behavior surface a reader needs to interpret SessionStart messages, write or extend a bootstrap manifest, run the bootstrap CLI, and reason about plugin dependency lifecycle. The references split along the reader's question: engine mechanics and reload semantics, manifest schema and terminal operations, dependency and library patterns, the Python environment contract, and fleet and data operations.

Where to start

Open plugins/bootstrap/skills/bootstrap/SKILL.md for the message-outcome table and the update-lifecycle protocol that every other document builds on. For a specific manifest field, jump straight to plugins/bootstrap/skills/bootstrap/references/manifest-reference.md.

Routes

  • Configure a new plugin dependency
    1. plugins/bootstrap/skills/bootstrap/references/manifest-reference.md (declare the entry)
    2. plugins/bootstrap/skills/bootstrap/references/engine-internals.md (how the engine processes it)
    3. plugins/bootstrap/skills/bootstrap/references/plugin-reload-lifecycle.md (when it goes live)
  • Diagnose a bootstrap pass failure
    1. plugins/bootstrap/skills/bootstrap/SKILL.md (message outcomes)
    2. plugins/bootstrap/skills/bootstrap/references/remediation-reference.md (check methods and fixes)
    3. plugins/bootstrap/skills/bootstrap/references/bootstrap-cli.md (run a pass manually)
  • Wire an optional plugin dependency
    1. plugins/bootstrap/skills/bootstrap/references/deferred-requirements.md (detect early, ask late)
    2. plugins/bootstrap/skills/bootstrap/references/action-triggered-install.md (plugin-specific mechanics)
    3. plugins/bootstrap/skills/bootstrap/references/manifest-reference.md (install: manual field)

Engine and lifecycle

  • plugins/bootstrap/skills/bootstrap/references/engine-internals.md -- two-phase architecture, engine phases, registry repair, and the single-instance lock. Open it when you need to trace what a pass actually does or why a registry record is malformed.
  • plugins/bootstrap/skills/bootstrap/references/plugin-reload-lifecycle.md -- the measured rule for when a code edit, registration change, or version bump goes live. Open it before telling a user to restart.

Manifest and CLI

  • plugins/bootstrap/skills/bootstrap/references/manifest-reference.md -- the full bootstrap.json schema, every field, merge semantics, and the session-env allowlist. The primary reference for writing or extending a manifest.
  • plugins/bootstrap/skills/bootstrap/references/bootstrap-cli.md -- every verb of the bootstrap command: run, reset, profile, python, codex-hook, install-hook, and project-only mode. Open it for terminal operations.
  • plugins/bootstrap/skills/bootstrap/references/plugin-setup-pattern.md -- how a plugin declares user-specific config (API keys, paths) via the config section or the legacy setup.py CLI. Short; open it when adding a new plugin that needs credentials.

Dependency and library patterns

  • plugins/bootstrap/skills/bootstrap/references/dependency-philosophy.md -- the principles behind download-vs-respect, PATH repair, and per-tool choice. Open it before deciding how a new tool entry should behave.
  • plugins/bootstrap/skills/bootstrap/references/library-consumption.md -- every mode by which a Python process reaches a published shared library, with support status and update mechanics for each. Open it when wiring a cross-plugin or cross-project import.
  • plugins/bootstrap/skills/bootstrap/references/action-triggered-install.md -- the three-part flow for a specialty plugin that only some developers need: declare manual, preflight at the point of need, install on consent. Open it when a skill depends on an optional plugin.
  • plugins/bootstrap/skills/bootstrap/references/deferred-requirements.md -- the general detect-early-ask-late pattern and the add_deferred_requirement API. The principle behind action-triggered install and any optional credential or SDK.

Environment and remediation

  • plugins/bootstrap/skills/bootstrap/references/python-interpreter.md -- the BOOTSTRAP_PYTHON and BOOTSTRAP_PROJECT_PYTHON contract, call-site expressions, shell persistence, and opt-out rules. Open it when a script needs the right interpreter.
  • plugins/bootstrap/skills/bootstrap/references/remediation-reference.md -- the check method and remediation action for every condition category the engine handles, plus the UX ladder that ranks every user-facing message. Open it to understand why a pass surfaces a particular prompt.

Fleet and data

  • plugins/bootstrap/skills/bootstrap/references/fleet-management.md -- the ensure-bootstrap hook and how an administrator gets the plugin onto every machine in a project. Open it when onboarding a new team or project.
  • plugins/bootstrap/skills/bootstrap/references/durable-project-data.md -- where a plugin writes project data (.plugin-data vs .local-data), the size gate, and the rule that bootstrap never writes durable artifacts. Open it before choosing a storage path for generated output.
