Bootstrap plugin shared library that processes manifests, runs tool and environment checks, and defers fixes that need user attention.

This directory holds the Python modules behind the bootstrap plugin's session pass. The pass checks the machine: tools, PATH, environment, and manifests. It installs whatever it can without a terminal and defers the rest into a queue a user runs with consent. Modules are organized by job rather than call graph, and every check follows the same shape: a side-effect-free check, an idempotent fix, an authoritative re-check.

Where to start

Open engine.py first: it sequences the whole pass and its docstrings name what each phase calls. For a behavior, go to the module named for that job below; the check/fix pair is the unit you will edit.

Routes

  • Session-start pass: the shell hook stamps a cooldown, harvest.py relaunches engine.py, which runs the phases under proc_lock.py and appends the verdict with log.py.
  • Deferring a fix: a check attaches an elevation descriptor, fix_queue.py collects them into the queue, and fix_runner.py executes it once a terminal is available.
  • Delivery of a verdict: the pass writes a pending display file, and display_relay.py stamps its age and emits it at the next prompt.

The pass

  • engine.py: the pass itself: lock, phase order, crash containment, hook response.
  • harvest.py: relaunches a pass when one did not run.
  • proc_lock.py: the engine-wide lock every launcher stands down behind.
  • stamps.py: pass stamps and per-project cooldowns.
  • log.py: appends to the per-plugin bootstrap log.
  • session_env.py: buffers the session env-file block, written once per pass.

The code_review and managed_state subpackages have their own pages.

Manifest loading

  • manifest_merge.py: the deep merge layered manifests and the env gate share.
  • manifest_lint.py: validates a manifest before a pass trusts it.
  • plugin_resolve.py: resolves plugin references to install locations.

Tool checks

  • tool_check.py: check-first resolution and the re-check that decides a tool is present.
  • tool_paths.py: where an installed tool lands and its env var.

Package backends

  • apt.py: Ubuntu installs; defers, never prompts, without passwordless sudo.
  • brew.py: macOS formula and cask installs; brew itself is detected only.
  • scoop.py: Windows userspace installs.
  • npm_check.py and pypi_check.py: node and Python package installs.
  • git_dep_check.py: dependencies checked out from git.
  • downloader.py: sha256-verified binaries into the local bin.

Tool environments

  • venv_check.py: per-plugin virtualenvs: provision, export, re-exec.
  • interpreter_env.py: the interpreter a plugin's venv should use.
  • python_stub_check.py: finds a WindowsApps python stub that shadows a real interpreter.

Paths

  • path_check.py: adds and removes PATH entries in shell config and the registry.
  • path_prune.py: finds dead PATH entries and queues a consent task to delete them.

Environment and machine identity

  • env_manifest.py: the layered env.json files, the machine registry, and the phase gate.
  • env_features.py: check/fix pairs for symlinks, shell rc blocks, macOS defaults.
  • env_var_check.py: persists env vars to rc or registry and exports them live.
  • platform_detect.py: which OS the pass runs on.

Deferring and delivery

  • fix_queue.py: collects elevation descriptors into the queue; cheap work first, downloads last.
  • fix_runner.py: the one place with a terminal: plan, then the queue.
  • display_relay.py: stamps a pending verdict with its age at delivery.

Codex integration

  • codex.py: Codex CLI detection and the one sanctioned exec argv.
  • codex_hook.py: installs the project-local Codex hook and pre-checks source-control ignores.
  • agent_skills_check.py: links the project's Claude skills where Codex reads them.

Plugin config

  • config.py: bootstrap's own config: load, migrate, save.
  • config_check.py: init, validate, and autodetect a plugin's config.
  • config_resolve.py: merges shipped defaults, user, and project layers; a bad layer errors loudly.

Marketplace and registry

  • marketplace_lifecycle.py: the largest module: marketplace and plugin install and update.
  • registry_repair.py: repairs the plugin registry when it drifts.

Vendored into other plugins

  • bootstrap_guard.py: vendored into other plugins: provision check, and a re-exec into the plugin venv before the import.
  • path_repair.py: also vendored: PATH repair for plugin scripts.

Both stay stdlib-only and never import the package; a drift test keeps copies in sync.

Shared plumbing

  • atomic_write.py: the one atomic write: temp file next to destination, then rename.
