Bootstrap engine and shared library for platform tool installation, Codex CLI integration, environment and config management, code review, and remediation.

This is the shared Python library behind the bootstrap plugin: the code its SessionStart engine, hooks, and scripts import rather than a runnable plugin of its own. Every module follows the same shape -- a side-effect-free check, a fix, and an authoritative re-check -- so a pass is idempotent and a second run writes nothing when the first already fixed things. Most of it is standard-library only because the hooks run before a plugin venv exists; a few modules are thin aliases that make a bootstrap name resolve to a module owned by another distribution. It splits by job: the pass itself, the platform installers, Codex wiring, config and environment resolution, and the deferred-remediation queue.

Where to start

Start with plugins/bootstrap/bootstrap_lib/engine.py -- the SessionStart pass that reads the manifests, runs each phase, and writes the verdict the hooks surface. If your question is why a plugin cannot import the library at all, open plugins/bootstrap/bootstrap_lib/bootstrap_guard.py first, since it runs before a venv exists.

Routes

  • A root-requiring tool gets deferred
    1. plugins/bootstrap/bootstrap_lib/apt.py defers the install when there is no passwordless sudo.
    2. plugins/bootstrap/bootstrap_lib/fix_queue.py harvests that elevation descriptor into a deferred task.
  • Codex becomes available and a skills link is made
    1. plugins/bootstrap/bootstrap_lib/codex_detection.py probes the CLI.
    2. plugins/bootstrap/bootstrap_lib/agent_skills_check.py links the project's Codex skills directory to Claude Code's so Codex reads the same skills.
  • Config resolves at read time
    1. plugins/bootstrap/bootstrap_lib/config_check.py seeds a default at session start.
    2. plugins/bootstrap/bootstrap_lib/config_resolve.py deep-merges the shipped, user, and project layers on every read.
  • A pass delivers its verdict
    1. plugins/bootstrap/bootstrap_lib/engine.py writes the pending verdict.
    2. plugins/bootstrap/bootstrap_lib/display_relay.py stamps it with its age and emits it on the next prompt.

The engine pass

  • plugins/bootstrap/bootstrap_lib/engine.py -- the pass itself: reads the manifests, runs each phase under a single-instance lock, and writes the verdict. Trace a phase or a message here.

Tool installation

  • plugins/bootstrap/bootstrap_lib/apt.py -- Ubuntu installs via apt-get, never prompting; defers to the remediation queue when there is no passwordless sudo.
  • plugins/bootstrap/bootstrap_lib/brew.py -- macOS installs via Homebrew; detects Homebrew itself only and routes casks that need sudo to the queue.
  • plugins/bootstrap/bootstrap_lib/downloader.py -- downloads tool binaries into the user's local bin, verifies the sha256, and extracts archives.

Codex CLI

  • plugins/bootstrap/bootstrap_lib/codex_detection.py -- asks whether a usable Codex CLI is installed; the stdlib-only probe the engine and the skills check call.
  • plugins/bootstrap/bootstrap_lib/codex.py -- an alias: the bootstrap codex name resolves to the codex command builder in the katsoft-llm-kit distribution.
  • plugins/bootstrap/bootstrap_lib/codex_hook.py -- installs and maintains the guarded user-level Codex SessionStart hook and strips legacy project hooks.
  • plugins/bootstrap/bootstrap_lib/agent_skills_check.py -- links the project's Codex skills directory to Claude Code's so Codex reads the same skills, after excluding the generated path from version control.

Config and environment

  • plugins/bootstrap/bootstrap_lib/config.py -- loads, migrates, and persists the bootstrap plugin's own config.
  • plugins/bootstrap/bootstrap_lib/config_check.py -- seeds and validates a plugin's config at session start and runs its autodetect scripts.
  • plugins/bootstrap/bootstrap_lib/config_resolve.py -- resolves a plugin's effective config at read time by deep-merging the shipped, user, and project layers.
  • plugins/bootstrap/bootstrap_lib/env_manifest.py -- the env manifest core: layered loading, machine-identity resolution, and the per-origin env gate.
  • plugins/bootstrap/bootstrap_lib/env_features.py -- the env feature mechanisms: symlinks, shell rc, macOS defaults, and the env-checks command runner.
  • plugins/bootstrap/bootstrap_lib/env_var_check.py -- persists and live-exports env vars to the shell rc or the Windows registry, and guards plugin-root names.

Remediation

  • plugins/bootstrap/bootstrap_lib/fix_queue.py -- harvests deferred operations into a typed task list, writes the queue file and the fix scripts, and launches the runner on a fix-all.

Guards, aliases, and session plumbing

  • plugins/bootstrap/bootstrap_lib/bootstrap_guard.py -- vendored into plugins: fails with an actionable message when bootstrap never provisioned, and re-execs into the plugin venv.
  • plugins/bootstrap/bootstrap_lib/_contracts_alias.py -- makes a bootstrap contract module resolve to the canonical module in the katsoft-contracts distribution.
  • plugins/bootstrap/bootstrap_lib/_llm_kit_alias.py -- makes a bootstrap module resolve to the canonical module in the katsoft-llm-kit distribution.
  • plugins/bootstrap/bootstrap_lib/execution_event.py -- an alias: the bootstrap execution_event name resolves to the katsoft-contracts module.
  • plugins/bootstrap/bootstrap_lib/claudx.py -- keeps nested claude children faithful to a claudx test session by validating and re-deriving the plugin flags.

Review and persisted state

  • code_review -- the code-review machinery: rule defaults, mechanical checks, and the repository-level pass; open it when a finding is wrong or a rule needs tuning.
  • managed_state -- the library's persisted managed state; open it when stored state looks wrong or needs inspecting.
