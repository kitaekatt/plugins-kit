Shared VCS-neutral code-review pipeline for p4-kit and git-kit

This package is the shared back half of the code-review pipeline that p4-kit and git-kit both run. The plugins keep their VCS-specific front halves -- change resolution, diff fetching, header parsing -- and hand off everything format-neutral here: per-file section splitting, chunking, the standards-file ancestor walk, submit-gate matching, deterministic scans, and bundle writing. The reviewer-lane machinery lives in the same place: canonical prompt text shared by the native-agent and configured-endpoint dispatch paths, the issue-array schema, and profile resolution with model fallbacks. A third concern is the memory that survives a re-run of the same change, so already-declined findings render collapsed instead of being re-litigated. Nothing here names a VCS; the adapters in the owning plugins supply the identifiers.

Where to start

Open pipeline.py first: its top docstring diagrams the front-half and back-half split, and assemble_bundle is the call that composes every other module here. If you only need the contract, the package docstring in __init__.py is short and complete.

Routes

  • Prepare a bundle: pipeline.py splits the diff into sections, assemble_bundle pulls in chunking.py and claude_mds.py, and emit_bundle writes the bundle to disk.
  • Scan one file mechanically: mechanical_config.py resolves the check layers, and the mechanical/ registry dispatches scan_file over the per-file snapshot.
  • Choose a lane's model: review_profiles.py resolves model, fallbacks, and effort; lane_prompts.py decides which lanes may take an endpoint id.
  • Re-run the same change: ledger.py supplies ledger_hits at prepare time and record_from_file after the verdict, as the --ledger-record back-end.

The shared back half

  • pipeline.py -- the composition point: split_sections, run_vcs, assemble_bundle, emit_bundle. Open when bundle fields or file routing (claims, machine-emitted files) change.
  • __init__.py -- the package contract: front halves deliver a raw diff plus a per-file action map, and everything after that is here.
  • chunking.py -- byte-balanced chunking at directory boundaries plus the chunk index writer. Open when a chunk comes out too large or splits at the wrong boundary.
  • _globs.py -- claim-glob matching where an exclusion pattern beats every positive. Open when a claimed file is missed or over-claimed.

Reviewer lanes

  • lane_prompts.py -- the single text source for lane prompts, the issue-array schema, and the agent-versus-endpoint dispatch sets. Bump PROMPT_VERSION whenever a prompt changes.
  • lane_output.py -- parses and validates one lane response against its prepared bundle, including citation verification for the standards-compliance reviewer. Its CLI validates a response standalone.

Deterministic checks

  • mechanical_config.py -- additive shipped, user, and project layers of pattern checks, with hard caps and per-match timeouts.
  • mechanical/ -- Seam A: per-file checks that see snapshot text only: diff parsing, non-ASCII, absolute paths, structured-data parsing, duplicate keys, and CSV/TSV column counts; the registry and dispatcher live in mechanical/__init__.py.
  • mechanical_repository/ -- Seam B: checks that query the frozen repository snapshot: local Markdown link and anchor targets, and CPython compilation under the mapped interpreter version.
  • machine_emitted.py -- banner-signature detection, the content axis for machine-emitted artifacts.
  • machine_emitted_paths.py -- declared write-path detection, the path axis. Either axis removes a file from the reviewer chunks; it is reported, never silently skipped.
  • triviality.py -- the pure-mechanical skip guard for claimed files. It fails closed, so an unparseable diff always gets the full review.

Review configuration

  • review_profiles.py -- resolves sparse user and project overrides over the shipped profiles. Open when a lane dispatches to the wrong model or effort.
  • defaults/review_profiles.yaml -- the shipped data_only and code profiles.
  • defaults/mechanical_checks.yaml -- the shipped pattern-check layer, intentionally empty.

Re-run memory

  • ledger.py -- declined findings keyed by file, reason, and a normalized wording anchor; a baseline token re-surfaces them when the change moves underneath.
