  • drivers Execution drivers that claim units from a prepared wave and record their outcomes through the durable run store; how each unit's text is produced varies by driver.

The generic library for LLM-in-the-loop batch content pipelines, with canonical store, freshness, validation, LLM platform, CLI scaffold, durable execution, delivery, audit, providers, round-trip, and VCS seams.

This is the importable core of content-pipeline-kit: the shared machinery for LLM-in-the-loop batch content systems, written with no project-specific knowledge. Twelve subpackages sit one level down, each importable on its own; the package deliberately re-exports nothing, so the import graph stays a strict DAG and a consumer adopts one piece without pulling in the rest. Every subpackage states its dependency contract in its own init module, and the opt-in components are never reached from the core import path. A surprising behavior is explained in the module docstring, alongside its deliberate deviations from the source systems.

Where to start

Open __init__.py first: its docstring is the map, one line per subpackage. Then go straight to the subpackage matching the behavior you are changing.

Routes

  • Wire a command line: cli/scaffold.py -> cli/run.py -- the scaffold dispatches; the adapters hand it the command registry.
  • Drive a durable run: execution/store.py -> execution/controller.py -> execution/wave.py -- create the run, prepare the wave, loop until it drains.
  • Audit a finished batch: audit/auditor.py -> audit/report.py -- classify the findings, then roll them into coverage and cost-per-dollar views.
  • Deliver a changeset: deliver/inplace.py -> vcs/seam.py -- apply the marked rows, then drive the backend seam; Perforce ships in p4-kit, not here.

Package entry and defaults

  • __init__.py -- the package docstring: the strict-DAG import rule and a one-line scope per subpackage.
  • default_config.yaml -- plugin-level defaults only: the response-cache directory and model-binding overrides; per-project values live in project config.

The canonical store

  • store/projection.py -- the projected value-read that delivery and audit both consume; open it when a delivered value looks wrong.
  • The remaining store modules carry the attributed record and candidate shapes; the store is the source of truth for machine content.

Freshness

  • freshness/classify.py -- the two-tier classification the whole package gates on: fresh, stale, or missing, plus the needs-generation set.
  • The hashing, tier, seed, and ensure modules supply the content hashes and the tiers behind it.

Validation

  • validate/contract.py -- the one-rule-many-call-sites validator contract; the worker protocol and the adapter evaluate submissions against it.
  • The floor guard and the riders modules are the guard rails around that contract.

The LLM platform

  • llm/platform.py -- the platform binding: transport, cache, cost, budget, and the halt taxonomy a budget stop is built on.
  • llm/backends.py -- where a model declaration resolves to a drive and a model; the create-run path asks it.
  • Convergence and the YAML extraction helper are opt-in; keys, models, and the client come from llm-scripting-kit.

Pipeline shapes

  • pipeline/workunit.py -- the flat and graph work-unit strategies that decide what a wave may contain.
  • pipeline/single_pass.py -- the single-pass shape, plus the Gate and run-gates seam the run controller runs.
  • pipeline/convergence_loop.py -- the convergence-loop alternative to a single pass; open it when the pipeline validates until the output converges.

Durable execution

  • execution/store.py -- the SQLite run store: runs, units, attempts, atomic claims, fencing tokens, leases. The only place run truth lives.
  • execution/controller.py -- prepare and finalize: the gate run that records skips and returns a wave, and the apply of every accepted unit.
  • execution/wave.py -- the ready-wave query; for a graph run, an empty wave is not proof of completion -- the docstring has the loop shape.
  • execution/protocol.py -- the versioned JSON worker protocol as mountable handlers: the machine-facing counterpart of the CLI.
  • execution/adapter.py -- the RunAdapter contract a consumer implements: reconstruct a unit, build the request, supply validators, apply, reconcile.
  • Model carries the record shapes and state machine; workerpack is the per-worker packaging. How a claimed unit gets its text is the drivers page's job.

CLI scaffold

  • cli/scaffold.py -- dispatch, scope filtering, did-you-mean, and uniform YAML output: the core a project CLI wires onto.
  • cli/run.py -- the command adapters over the run store; argv parsing only, no execution logic.
  • Budget and bulk add the halt-aware sweep -- preflight, then a clean stop with partial progress -- and unsupported is the sticky exclude-forever registry.

Delivery and the VCS seam

  • deliver/inplace.py -- in-place mutation with the do-no-harm marker and first-class revert; rewrites only machine-owned rows, and only on diff.
  • deliver/projection.py -- the append-only alternative: an artifact beside the source, rolled back by rename, never overwritten.
  • vcs/seam.py -- the backend seam both delivery modes drive; git is the default, null is the no-op, Perforce ships in p4-kit.

Audit

  • audit/auditor.py -- classifies every output against policy, the store, and ground truth with the runtime's own classifiers.
  • audit/report.py -- coverage views and the impact-per-LLM-dollar rollups over an audited batch.
  • audit/reasoning_chain.py -- the per-item sidecar: the inputs, each attempt, the rejections, the accepted payload.

Context providers and round-trip

  • providers/registry.py -- the tiered context-provider registry; open it when a generated prompt is missing context.
  • roundtrip/questions.py -- the human-in-the-loop round-trip: the questions a batch asks and the returns it accepts.
