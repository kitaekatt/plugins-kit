Content-pipeline skills: the domain architecture and vocabulary, background-lane and workflow-lane orchestration, and one-unit worker execution.

These four skills are how the content-pipeline plugin is meant to be used, and they are split by the role you play in a run. One is a domain skill: the architecture vocabulary and abstraction map for an LLM-in-the-loop batch content pipeline, plus deeper documents on building, porting, and wiring it. Two are orchestration skills, one per execution lane, because the background-session lane and the Workflow-tool lane are not interchangeable procedures. The fourth is the worker's own procedure for completing a single work unit. Open the skill that matches your seat, and reach for its deeper documents only when you need the mechanism.

Where to start

Open plugins/content-pipeline-kit/skills/content-pipeline-domain/SKILL.md first if you are new to the architecture: it defines the store, freshness, validation, and delivery vocabulary the other three skills assume. If you already know the model, go straight to the skill for your lane, or to the one-unit worker procedure when your session must complete a unit.

Routes

  • Drive a run on background sessions
    1. Open plugins/content-pipeline-kit/skills/background-pipeline/SKILL.md: prepare the wave through the consumer's protocol mount.
    2. Dispatch one bounded wave with dispatch_wave and read status digests at batch boundaries, never unit content.
    3. Apply every accepted unit with finalize_run; a halted run parks until resume_run clears it.
  • Drive a run on the Workflow tool
    1. Open plugins/content-pipeline-kit/skills/workflow-pipeline/SKILL.md; verify the four preconditions, then assemble the wave with build_wave_args.
    2. Invoke run-ready-wave from the top-level session and reconcile the advisory aggregate against the store.
    3. Finalize accepted units with finalize_run; re-entry after any halt is a fresh wave, not a resume.
  • Complete one work unit as a worker
    1. Open plugins/content-pipeline-kit/skills/execute-work-unit/SKILL.md; run the read invocation, the only step that returns unit content.
    2. Write the fenced answer and author the submit envelope, substituting only the fencing token.
    3. Submit; revise the answer on rejection, and on exhaustion run the fail envelope and stop.

Understand the architecture

  • plugins/content-pipeline-kit/skills/content-pipeline-domain/SKILL.md is the architecture vocabulary and abstraction map: the attributed store, two-tier freshness, one-validator-many-sites validation, and the two delivery modes. Open it to learn the terms the other skills assume.
  • plugins/content-pipeline-kit/skills/content-pipeline-domain/references/design-discipline.md is the design philosophy behind the library: each opt-in guardrail, such as human-always-wins, do-no-harm markers, and one-predicate freshness, and the component that embodies it.

Build or port a pipeline

  • plugins/content-pipeline-kit/skills/content-pipeline-domain/references/building-a-pipeline.md is the stepped procedure for a new pipeline: pick the shape and work-unit strategy, wire the store and freshness, register providers, and choose a backend and delivery mode.
  • plugins/content-pipeline-kit/skills/content-pipeline-domain/references/porting-a-pipeline.md is the subsystem-first method for collapsing an existing monolithic LLM-batch tool onto the library in dependency order, pinning its own tests as the equivalence baseline.

Orchestrate a run

  • plugins/content-pipeline-kit/skills/background-pipeline/SKILL.md is the procedure for driving a run through Claude background sessions: prepare, dispatch, read status digests, finalize. The orchestrating session never ingests unit content.
  • plugins/content-pipeline-kit/skills/workflow-pipeline/SKILL.md is the same job through the native Workflow tool: the four preconditions, build_wave_args, the registered run-ready-wave, and reconcile-then-finalize.
  • plugins/content-pipeline-kit/skills/content-pipeline-domain/references/session-recipients.md is the mount owner's guide to the session transport: the protocol to mount, the RunAdapter fields to declare, and the allowlist a worker needs.
  • plugins/content-pipeline-kit/skills/content-pipeline-domain/references/workflow-lane.md is how the workflow lane differs from the background lane: the agent claims its own unit, there is no renewer, and re-entry is a fresh invocation.

Act as a worker

  • plugins/content-pipeline-kit/skills/execute-work-unit/SKILL.md is the one-unit procedure a background worker follows: read, write the fenced answer, author the submit envelope, submit, and fail on exhaustion. Run every invocation exactly as written.
  • content-pipeline-kit Content-pipeline-kit plugin packaging: bootstrap configuration, public API surface contract, one-unit worker agent, consumer contract checker, and parallel wave workflow.
  • README.md The plugin's human-facing README: the higher-level overview to open before choosing a skill.
