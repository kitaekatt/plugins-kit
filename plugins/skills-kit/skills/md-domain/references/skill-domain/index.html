Skill-domain reference documentation for skill-authoring contracts, vocabulary, and audit tools.

This is the reference layer behind the md-domain skill: the contracts a SKILL.md must satisfy, the canonical vocabulary those contracts use, the structural patterns a multi-area skill adopts, and the machine checks that verify all of it. A term book pins the vocabulary, a framework document states the per-type contracts and the audit procedure, a set of authoring patterns covers routing and sub-area configuration, and a small library of command-line tools does the deterministic part of an audit. Two worked pieces show the checks on real material, including the friction they fed back into the framework. Read the vocabulary before the contracts: every contract row and audit verdict in this directory uses its terms without redefining them.

Where to start

Open glossary.md first: it pins every term the contracts and audits in this directory use. Then framework.md when you need the contract itself or the audit procedure.

Routes

  • Audit a skill: framework.md -> scripts.md -> example-audit.md -- the contract rows, the checks that verify them, a finished audit to compare against.
  • Author a domain-skill: glossary.md -> framework.md -> domain-layering.md -- terms first, then the type's contract and assembly order, then the routing surface it exposes.
  • Read the corpus reports: report-usage.md -> scripts.md -- the subcommand reference, then the shared discovery both report views run on.

Vocabulary

  • glossary.md -- canonical terms for skill authoring: the material, the conventions, the design principles, and the six skill types. Open it to pin down a word before arguing about a contract row.

Type contracts

  • framework.md -- the per-type contracts, the universal frontmatter rules, the conditional-requirement grammar, and the audit procedure. Open it before authoring or auditing anything here.
  • schema-fixtures.md -- the smallest legal instance block for every contract, kept valid by a corpus check on each run. Open it to copy a skeleton that passes.

Authoring patterns

  • domain-layering.md -- the routing surface for a domain-skill with several sub-areas: the greeting menu, argument dispatch, and overview detection. Open it when decomposing a large knowledge area.
  • patterns-actions.md -- deterministic multi-step workflows as ordered steps with captured values between them. Open it when a recipe must run the same steps in the same order.
  • subdomain-schema.md -- the configuration a sub-area carries: canonical state terms, operations, scope axes, and readback phrasing. Open it when a sub-area needs a fixed vocabulary.

Audit tooling

  • scripts.md -- the three per-skill command-line utilities for auditing, classifying, and tagging a skill, plus the shared discovery and structural detectors behind them. Open it when running or extending a check.
  • report-usage.md -- the full reference for the roster and hierarchy report subcommands: arguments, locations scanned, row formats. Open it for the exact flag set.

Worked examples

  • example-audit.md -- a complete audit of a real skill against the discipline-skill contract, preserved as an artifact. Open it to see a verdict play out, including the friction it fed back into the framework.
  • example-verification.md -- the pre-ship pass for shell examples in a SKILL.md, built from two real bugs it surfaced. Open it before shipping any skill with copy-paste commands.
