Reference material for the skill-domain: type contracts, canonical vocabulary, structural patterns, schema fixtures, and audit tooling documentation.

This directory is the working reference set for skill-domain authoring. It carries the canonical type vocabulary, the contract rules that make each skill type checkable, and the patterns for decomposed or multi-sub-area skills. The audit material here supports one-skill audits and corpus-wide reports.

Where to start

Open plugins/skills-kit/skills/md-domain/references/skill-domain/framework.md first; it states the per-type contracts and the audit procedure. Use plugins/skills-kit/skills/md-domain/references/skill-domain/glossary.md when a term needs its canonical definition before comparing a skill against a contract.

Routes

  • Learn the type system
    1. Start with the canonical terms in plugins/skills-kit/skills/md-domain/references/skill-domain/glossary.md
    2. Read the contract rules in plugins/skills-kit/skills/md-domain/references/skill-domain/framework.md
    3. Check the smallest legal blocks in plugins/skills-kit/skills/md-domain/references/skill-domain/schema-fixtures.md
  • Audit one skill
    1. Use the contract rules in plugins/skills-kit/skills/md-domain/references/skill-domain/framework.md as the checklist.
    2. Run the deterministic checks documented in plugins/skills-kit/skills/md-domain/references/skill-domain/scripts.md
    3. Compare the output against the worked audit in plugins/skills-kit/skills/md-domain/references/skill-domain/example-audit.md
  • Run corpus reports
    1. Read the report subcommand reference in plugins/skills-kit/skills/md-domain/references/skill-domain/report-usage.md
    2. Use the shared discovery notes in plugins/skills-kit/skills/md-domain/references/skill-domain/scripts.md when the report skill set looks wrong.
