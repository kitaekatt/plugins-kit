The md-domain skill reference documentation for audit framework, standards, lane procedures, authoring patterns, and provenance records

These files are the reference layer for the md-domain skill, which audits and authors markdown artifacts. They separate the shared audit vocabulary from the lane procedures, configurable standards, document-shape patterns, and decision histories. The material is written for agents and for human review of audit output; most files are read on demand rather than top to bottom. A returning reader can use the grouping below to recover the right file for a placement, audit, configuration, or provenance question.

Where to start

Open audit-framework.md first: it defines the vocabulary every audit lane uses and points to the machine-readable registry.

Routes

  • Read a finding: references-finding-taxonomy.md -> audit-framework.md -> standards/references-standards.md
  • Place a fact: cohesion-principles.md -> authoring-patterns/content-authoring.md -> authoring-patterns/three-surfaces.md
  • Configure or extend standards: configuring-standards.md -> authoring-standards.md -> standards/skill-standards.md

Audit vocabulary and registry

  • audit-framework.md -- glossary for audit lanes; read when a term like subject, audit-kind, or taxonomy is unclear.
  • audit-framework.yaml -- machine-readable registry of primitives, compositions, and audit-kind bindings; authoritative on divergence.

Finding and disposition guidance

  • references-finding-taxonomy.md -- applies the four-disposition contract to references-audit findings; open when interpreting a scanner report.
  • coverage-gap.md -- explains what a clean audit does not check; open before treating COMPLIANT as coverage.
  • capability-boundaries.md -- states where md-domain stops and code review or future code audit starts; open for defect observations.

Placement and authoring patterns

  • cohesion-principles.md -- load graph and CRP, CCP, and ADP placement rules; open for where a fact should live.
  • authoring-patterns/content-authoring.md -- shapes facts as YAML header, markdown, or embedded YAML; open for how to encode content.
  • authoring-patterns/three-surfaces.md -- deeper treatment of the three surfaces and common authoring mistakes.
  • authoring-patterns/actions-pattern.md -- ordered action recipes with tool steps and capture; open when a workflow must be repeatable.
  • authoring-patterns/area-ownership.md -- identity, scope, sub-area registry, and routing; open when a document claims an area.
  • authoring-patterns/area-config.md -- six-field runtime contract for an area; open after ownership is expressed.
  • authoring-patterns/query-tool-pattern.md -- lookup facade with YAML output and did-you-mean; open for catalogs.

Standards and configuration

  • configuring-standards.md -- user guide to layering, rule ids, thresholds, and adapters; open to tune audits.
  • authoring-standards.md -- schema for additive standards files; open when adding a project standard.
  • standards/ -- five per-artifact standard docs; open for the criteria a lane applies.

Lane procedures

  • lanes/audit-lane.md -- one audit pipeline parameterized by artifact; open to run or debug an audit.
  • lanes/coverage-lane.md -- report-only analysis over a directory's direct code; open before generating coverage.
  • lanes/generation-lane.md -- consumes coverage to write documents; open when generation output is wrong.

Provenance records

  • provenance/ -- decision histories for cohesion, skill-authoring, and standards; open when a rule feels arbitrary.
