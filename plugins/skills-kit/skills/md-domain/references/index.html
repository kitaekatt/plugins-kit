Reference documentation for the md-domain skill: audit framework, per-artifact standards, lane procedures, authoring patterns, provenance records, and cross-cutting guidance on cohesion, capability boundaries, and standards configuration.

These are the on-demand reference docs for the md-domain skill, which authors and audits the project's markdown. The skill loads them by name from its dispatch table rather than all at once, so each doc is scoped to one reading task and the shared machinery is factored out into the docs every other doc defers to. The material splits along the skill's verbs and the questions that cut across them: the shared audit model, the per-verb procedures and their criteria, where a fact belongs and what md-domain leaves to other capabilities, how to tune the standards, and the patterns for shaping the documents it writes. A sibling page covers the skill-domain vocabulary the audit model draws on.

Where to start

Open plugins/skills-kit/skills/md-domain/references/audit-framework.md first: every audit lane defers to it for the shared vocabulary (subject, rule, finding, severity, disposition), which restores the model fastest. For where a fact should live instead of what an audit checks, open plugins/skills-kit/skills/md-domain/references/cohesion-principles.md.

The audit model

  • plugins/skills-kit/skills/md-domain/references/audit-framework.md - the canonical glossary: subject, rule, finding, severity, taxonomy, disposition; open it to learn the vocabulary every lane shares.
  • plugins/skills-kit/skills/md-domain/references/audit-framework.yaml - the machine registry: primitives, compositions, and the audit-kind table; scripts load it, and it is authoritative over the glossary on divergence.
  • plugins/skills-kit/skills/md-domain/references/references-finding-taxonomy.md - the A-K categories and per-rule disposition defaults; open it when fixing a references-audit report.

Lanes and their criteria

  • plugins/skills-kit/skills/md-domain/references/lanes/audit-lane.md - the one parameterized audit procedure; its dispatch table binds each lane to a criteria doc, a discover script, and a detect/remediate workflow.
  • plugins/skills-kit/skills/md-domain/references/lanes/coverage-lane.md - the analyze (coverage) procedure; reads a directory's own code to name the gaps its ambient orientation doc is missing.
  • A criteria doc per audited subject holds the table and taxonomy its lane applies, and the generation-lane procedure writes the ambient doc from the coverage it produces; the dispatch table names each.

Placement and boundaries

  • plugins/skills-kit/skills/md-domain/references/cohesion-principles.md - the shared spine for where a fact lives: the placement principles on the load graph; every lane defers to it on placement.
  • plugins/skills-kit/skills/md-domain/references/capability-boundaries.md - what md-domain does and leaves to code review and code audit (not yet built); the deferred-defects hand-off is specified here.
  • plugins/skills-kit/skills/md-domain/references/coverage-gap.md - what a clean audit does not tell you: the corpus-to-code relation no document rule checks, and the opt-in coverage design that would close it.

Tuning the standards
