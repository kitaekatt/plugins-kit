The skills-kit skills that audit and produce markdown, encode insights, teach the materialized-output pattern, and review sessions for documentation updates

Four skills live here, one per directory: one that audits, authors, generates, and analyzes project markdown, one that turns a session-discovered insight into a persistent record, one that teaches the pattern for materialized outputs, and one that reviews the finished session for documentation updates. Each skill keeps its load-bearing contract in a versioned YAML block, and the prose around it is orientation; the per-skill meta files beside it carry decision provenance instead of contract content. The markdown skill is the exception in scale: its reference docs, audit scripts, and workflow scripts each have their own page. The encoding and review skills stay thin because they defer the shared decisions -- where a fact lives, what shape it takes, what good looks like -- to that one skill.

Where to start

Start with md-domain/SKILL.md. Its dispatch table names every lane for the project's markdown, and the encoding and session-review skills both route their placement and standards questions to it.

Routes

  • Wrap up a session: update-documentation/SKILL.md audits the session and filters it into a severity-ranked recommendation table; a candidate that needs a durable home continues through knowledge-encoding/SKILL.md, and a new skill or a generated guidance file goes to the author and generate lanes in md-domain/SKILL.md.
  • Encode one insight: knowledge-encoding/SKILL.md states the insight in one sentence, runs the go / no-go test, and defers placement and shape to the markdown skill's references page; the record is written with its why and provenance, and a contract change triggers the merge-gate re-audit before the work is done.

Audit and production of project markdown

  • md-domain/SKILL.md -- the single front door: four verbs, audit, analyze, author, generate, routed by a dispatch table to per-artifact standards and lane procedures, with the invocation grammar and the scope-announcement rules. Open it when any markdown question starts.
  • md-domain/CLAUDE.md -- why this skill is one folded domain instead of routers and members: the fold decision, the required lane-record fields, and the contracts preserved verbatim through it. Open it when the skill's shape or its rules are about to change.

Encoding a discovered insight

  • knowledge-encoding/SKILL.md -- the eight-step procedure that turns one session insight into a persistent record, including the go / no-go test for whether to encode at all. Placement and content shape defer to the markdown skill's references.

The materialized-output pattern

  • materialized-output/SKILL.md -- the recognition model: when a deep scan or inference should emit a structured artifact with a refresh discipline instead of a printed answer, plus the practices and anti-patterns of insight engineering.
  • materialized-output/CLAUDE.md -- the per-skill meta: why the skill is typed a pattern skill, where its content was ported from, and the note about a future tool-skill sibling.

Reviewing a session for documentation updates

  • update-documentation/SKILL.md -- the end-of-session procedure: audit code changes, recovered errors, and inefficient operations; filter the candidates; classify each into exactly one target; present the severity-ranked table before editing.
