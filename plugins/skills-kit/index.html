The skills-kit plugin that authors and audits project markdown through a verb-by-artifact dispatch, carrying its four skills, fan-out lane workflows, and deprecation contract.

This is the skills-kit plugin: it audits and authors the markdown a project loads or ships - the guidance and skill files an agent reads at runtime, the project docs, and the links between them. It is organized around one front door that dispatches by verb and artifact: name an action (check, write, generate, analyze, render) and a target (a skill, a guidance file, a project doc, or the cross-references), and the door routes the pair to the one lane that handles it, so checking and writing read the same written-down standards from opposite directions. Three smaller skills sit beside the door for encoding a fresh insight, reviewing a finished session, and designing a tool that emits a durable artifact. The heavier machinery - the validator library, the discovery and audit scripts, the standards and lane reference docs, and the command dispatcher - each has its own page, linked above.

Where to start

Start with the front door, plugins/skills-kit/skills/md-domain/SKILL.md. Its dispatch table maps every verb-and-artifact pair to the lane and the standards doc that lane reads, so it tells you where a request lands before you open a single other file.

Routes

  • Audit a corpus of guidance files
    1. The dispatch row in plugins/skills-kit/skills/md-domain/SKILL.md names the lane, its procedure, and its standards doc.
    2. When a lane spans two or more files, plugins/skills-kit/skills/md-domain/workflow/claude-md-detect.js fans out one detect lane per file and classifies each finding, making no edits.
    3. After the decision gate, plugins/skills-kit/skills/md-domain/workflow/claude-md-remediate.js applies only the edits you accepted, in a separate pass.
  • Write a guidance file from code
    1. Analysis in plugins/skills-kit/skills/md-domain/workflow/coverage-detect.js reads one directory's own code and reports the facts its guidance file should carry - report-only, no edits.
    2. Then plugins/skills-kit/skills/md-domain/workflow/claude-md-generate.js writes the documents deepest first, composing each parent from its own code plus its children's finished files.
  • Read how the plugin ships
    1. plugins/skills-kit/.claude-plugin/plugin.json is the manifest: name, version, and the dependency on the bootstrap plugin.
    2. plugins/skills-kit/bootstrap.json sets the required bootstrap version, the shared libraries, and the pyyaml venv check.
    3. plugins/skills-kit/pyproject.toml declares the Python package, the Python floor, and its single dependency.

The dispatch and its shape

  • plugins/skills-kit/skills/md-domain/SKILL.md - the single front door; its dispatch table is the routing source, so open it to trace any verb-and-artifact pair to the lane that handles it.
  • plugins/skills-kit/skills/md-domain/CLAUDE.md - the shape decisions for that skill: why it is one skill, the required lane-record fields, and the decision provenance. Open it when editing the dispatch.

The three companion skills

  • plugins/skills-kit/skills/knowledge-encoding/SKILL.md - the procedure for turning a discovered insight into a durable record, deferring placement and shape to the placement and content-shape references. Open it after a session surfaced a finding worth keeping.
  • plugins/skills-kit/skills/update-documentation/SKILL.md - the end-of-session pass that filters session work into a short, approved set of doc updates. Open it before committing.
  • plugins/skills-kit/skills/materialized-output/SKILL.md - the pattern skill for designing a tool that emits a durable structured artifact instead of a one-shot print. Open it when a deep scan would otherwise be recomputed per query.
  • plugins/skills-kit/skills/materialized-output/CLAUDE.md - the type rationale and provenance for that skill: why it is a pattern-skill and where its content came from.

How the plugin ships

  • plugins/skills-kit/.claude-plugin/plugin.json - the plugin manifest: name, version, and the dependency on the bootstrap plugin. Open it to see what the plugin declares to the marketplace.
  • plugins/skills-kit/bootstrap.json - the provisioning: the required bootstrap version, the shared libraries, and the pyyaml venv check. Open it to see what must be installed.
  • plugins/skills-kit/pyproject.toml - the Python package definition: name, the Python floor, and its single dependency. Open it when the library packaging changes.

The deprecation contract

  • plugins/skills-kit/contract/public-surface.json - the deprecation ledger for the audit module's public names: what is deprecated, since which version, and what replaces it. Open it when changing the audit API.

The fan-out lanes

  • plugins/skills-kit/skills/md-domain/workflow - ten fan-out lane scripts: the per-artifact detect and remediate passes for the audit lanes, the report-only coverage detect, and the wave-ordered generate orchestrator. Each is dispatched by the front door when a lane spans more than one file.
