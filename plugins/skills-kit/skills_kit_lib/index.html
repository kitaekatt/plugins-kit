The skills-kit plugin library that validates, classifies, and audits skill documents against typed-unit schemas, with its shipped standards and lane-model configuration.

This is the Python library behind the skills-kit plugin. It validates, classifies, and audits skill and instruction documents, and it resolves the standards and lane-model configuration those audits run under. Everything hangs off one idea: a small rule-DSL schema engine and a registry of typed units, so a document's fenced YAML blocks are checked row by row instead of by prose guesswork. Skill-type roots are mutually exclusive (one per document); portable units coexist freely. Every verdict is a per-row pass, fail, judgment-required, or n-a, and the code reports a staged-but-unvalidated state rather than guessing when the YAML parser is absent.

Where to start

Open plugins/skills-kit/skills_kit_lib/__init__.py for the one-line map of every module and what it does; open plugins/skills-kit/skills_kit_lib/audit.py when you need the per-skill verdict path.

Routes

  • Audit one skill
    1. Run python -m skills_kit_lib.classify <document> to infer the type from the YAML root, or to score the body heuristically when no contract block is present.
    2. Run python -m skills_kit_lib.audit <document> to validate the document against that type's schema and print a per-row verdict.
  • Check the corpus
    1. Run python -m skills_kit_lib.checks, which first validates every registered schema's owner doc against its schema.
    2. It then resolves every domain and capability member ref against the union of on-disk skill names, so a renamed or moved member fails the run instead of dangling.
  • Stamp the type tag
    1. Run python -m skills_kit_lib.tag <document> <type> to write the advisory skill-type frontmatter.
    2. It is idempotent and refuses to overwrite an existing value without --force; use --check to preview the change without writing.

The schema engine

  • plugins/skills-kit/skills_kit_lib/schema_engine.py - the rule-DSL walker that turns a parsed payload plus a schema dict into per-path pass or fail; the module docstring is the source for the rule vocabulary.
  • plugins/skills-kit/skills_kit_lib/schema_registry.py - the registry of typed-unit roots, split into skill-type (mutually exclusive), portable (coexist), and claude_md, plus the mixed-type detector; open it to see what a block's root resolves to.
  • plugins/skills-kit/skills_kit_lib/rule_fragments.py - shared rule fragments (keywords, scope, fact item, anti-pattern, technique step) the schema modules compose instead of restating.

Reading documents

  • plugins/skills-kit/skills_kit_lib/document_walker.py - fenced-YAML-block extraction and the one canonical fence regex; open it when a block is present but not parsed.
  • plugins/skills-kit/skills_kit_lib/markdown_heuristics.py - the structural-shape detectors and the one frontmatter parser; it scores a body against each skill type for the legacy fallback.
  • plugins/skills-kit/skills_kit_lib/corpus.py - skill-document discovery across the user, project, and plugin tiers; the one source for what skills exist and how to read each.
  • plugins/skills-kit/skills_kit_lib/dirwalk.py - the shared depth-limited directory walk the discover scripts use; it prunes noise and hidden directories down to the one hidden dir the audits need.
  • plugins/skills-kit/skills_kit_lib/instruction_files.py - resolves which agent instruction file a directory reads and whether one is shadowed; open it before adding a new instruction-file convention.

Per-skill CLIs

  • plugins/skills-kit/skills_kit_lib/audit.py - the per-skill audit; runs the deterministic contract checks and prints a per-row verdict (pass, fail, judgment-required, or n-a). The main entry point for checking one skill.
  • plugins/skills-kit/skills_kit_lib/classify.py - infers a skill's type from its YAML contract root, or scores the body heuristically when no contract block is present.
  • plugins/skills-kit/skills_kit_lib/tag.py - writes the advisory skill-type frontmatter; idempotent, and it refuses to overwrite an existing value without --force.

Configuration

  • plugins/skills-kit/skills_kit_lib/standards_resolve.py - resolves the layered standards configuration across the shipped, user, and project layers (later-wins) and fails loudly on a malformed layer or an un-tunable id.
  • plugins/skills-kit/skills_kit_lib/lane_models.py - resolves the lane-model slot, the model and effort each md-domain lane family runs under, across the same layers with the shipped file as layer 0.
  • plugins/skills-kit/skills_kit_lib/rule_catalog.py - the source for every rule id and its bucket, group, and description; the resolver reads it to reject architectural ids, and the docs render from it.
  • plugins/skills-kit/skills_kit_lib/material.py - the one binding skills-kit keeps to the skill-material module of the bootstrap library, plus the material command; open it to read the absent, too-old, and no-pyyaml states.

Unit contracts

The registered typed-unit contracts live in one package - plugins/skills-kit/skills_kit_lib/schemas/skill_types.py for a skill type's contract, plugins/skills-kit/skills_kit_lib/schemas/portable.py for the portable units (references, facts, area_config, sub_areas, actions, asset_dependencies), plugins/skills-kit/skills_kit_lib/schemas/claude_md.py for the claude_md document contract, and plugins/skills-kit/skills_kit_lib/schemas/standards.py for the standards_set unit; importing the package registers them all, so a submodule import sees the populated registry.

The shipped defaults

The criterion sets every audit reads first, plus the lane defaults - plugins/skills-kit/skills_kit_lib/defaults/standards/SKILL-standards.md (frontmatter, size, and record floors), plugins/skills-kit/skills_kit_lib/defaults/standards/SKILL-legacy-standards.md (the legacy per-type heuristics), plugins/skills-kit/skills_kit_lib/defaults/standards/CLAUDE-md-standards.md (instruction-file size and record floors); the fenced standards_set block in each is the source for a criterion's id, statement, severity, and threshold. plugins/skills-kit/skills_kit_lib/defaults/lane_models.yaml carries the shipped model and effort per lane family before user and project layers override.

Corpus checks

plugins/skills-kit/skills_kit_lib/checks.py - the corpus-level checks that run over the whole registry and file system: they validate every owner doc and resolve every domain and capability member ref; run them to catch drift and dangling members.
