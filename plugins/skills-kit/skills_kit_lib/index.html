skills_kit_lib validates skill and document YAML contracts and provides audit, classification, tagging, SKILL.md discovery, and standards-resolution tools for skills-kit.

This is the plugin-level Python library behind the skills-kit audits. It turns the fenced YAML blocks inside a skill document into typed units, validates each unit against a small Python-dict rule grammar, and scores the narrative body for documents that have not adopted a contract yet. Per-skill commands work on one file at a time; corpus checks work on the registry plus the filesystem and catch drift between a schema and the prose spec that names it. Schemas are Python literals that self-register at import, which is why the import order inside the package is load-bearing.

Where to start

Open __init__.py first: its docstring is the package map, and its single import shows that schemas must register before anything reads the registry. When a verdict needs explaining, open audit.py: its docstring names the three runtime states (validated, staged without a parser, legacy fallback) that decide which rows you will see.

Routes

  • Type a skill: classify.py proposes a type from the YAML root or, when no contract block exists, from scored content shape; tag.py writes the advisory frontmatter value it found; audit.py re-checks the contract row by row. Each runs as a python -m module command, and the docstrings carry the exact form.
  • Corpus drift sweep: after a reorg that moves or renames skills, run the checks command from checks.py; it validates every schema's owner doc and resolves every domain and capability member reference, and a failure names the doc or ref that broke.
  • Add a typed unit: write the schema in schemas/portable.py (or schemas/skill_types.py), register it at module load, and add the module to schemas/__init__.py so package import populates the registry before the walker reads it.
  • Tune the audit: a new rule row in audit.py must also get its id in rule_catalog.py; standards_resolve.py then decides whether user config may switch it off, and only the optional bucket may be tuned.

The commands

  • audit.py -- per-skill contract checks; open it when a pass, fail, judgment-required, or n/a row needs explaining, and mind the three runtime states, which change which rows run when no YAML parser is installed.
  • classify.py -- infers a skill's type from its YAML root, or from scored content shape when no contract block exists.
  • tag.py -- writes or replaces the skill-type frontmatter value; idempotent, and it refuses a different existing value without the force flag.
  • checks.py -- the corpus-level checks: owner-doc validation and member-reference resolution. The owner docs it opens live in the plugin's skills tree, not here, so a failure can name a doc outside this package.

The rule engine

  • schema_engine.py -- walks a parsed YAML payload against a schema dict and emits per-path failures; its module docstring is the reference for the whole rule grammar.
  • schema_registry.py -- the registry of typed-unit roots; skill-type roots are mutually exclusive within one document, portable roots coexist freely.
  • rule_fragments.py -- the shared rule fragments (keywords, scope, fact item, anti-patterns, technique steps) that schemas reuse instead of restating.

The schemas

  • schemas/skill_types.py -- one schema per canonical skill type, seven roots, each with forbidden keys that flag mixed-type drift.
  • schemas/portable.py -- the six portable units (references, facts, area_config, sub_areas, asset_dependencies, actions) that nest inside a skill-type unit or stand alone.
  • schemas/claude_md.py -- the document-type schema for the persistent insights file (insights, conventions, glossary); the non-empty floor is a document-level check, not a key here.
  • schemas/standards.py -- the standards_set unit behind the configurable-standards files; registered as portable so it never trips mixed-type drift.
  • schemas/__init__.py -- the import trigger: importing the package registers all four schema modules, so the registry is set before the first consumer reads it.

Reading a document

  • document_walker.py -- extracts fenced YAML blocks and recognized typed units; it separates the no-block, broken-block, and no-parser states so a parse error never masquerades as a missing contract.
  • markdown_heuristics.py -- the stdlib-only structural detectors and the one frontmatter parser in the plugin; the scoring behind classify's fallback path.
  • corpus.py -- discovers skills across the user, project, and installed-plugin tiers; the parse entry point the corpus checks reuse.
  • dirwalk.py -- the shared depth-limited directory walk behind the audit discovery scripts; one walk implementation, one skip list.

Tuning the audit

  • rule_catalog.py -- the single catalog of every audit rule id with its bucket, group, and user-facing description; it must stay in sync with the rule assignments the audit rows emit.
  • standards_resolve.py -- resolves the layered user and project config into disabled optional rules, threshold overrides, and standards files; it raises loudly on anything un-tunable instead of degrading silently.

Provenance

  • CLAUDE.md -- the per-directory insight log: corrections with origins, design choices, and audit lessons. Open it to trace why a rule behaves the way it does.
