The OpenAI-compatible front door that routes chat requests to configured transport deployments.

This module is a single, self-contained front door: it accepts OpenAI-compatible chat-completion requests and forwards each one to a transport deployment from the endpoint registry. All of the routing logic lives in one server module; the two files beside it are thin wrappers that keep the package importable without the web stack and give the server a module entry point. The idea that makes the layout make sense is lazy web dependencies: FastAPI, uvicorn, and httpx load only when the app is actually built or run, so importing the kit never pulls the front door into the import path. Requests are grouped by model name, and within a group the door walks the deployments in tier order, holding each one to its parallel cap and spilling to the next tier before it gives up.

Where to start

Open plugins/llm-scripting-kit/lib/llm_scripting_kit/frontdoor/server.py first: the app factory, deployment selection, request rewriting, and every HTTP route are all in that one file. The other two files are one-liners you reach for only when wiring the server into a process.

Routes

  • Boot the server
    1. plugins/llm-scripting-kit/lib/llm_scripting_kit/frontdoor/__main__.py: the module entry point
    2. main(): the CLI that starts the server
    3. create_app(registry)
  • Trace one completion
    1. POSTv1 chat-completions: the single inbound route
    2. choose(): picks a deployment in the group, honoring its parallel cap
    3. _normalize_body(): rewrites the model and relocates reasoning effort
    4. call_upstream(): posts to the deployment's chat completions endpoint
  • Resolve a credential
    1. _deployment_key(): resolved once per deployment
    2. env var, then
    3. get_api_key(): the plugin's layered lookup

Request routing and forwarding

  • plugins/llm-scripting-kit/lib/llm_scripting_kit/frontdoor/server.py. The complete front door: loads the registry, groups and ranks the transport deployments, rewrites each request's model and reasoning effort, calls the upstream deployment with per-deployment auth, and serves the chat-completions, models, health, and who routes plus the JSONL access log.

Entry points

  • plugins/llm-scripting-kit/lib/llm_scripting_kit/frontdoor/__init__.py. Re-exports create_app and main; keeps FastAPI, uvicorn, and httpx out of the import path so loading the kit never requires the web stack.
  • plugins/llm-scripting-kit/lib/llm_scripting_kit/frontdoor/__main__.py. The python -m entry point; runs main() and exits with its return code.
  • llm_scripting_kit The llm-scripting-kit package that resolves credentials, endpoints, models, reachability, quota pacing, and completion backends for configured model calls.
  • README.md The human-facing overview of the llm-scripting-kit plugin.
  • model_endpoints.py The endpoint-registry module the front door reads for deployment groups, order, and parallel caps.
