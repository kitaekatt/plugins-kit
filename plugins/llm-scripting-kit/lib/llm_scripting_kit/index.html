The llm-scripting-kit library that configures, verifies, and dispatches LLM model calls across OpenAI-compatible servers and CLI harnesses, with layered credential resolution, reachability checks, and subscription quota pacing.

This is the shared LLM access layer for the plugins. It turns a named model into a concrete endpoint and a credential, checks that the endpoint is usable right now, and runs the call over whatever transport a machine can reach -- an OpenAI-compatible HTTP server or one of three local CLI harnesses. Configuration is layered, from a shipped baseline up through fleet-wide, machine-local, and per-project files, so a machine-specific choice beats the fleet default. The import boundary is stdlib-only: the openai SDK, psutil, and the shared bootstrap library load lazily, so a consumer that only needs a raw key or a reachability check pays nothing for the transports.

Where to start

Open plugins/llm-scripting-kit/lib/llm_scripting_kit/__init__.py first: its re-exports are the whole public surface, and the module docstring names the four transports and the config layering together. To read the command surface instead of the import surface, start with plugins/llm-scripting-kit/lib/llm_scripting_kit/cli.py.

Configuration and model registry

  • plugins/llm-scripting-kit/lib/llm_scripting_kit/__init__.py -- the package's re-export map; its docstring names the four transports and the config layering in one place.
  • plugins/llm-scripting-kit/lib/llm_scripting_kit/models.py -- layered config resolved to the effective model and endpoint map; resolve_model and resolve_endpoint.
  • plugins/llm-scripting-kit/lib/llm_scripting_kit/model_endpoints.py -- reads the user-owned model-endpoints registry; the entry schema and per-entry effort-style resolution.
  • plugins/llm-scripting-kit/lib/llm_scripting_kit/constants.py -- the shipped default endpoint values and the canonical key and config file paths.
  • plugins/llm-scripting-kit/lib/llm_scripting_kit/default_config.yaml -- the shipped baseline config, the lowest layer; a test keeps it in sync with the model map.

Credentials and the client

  • plugins/llm-scripting-kit/lib/llm_scripting_kit/api_key.py -- resolves an endpoint's key through env, project, user, then key_file; records the source and flags the superseded project path.
  • plugins/llm-scripting-kit/lib/llm_scripting_kit/client.py -- make_openai_client, a lazily-imported openai SDK client pointed at the resolved endpoint.
  • plugins/llm-scripting-kit/lib/llm_scripting_kit/env_file.py -- the minimal KEY=VALUE reader and writer the credential layers build on.

Dispatch: the completion seam

  • plugins/llm-scripting-kit/lib/llm_scripting_kit/declaration.py -- describe and run, the one API over a model declaration; pace ordering and the floor diagnostic.
  • plugins/llm-scripting-kit/lib/llm_scripting_kit/completion/factory.py -- create_backend, where a named transport becomes a runnable backend.
  • plugins/llm-scripting-kit/lib/llm_scripting_kit/completion/backends.py -- the four transports: the OpenRouter HTTP endpoint and the claude, codex, and opencode CLIs.
  • plugins/llm-scripting-kit/lib/llm_scripting_kit/completion/types.py -- BackendOptions, LLMResponse, and the seam's error vocabulary.
  • The remaining seam modules -- capability tables, the output contract, halt and result handling, and the per-harness runners -- support the four backends.

Verification and health

  • plugins/llm-scripting-kit/lib/llm_scripting_kit/reachability.py -- liveness checks (a GET of a transport's models endpoint, a harness's version probe); three verdicts, never a bare boolean.
  • plugins/llm-scripting-kit/lib/llm_scripting_kit/account.py -- OpenRouter auth/key validation and the models endpoint probes.

Quota pacing and seats

  • plugins/llm-scripting-kit/lib/llm_scripting_kit/usage_budget.py -- conserve_usage quota pacing and the session-pinned verdict that gates selection.
  • plugins/llm-scripting-kit/lib/llm_scripting_kit/seats.py -- frontier seat discovery: which harness seats are up and beside a given model.

Harness, effort, and the local swapper

  • plugins/llm-scripting-kit/lib/llm_scripting_kit/harness_adapters.py -- argv builders for the codex and opencode harness dispatches.
  • plugins/llm-scripting-kit/lib/llm_scripting_kit/effort.py -- the reasoning-effort wire vocabulary shared by the front door and the direct seam.
  • plugins/llm-scripting-kit/lib/llm_scripting_kit/swapper.py -- the local model-swapper client and lifecycle: launch guard, terminate, strays, and acceptance fixtures.

The front door

  • plugins/llm-scripting-kit/lib/llm_scripting_kit/frontdoor/server.py -- the OpenAI-compatible fill-first front door HTTP server and its acceptance checks.

The CLI

  • plugins/llm-scripting-kit/lib/llm_scripting_kit/cli.py -- the public subcommands: status, set-key, probe, usage, describe, seats, complete, swapper, frontdoor.
  • plugins/llm-scripting-kit/lib/llm_scripting_kit/request_protocol.py -- the versioned complete --request-file request half of the protocol.
  • plugins/llm-scripting-kit/lib/llm_scripting_kit/review_lane.py -- dispatch one code-review lane against a configured endpoint.
