The llm-scripting-kit plugin distribution that provides the installed CLI, local Qwen server scripts, credential setup, and completion-seam reference

This directory is the llm-scripting-kit plugin distribution: the installed command, the local Qwen server tooling, the session-start credential pass, and the reference the fleet reads for how a completion call is made. It is deliberately thin. The verbs, the endpoint registry, and the completion backends are implemented in the Python package one level down, and that package carries its own page. What stays here is the shell surface around that package -- the shims on PATH, the measured server profiles, the bootstrap pass -- plus the documentation. Hold the split: a change to a verb belongs below this directory; a change to a shim, a server profile, or the docs belongs here.

Where to start

Start with README.md, the human-facing reference: every CLI verb with an example, the exit-code table, and how the configured, reachable, and quota axes differ.

Routes

  • The installed command: bin/llm-scripting-kit and its Windows twin pick a Python interpreter and exec scripts/llm_scripting_kit_cli.py, which puts the bundled library on the path and hands off to the verbs implemented in the Python package, covered by its own page.
  • Launch a Qwen profile: bin/qwen36-server, bin/qwen38-server, and bin/qwen38l-server each exec scripts/model-server.sh with their profile, which assembles the measured NInfer or llama.cpp command line.
  • Swap the resident server: bin/qwen-switch runs scripts/qwen-switch.sh, which stops the identified listener on the profile port and relaunches scripts/model-server.sh detached.
  • Session-start credential pass: bootstrap.json points the bootstrap engine at custom_bootstrap.py, which migrates the renamed data dir, resolves the key, and defers or validates it.

The installed command

  • bin/llm-scripting-kit -- the Unix shim: picks the plugin venv Python, then the standalone Python, then PATH, and execs the launcher. Open it when the command starts under the wrong interpreter.
  • bin/llm-scripting-kit.cmd -- the Windows twin of the same shim, with the same interpreter ladder and the same guard against a Store stub.
  • scripts/llm_scripting_kit_cli.py -- the interpreter-agnostic launcher the shims exec; it adds the bundled library to the path and delegates to the package CLI, which owns every subcommand.

Local Qwen servers

  • scripts/model-server.sh -- the canonical launcher for the three measured profiles: qwen36 and qwen38 through NInfer, qwen38l through llama.cpp. All bind localhost and port 8080 by default, so only one profile serves at a time.
  • scripts/qwen-switch.sh -- replaces the resident server: stops the identified listener, starts the launcher detached, and waits for the profile's exact model id.
  • bin/qwen36-server, bin/qwen38-server, bin/qwen38l-server -- one-line shims, one per profile, that exec scripts/model-server.sh with the matching profile; the trailing l in the name marks the llama.cpp path.
  • bin/qwen-switch -- the PATH shim for scripts/qwen-switch.sh, so the short name works from any working directory.

Credential setup

  • bootstrap.json -- declares the venv extras, the shared-library link into the package, and the session-start script the bootstrap engine runs.
  • custom_bootstrap.py -- the session-start pass itself: migrates the pre-rename data dir, resolves the key through env, project, and user layers, and either defers a missing key or validates it against a seven-day hash cache.
  • skills/openrouter-account/SKILL.md -- the skill for the key's day-to-day: preflight it at the point of need, set or rotate it, and split HTTP 401 (rotate the key) from 402 (top up the account).

Documentation and contracts

  • README.md -- the human-facing reference: every CLI verb with an example, the exit-code table, and the configured, reachable, and quota axes side by side.
  • CLAUDE.md -- the agent-facing companion: what this layer owns, the reachability and pacing invariants, and the per-transport rules. Open it when reviewing or changing behavior the human-facing reference only sketches.
  • references/completion-seam-contract.md -- the per-call contract of the completion seam: what each adapter advertises before a call and what the response reports after. Read it before changing an adapter, a capability record, or the complete verb.

Packaging

  • pyproject.toml -- package metadata and the CLI entry point; the sdk and frontdoor extras pull in the OpenAI SDK and the frontdoor stack.
  • .claude-plugin/plugin.json -- the plugin manifest: name, version, keywords, and the bootstrap dependency.
  • scripts/frontdoor.sh -- runs the package frontdoor module under the plugin venv Python; print-command shows the command without running it.
