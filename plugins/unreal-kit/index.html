Unreal Engine automation plugin for Claude: plugin manifest, bootstrap provisioning, defaults, hooks, and host-side Unreal scripts.

This is the unreal-kit Claude Code plugin: the layer that lets Claude run Python inside Unreal Engine whether the Editor is open or closed. Beyond its manifest, its work splits into three jobs — provisioning (turning the API on and resolving the project and engine), a small terminal surface for driving the Editor and searching the API, and session hooks that guard MCP calls and route console commands. The Python support modules and the agent skills live in sibling directories with their own pages. Provisioning is the connective tissue: the fast UDP path and the slower headless fallback both depend on the settings and venv it writes, so its logic is the thing to understand first.

Where to start

Start with README.md, which separates what the plugin ships from what it drives externally and lists the prerequisites behind every other file here. It is the fastest way back to context.

Routes

  • Bring up the live Editor for MCP authoring: scripts/ue_env_cli.py status → scripts/ue_env_cli.py launch-editor --wait-for-mcp
  • Search the Unreal API and recover a missing stub: scripts/search_unreal_stub.py <pattern> → scripts/refresh_unreal_stub.py --project-root .
  • Guard an MCP save against a stale editor build: hooks/pretooluse/check-editor-build-fresh.sh → hooks/pretooluse/detect-editor-stale.py

Overview and manifest

  • README.md — the human-facing overview: what the plugin ships versus what it drives externally, plus install and prerequisites. Open it before anything else.
  • .claude-plugin/plugin.json — the manifest Claude installs from: name, version, description, author, keywords, and the bootstrap dependency. Open it to change the plugin's public identity.

Provisioning and setup

  • bootstrap.json — the provisioning contract: required bootstrap version, the venv imports, the per-project and plugin config fields, the UserEngine.ini flags, the unreal-pip pin, and the stub download. Open it to change what setup does.
  • custom_bootstrap.py — the provisioning entry points the bootstrap engine calls: autodetect() finds the project and engine, and bootstrap() checks the enriched stub and defers the optional P4 provider.
  • defaults/config.yaml — the seed config with empty engine_dir and uproject that provisioning fills in per project.
  • pyproject.toml — the host-side Python spec: upyrc, pyyaml, websocket-client, and the 3.12 (not 3.14) interpreter range. Open it when a dependency or version bound looks wrong.

Host-side Unreal scripts

  • scripts/ue_env_cli.py — drives the Editor host: status reports running processes and MCP readiness; launch-editor spawns the Editor and can wait for the MCP bridge.
  • scripts/search_unreal_stub.py — searches the best available Unreal API stub (enriched first, then stock) and prints how to recover when neither exists.
  • scripts/refresh_unreal_stub.py — copies the project's compiled enriched stub into the durable plugin-data location. Open it after a full compile when API search comes up empty.

Session hooks

  • hooks/hooks.json — the hook registrations: a UserPromptSubmit command and a PreToolUse command matched to the mcp__unreal-engine__ tools.
  • hooks/userpromptsubmit/ue-console-cmd.sh — the ">" console-command hook: routes a ">"-prefixed prompt to the Editor via MCP and self-disables when the server is not configured.
  • hooks/pretooluse/check-editor-build-fresh.sh — the foreground PreToolUse check that blocks a save tool call when the editor build is stale, then launches the detached detector.
  • hooks/pretooluse/detect-editor-stale.py — the detached detector that compares the editor DLL against Build.version to set or clear the stale marker.
