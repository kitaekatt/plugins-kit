• unreal-kit Unreal Engine automation plugin for Claude: plugin manifest, bootstrap provisioning, defaults, hooks, and host-side Unreal scripts.

Python support modules for the unreal-kit plugin: dependency bootstrap, bootstrap-presence guard, Windows PATH repair, Unreal project discovery, editor launch and MCP readiness, configuration, stub refresh, and the Unreal MCP Automation Bridge client.

This is the Python support code behind the unreal-kit plugin's automated sessions. It follows the lifecycle of a session: get the right interpreter and packages, locate the project and engine, launch the editor, and drive it through the automation bridge. Two modules are canonical sources that other plugins copy in, and the set is written stdlib-first so a script can still run when the provisioning tooling is not importable. Most of it runs on the host around the editor, with a small part inside Unreal that installs the Python packages a script needs. What ties the shape together is that nearly every entry point is a guard-then-act function you call first, so failures surface as an actionable message rather than a crash.

Where to start

Open ue_env.py first when you need to drive the editor: its docstring walks scan, launch, and readiness, and shows where the MCP client plugs in. Open bootstrap_guard.py instead when a "not provisioned" error is what you are chasing; it is the canonical source for that guard.

Routes

  • Bring the editor up and drive it: ue_env.py -> ue_mcp_client/client.py. Launch a detached editor, then poll the bridge until the client handshake is ready.
  • Put a host script in the right interpreter: bootstrap_guard.py. Re-exec under the provisioned venv before the guarded import, and surface the absence message when provisioning never ran.
  • Install a missing UE-side package: bootstrap.py -> requirements.yaml. Read the package list and pass the missing entries to the in-editor installer.

Dependencies and the right interpreter

  • requirements.yaml -- the package list the UE-side installer works from; open it to add or drop a dependency.
  • bootstrap.py -- the UE-side dependency installer; call ensure_dependencies() at the top of a script that needs external packages, and open it when an import fails inside the editor.
  • bootstrap_guard.py -- the host-side presence guard: re-exec a script under the plugin venv and fail with an actionable message when provisioning never ran; the canonical copy other plugins vendor.
  • path_repair.py -- Windows PATH repair for subprocess reliability; open it when a tool is installed but a subprocess reports it missing.

Finding the project and the engine

  • ue_discovery.py -- find .uproject files and the Engine directory; open it when the runner cannot locate the project or the engine.
  • ue_identity.py -- confirm a responding editor belongs to the workspace you expect; open it when several editors run and the wrong one answers.
  • ue_ini.py -- read and write UE .ini settings without disturbing unrelated sections; open it when setup needs to flip a config flag.

Launching and driving the editor

  • ue_env.py -- host scaffolding: enumerate running editors, launch a detached one, and poll the bridge until it is ready; the hub for driving the editor from the host.
  • ue_mcp_client/__init__.py -- the package entry that re-exports the client and its error types; start here when importing the client.
  • ue_mcp_client/client.py -- the WebSocket client for the automation bridge: handshake, correlated request/response, and the named errors; open it when a request times out or the handshake fails.

Configuration and the API stub

  • ue_runner_config.py -- layered configuration (shipped, skill, user, project) and durable project-config writing; open it when a path or remote-execution setting resolves wrong.
  • unreal_stub.py -- resolve the API stub paths and explicitly refresh the durable stub; open it when completion is stale or a read-only stub blocks an update.
