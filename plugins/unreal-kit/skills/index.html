Unreal Engine automation skills for Claude agents, providing domain routing, shared runtime orientation, and live-Editor MCP server tooling.

This is the skills layer of the unreal-kit plugin: where a Claude agent looks when asked to do something with Unreal Engine. A domain skill on top routes natural-language intent to one of three member skills and states whether the task runs host-side or needs a live Editor. The members split by execution channel -- Python data access, ObjectRedirector cleanup, and live-Editor control through the MCP server -- and share one provisioned runtime underneath. Only the live-Editor MCP skill keeps its full material here; the other two members are documented on their own pages. The channel each task needs, not a single monolithic skill, is what this directory is organized around.

Live-Editor control has a hard precondition: the Editor must be open with the automation bridge plugin active, or MCP calls fail. When that is not true, the host-side Python path is the one that works, with the Editor open or closed.

Where to start

Open unreal-domain/SKILL.md first. Its routing table maps what you want to do to a member skill and states the Editor state that member needs, so it settles the only choice you must make before opening anything else.

Routes

  • Pick a member and its channel: unreal-domain/SKILL.md -> unreal-domain/references/shared-runtime.md
  • Find the tool domain for a task: ue-mcp-server/SKILL.md -> ue-mcp-server/references/tool-catalog.md
  • Run a multi-step authoring recipe: ue-mcp-server/SKILL.md -> ue-mcp-server/references/workflows.md

Routing and shared runtime

  • unreal-domain/SKILL.md -- the domain skill. Its routing table maps intent to a member and the Editor state that member needs, and its capability YAML carries the domain contract and guardrails. Open it to pick a member.
  • unreal-domain/references/shared-runtime.md -- the runtime under all three members: the provisioned venv, project and engine discovery, and the two execution channels with the member each one serves. Open it when you need to know where host-side Python runs or why a channel needs a live Editor.

Live-Editor MCP tooling

  • ue-mcp-server/SKILL.md -- the live-Editor skill. Its capability YAML lists one record per MCP tool domain -- keywords, action, reference section, and domain gotchas -- and the markdown after it carries orientation and usage patterns. Open it to find the domain for your task.
  • ue-mcp-server/references/tool-catalog.md -- concise per-domain action summaries; the connected server's schema and source remain the authority. Open it to check what a domain advertises before you call it.
  • ue-mcp-server/references/workflows.md -- multi-step recipes (Blueprint from scratch, level shell, material setup, PIE drive), each with ordered tool calls and the post-conditions to verify. Open it when a task spans more than one domain.
