Unreal ObjectRedirector cleanup workflow for Perforce projects with P4-safe fix-up and orphan modes and supporting helper libraries

This skill replaces Unreal's Fix Up Redirectors in Folder command for Perforce-backed projects: it classifies every ObjectRedirector by P4 safety, re-saves the referencers of the safe ones in a fresh changelist, deletes the orphaned ones, and names who to ping for the rest. The top-level file is the workflow itself: when to run it, which of the two modes to pick, and why a purge is staged as a small sampled slice before the full pass. The library modules underneath are the pieces that make a run P4-safe: one wraps the p4 client with timeout budgets, one scans project source for content paths that resolve to real assets, one fixes the on-disk shapes the phases pass to each other, and one converts package names to file paths from inside the editor. The phase runners that perform discovery, classification, filtering, and the apply phase live in their own directory with its own page.

Where to start

Open SKILL.md first: it defines the two invocation modes, the six-phase pipeline, and which helper module each phase calls. If you are debugging a specific failure instead, go straight to the module listed under the phase that failed.

Routes

  • Routine orphan purge: run the skill with the orphaned_safe mode keyword, optionally scoped to a content path; it classifies, applies the code-reference filter, and runs a delete-only pass over the filtered orphaned set.
  • Full fix-up after a rename or move pass: a scoped full run, then a directory-sampled test slice, then soak (playtest, tests, visual diff), then the full purge of the original safe set once the slice is clean.

A clean scan is a hint that a fix is safe, not proof: the reference scan catches the channels that have been observed and encoded, and quietly misses the rest. The pipeline therefore never full-purges cold; it commits one redirector per directory first, so a missed reference channel costs one small revert instead of a thousands-of-files rollback.

Workflow definition

  • SKILL.md — the skill contract: invocation modes, the six-phase pipeline, the directory-sample-then-soak-then-purge strategy, and the P4 and commandlet timeout budgets for unattended runs. Open it to plan a run or to change which phases execute.

P4 plumbing

  • lib/p4cli.py — host-side p4 client wrapper: separate timeout budgets for query and mutation verbs, parsing of opened and where output, and batched edit, delete, and reopen into a pending changelist. Open it when a P4 call times out, a file lands in the wrong changelist, or a where mapping looks ambiguous.

Reference detection

  • lib/code_refs.py — scans project source for content-path strings that resolve to real assets on disk, and caches the result with full provenance so later runs can reuse it. Open it when the scan misses a reference channel or the cache floods with false positives.

Phase data contract

  • lib/redirector_record.py — the on-disk shapes for the discovery YAML, the safe-set JSON, the reports, and the apply manifest, kept in one place so the phases stay aligned. Open it before changing any phase's input or output.

Editor-side path conversion

  • lib/package_paths.py — builds the mount map and converts package names to on-disk file paths; imports the unreal module, so it only runs inside the editor. Open it when a phase's path conversion disagrees with what is on disk.
