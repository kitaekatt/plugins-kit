Unreal Engine Python API skill and host-side runner, launcher, and configuration for script execution.

This is the Unreal Engine Python API skill: a plugin capability that lets an agent read, write, and extract Editor data through Python scripts that work with the Editor open or with it closed. The directory splits into a contract and a machine. The contract states scope, the two capabilities, and the binding gotchas; the machine finds a Python interpreter, chooses how to deliver the script, and brings results back. Two delivery paths matter everywhere downstream: a fast dispatch over UDP multicast to a running Editor, and a slow headless commandlet when no Editor is up, with results arriving as YAML files in the project rather than terminal output. The plugin is engine-generic by license, so project-specific paths and asset names are banned from these files.

Where to start

Open SKILL.md first: the fenced YAML block is the load-bearing contract, and the prose and code recipes after it are what you copy into a new script. When the run itself rather than the script is the question, use the host-side execution group below.

Routes

  • Author a script: take the template and the gotchas from SKILL.md, keep the bootstrap prelude intact, then hand the file to the runner.
  • Launch on Windows: scripts/ue-runner.cmd picks an interpreter, hands off to scripts/ue_runner.py, which re-execs under the plugin venv and dispatches to the matching Editor or falls back to the headless commandlet.
  • Get results back: the script writes YAML into the project output directory; the runner diffs a pre-dispatch snapshot against the directory after the run and copies the new file when --copy-output is given.
  • Find which setting won: CLI flags, then project-side config, then global config, then ue_runner_config.yaml, then hardcoded defaults, in the order the config file's header documents.

The skill contract

  • SKILL.md -- the skill definition. Its YAML block states the scope, the run-script and stub-search capabilities, the capability-level gotchas, and the index of the deeper docs; the sections after it carry the vocabulary, the essential-classes table, and the copy-ready script recipes. Open it when authoring a script or checking whether a UE Python oddity is a known gotcha.

The reference docs that the YAML indexes do not live in this directory; they are on the reference-docs page.

Host-side execution

  • scripts/ue_runner.py -- the runner itself. It re-execs under the bootstrap-provisioned plugin venv, resolves which project to target, sends the script to the running Editor whose project root matches, and falls back to a headless commandlet when no Editor answers. Open it when mode selection, the fallback, or output detection behaves unexpectedly.
  • scripts/ue-runner.cmd -- the Windows launcher. It picks a deterministic interpreter in order (standalone install, validated fallback, plugin venv) and hands off to the runner, exiting with code 3 and a bootstrap hint when none is found. Open it when a Windows invocation dies before Python starts.

Runner configuration

  • ue_runner_config.yaml -- global defaults: the multicast group and port for remote dispatch, plus the documented precedence chain from CLI flags down to hardcoded defaults. Open it when a remote endpoint changes or a setting does not seem to apply.
