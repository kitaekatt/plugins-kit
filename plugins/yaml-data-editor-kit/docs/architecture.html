yaml-data-editor-kit

Architecture and current implementation status for version 0.7.1. Sources: the plugin charter, dialect specification, binding note, and current Python package.

The idea

Make the data model explicit. A consuming project writes a profile in this plugin's YAML dialect. The profile declares types, shapes, meaning, presentation, and storage. The plugin loads that profile and validates a corpus without importing or hardcoding the consuming project's vocabulary.

A comment is a singular unit of intent attached to an anchor: the address of a document, record, or field in the loaded corpus. The anchor supplies context. Its guard records the exact anchored slice, so a later check can distinguish unchanged data from a moved or unresolvable address.

  • Profile, then corpus. Declarations describe data; they do not become project code.
  • Meaning has a home. Units, sentinels, provenance, and derived fields are declared.
  • Addresses are data. Selectors normalize to stable spelling and concrete points.
  • Guards are local. Hash the resolved slice under a comment, not the whole corpus.
  • Files are the seam. The charter keeps editor and dispatcher independent.

The shape: one plugin, four packages, one seam

This is a library, not a standalone tool. schema/ and comments/ contain current implementation. dispatch/ and editor/ are placeholders only. The charter defines a file seam between the future node-side editor and Python-side dispatcher: no shared process, RPC, or in-memory handoff.

The package shape is four-way, but implementation is not. The edge packages currently contribute only their package docstrings.

The profile boundary

The plugin is project-independent by contract. A consuming project supplies a profile: documents written in the dialect and naming that project's own types and fields. The profile stays with the consumer. This plugin interprets the dialect; it does not read, import, default, or require a particular profile. Illustrative nouns are allowed in docs and fixtures, but they are examples, not package vocabulary.

The dialect: three document kinds

A profile has three document kinds. Each fact has one home: shape in type, presentation in view, and storage in source.

KindDeclaresAnswers
typeRecords, fields, values, constraints, and field meaningWhat may be written
viewLabels, order, grouping, formatting, links, and computed presentation entriesHow it is shown
sourcePaths, layouts, record keys, metadata keys, and generated-file metadataWhere it is written

type supports scalar kinds string, int, float, bool, id, and text; compound shapes list, map, ref, enum, and record; and annotations such as unit, meaning, sentinel, derived, and provenance.

The loader is fail-closed: unknown keys and malformed declarations raise ProfileError. A loaded profile becomes a Profile containing TypeSpec, ViewSpec, and SourceSpec objects. Corpus validation returns located Diagnostic objects, with errors separated from advisories.

Implemented shape

  • value-shaped types, keyed-map sources, and document metadata
  • typed refs, sourced and stored-integer enums
  • nested records, lists, maps, ranges, sizes, and total maps
  • discriminated variants and sparse extensible records

Implemented checks

  • shape_from with a foreign-schema adapter
  • partial_of layers and declared routes
  • covers, matches_files, and unique
  • ordered declarations, source layouts, and path-key obligations

The comments package: address, guard, classify

comments/ is the 0.7.1 addition. It treats an anchor as an address in the loaded corpus, not as YAML's &anchor/*alias syntax. A selector can denote a set; an anchor is the singular subset used by a persisted comment.

Address grammar and public types

SurfaceWhat it does
parse_selectorParses up to three slash-separated segments: type, record, and dotted field path. It accepts type and record wildcards, @doc, zero-based #N, predicates with =, !=, has, and in, plus map-key field wildcards.
parse_anchorUses the selector grammar but refuses wildcards and predicates because a persisted anchor must be singular.
evaluateExpands a parsed Selector into an Evaluation of concrete Point values and reports matched records.
resolve_anchorResolves one singular address to a ResolvedAnchor containing its concrete point, exact slice value, and record. An optional guard prevents an indexed row from silently retargeting.
contains, overlaps, intersectsCompare concrete paths and evaluation sets by containment and overlap.
Selector, Point, Evaluation, ResolvedAnchorNormalized selector, concrete corpus point, set evaluation, and guarded resolved slice types. Predicate is the parsed record-filter type.

Predicates compare against declared field shapes. Numeric comparisons are refused; legal operators are exactly =, !=, has, and in. Identity globbing is refused. A field wildcard expands declared map keys; a bare id map key remains advisory and uncheckable rather than inventing a legal set.

Comment errors

errors.py defines the address failure hierarchy: AddressError is the base class, SelectorError reports illegal selector text, and EvaluationError reports a legal selector with no unambiguous denotation in the corpus.

Persistent comments

TypeCurrent contract
CommentFrozen record with id, parsed singular anchor, text, state, created, guard, and mapping annotations. States are only open and resolved. Comment.create resolves the anchor and computes its guard.
CommentStoreDirectory-backed file-per-comment store. init validates or creates the root; load returns comments plus malformed-file diagnostics; write atomically writes YAML; resolve changes only state and preserves the guard.
CommentSetThe pair returned by a load: parsed comments and Diagnostic objects.

Hashing and staleness

hashing.py

  • canonical_bytes recursively normalizes mappings and preserves list order.
  • Absent values are distinct from present null values.
  • slice_hash returns a SHA-256 guard with the sha256: prefix.

staleness.py

  • check_anchors does not mutate stored guards.
  • OK means the current slice matches.
  • MOVED means the slice changed; UNRESOLVABLE means the address cannot resolve.
  • reanchor explicitly accepts the current slice.

Design boundary and current status

The binding note records an intended dispatcher boundary: it would be the only package importing content-pipeline-kit and would use its work-unit, execution, delivery, validation, and anchored-slice freshness machinery. That is design documentation, not a claim that the binding is implemented: current dispatch/ has only its one-line docstring.

  1. Schema dialect and corpus validation IMPLEMENTEDProfile loader, model, sources, corpus records, merge algebra, constraints, views, and diagnostics.
  2. Anchored comments IMPLEMENTEDSelector and anchor grammar, evaluation, containment predicates, comment store, canonical hashing, and staleness reports.
  3. Editor surface UNBUILTeditor/__init__.py is one docstring line. No node-side editor implementation is present.
  4. Dispatcher and pipeline binding UNBUILTdispatch/__init__.py is one docstring line. No planner, driver, or content-pipeline-kit import is present.
