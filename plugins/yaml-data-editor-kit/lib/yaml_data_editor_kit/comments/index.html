The anchor and comment model that stores guarded units of intent over a loaded corpus.

This package is the kit's anchor and comment model. It gives the editor a dialect for naming exact slices of a loaded corpus, a sha256 hash that guards each slice, and one YAML file per guarded unit of intent. The organizing split is singular versus set: an anchor names exactly one point (one type, one record, one field path), while a selector may widen to a set with wildcards and field predicates. A comment stores the guard of the slice it was filed against, so a corpus edit shows up as a stale comment instead of a silently drifted instruction. The file-per-comment store is the seam the dispatcher reads and writes.

Where to start

Open plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/comments/__init__.py first. It re-exports the whole public surface (address grammar, guard hashing, staleness checks, comment store), so you can place any function before reading a module.

Routes

  • File a guarded comment
    1. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/comments/store.py -- Comment.create() takes the anchor text and the live corpus
    2. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/comments/address.py -- parse_anchor() enforces the singular grammar, and resolve_anchor() pins the anchor to exactly one slice
    3. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/comments/hashing.py -- slice_hash() computes the sha256 guard create() stores on the comment
    4. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/comments/store.py -- CommentStore.write() persists the comment as one atomic YAML file
  • Check anchors after the corpus moves
    1. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/comments/staleness.py -- check_anchors() re-resolves every stored comment against the live corpus
    2. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/comments/address.py -- resolve_anchor() finds the slice each anchor still names
    3. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/comments/hashing.py -- slice_hash() compares the slice with the stored guard; the report comes back ok, moved, or unresolvable

The address dialect

  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/comments/address.py -- the selector and anchor grammar: canonical spellings, wildcards, predicates, and expansion into concrete points; open it for what an anchor may be and for every refusal the grammar enforces
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/comments/errors.py -- the two immediate failure classes: illegal selector text, or a legal selector with no unambiguous denotation in the corpus

Guards and staleness

  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/comments/hashing.py -- canonical YAML serialization of a resolved slice and its sha256 guard, the exact bytes a comment is compared against
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/comments/staleness.py -- classifies stored guards against a live corpus as ok, moved, or unresolvable, and re-anchors a comment to accept the current slice

The editor/dispatcher seam

  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/comments/store.py -- one atomic YAML file per comment: create, load, write, resolve, and rule, with a diagnostic for every malformed file; the record layout the dispatcher plans against
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/comments/__init__.py -- the package's full public surface in one file, the quickest map of what each module carries
  • yaml_data_editor_kit The YAML data editor kit for schema validation, anchored-comment dispatch, and the Databench editor boundary.
  • dispatch The anchored-comment dispatch: how open comments are planned and executed against the corpus this package guards.
  • schema The corpus and profile model every selector here evaluates against.
  • dialect.md The kit's dialect documentation: the readable counterpart to the grammar this package enforces.
