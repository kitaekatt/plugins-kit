The YAML data editor kit for schema validation, anchored-comment dispatch, and the Databench editor boundary.

This package is the library half of the YAML data editor kit, and it is deliberately project-independent. It reads a directory of YAML data files against a declared dialect profile, so every record carries a type, an identity, and a field-by-field check. A dispatch layer then turns anchored editorial comments into planned work units and executes them inline or as a background wave, refusing any write whose anchored slice has changed in the meantime. One small module exists only to say where the human editor stops being this package's concern. The comment model that carries the anchored intent has its own page one level down, and the plugin-level documentation sits one level up.

Where to start

Open dispatch/request.py first: the dispatch request YAML is the file seam the editor hands this package, and it names the corpus, the comment store, the run directory, and the driver a run receives. If your work is the dialect rather than execution, open schema/loader.py instead, because its fail-closed key checks define what a legal declaration is.

Routes

  • Check a corpus: schema/loader.py -> schema/corpus.py -> schema/validate.py, profile into records into findings.
  • Run the inline lane: dispatch/request.py -> dispatch/planner.py -> dispatch/run.py, a validated request through planned units to the run's attributed store.
  • Run the staged background lane: dispatch/background.py, with each worker entering through dispatch/worker_mount.py, and back to dispatch/background.py for status and finalize.
  • Turn a worker ambiguity into an open question: dispatch/worker_mount.py fail handler into dispatch/protocol.py.

Declaring and checking record shapes

  • schema/__init__.py - The two entry points a caller imports: profile loading and corpus validation.
  • schema/loader.py - Reads type, view, and source documents into the profile; an unknown key is an error, so a typo cannot silently drop a check.
  • schema/model.py - The object model a loaded profile becomes; open it when reading or extending a declaration's vocabulary.
  • schema/corpus.py - Reads the data files a profile names into addressable records, and settles which source owns each file and key.
  • schema/validate.py - Checks every record against its type and returns findings that name the file, the record, and the field.
  • schema/merge.py - The merge algebra for extensible types: how a child record combines with its ancestors, with cycles refused.
  • schema/adapter.py - Reads a foreign schema-as-data declaration through a type's adapter, for corpora that keep their own schemas as data.
  • schema/errors.py - The two failure channels: an exception for a broken declaration, collected diagnostics for data missing a legal one.

Turning anchored comments into applied edits

  • dispatch/__init__.py - The package facade; its import guard turns a missing content_pipeline dependency into one message that names the remedy.
  • dispatch/request.py - Loads the file-backed request that starts a run; every problem is a diagnostic, and paths resolve from the request file.
  • dispatch/planner.py - Groups open instruction comments into work units, mechanically by anchor or, when a backend is configured, through a model that merges whole units.
  • dispatch/run.py - The inline lane: plans units, executes them through content-pipeline-kit, and writes the machine slice of the run's attributed store.
  • dispatch/background.py - The staged background API, prepare through finalize; the run directory is reserved atomically so a failed prepare cannot strand a path.
  • dispatch/state.py - The durable, digest-authenticated dispatch plan a background run reconstructs from; tampered units or paths are rejected on load.
  • dispatch/worker_mount.py - The worker-side protocol mount: claim, read, submit, fail, each re-authenticated against the plan and rechecked for freshness.
  • dispatch/protocol.py - Turns a worker's terminal ambiguity failure into an open question comment, idempotently, so an interrupted worker cannot lose it.
  • dispatch/units.py - The shared prompt and response-validation source; when the inline lane and a worker disagree about a response, this file decides.
  • dispatch/adapter.py - Derives the execution adapter from a durable plan, so a background run replays with the same unit identity and prompts.

The editor boundary

  • editor/__init__.py - Code-free on purpose: Databench owns the browser surface, this kit ships no editor, and new work goes to the dialect or to the comment model's page.

Package root

  • __init__.py - One docstring line: the dialect, the comment model, dispatch, and the editor boundary.
