The YAML data dialect that declares and validates corpus type shapes and plans and executes anchored-slice transformations through inline and background LLM dispatch.

This is the Python package that sits between a project's YAML data files and whatever edits them. It does two jobs. The first declares what the data is allowed to look like and proves a corpus against that declaration, naming every problem with a file, a record, and a field. The second takes an anchored note about one slice of that data and turns it into a validated transformation, run inline in one process or as a staged background dispatch that workers settle one unit at a time. The two meet at a file-backed request, and a boundary module marks where the browser surface stops being this package's concern; the transformation half rides on the shared content-pipeline library and needs it present to run.

Where to start

Open plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/loader.py to see how the dialect reads a profile and refuses a bad declaration, or plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/run.py to follow one inline dispatch from request to applied result. The first is where shape and checking questions land; the second is where execution and staleness questions land.

Routes

  • Check a corpus against its profile
    1. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/loader.py load the profile
    2. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/corpus.py read every source into records
    3. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/validate.py collect the findings
  • Run one inline dispatch
    1. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/request.py read the request
    2. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/planner.py plan the units
    3. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/run.py run and apply them
  • Stage a background dispatch
    1. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/background.py prepare and reserve the run
    2. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/state.py write the authenticated plan
    3. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/worker_mount.py mount the worker protocol
    4. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/background.py run the wave and finalize

Read and declare the dialect

  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/__init__.py -- the package face; one docstring naming the four parts.
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/__init__.py -- the two entry points: load a profile, or validate a corpus.
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/loader.py -- the fail-closed profile loader; open it when a declaration is refused.
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/model.py -- the in-memory Profile and the spec dataclasses it holds.
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/errors.py -- two failure channels: a raised ProfileError, a collected Diagnostic.
  • Two more dialect files sit here: the extensible-merge algebra and the foreign-adapter shape reader.

Check a corpus against the profile

  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/corpus.py -- reads every declared source into addressable records off disk.
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/validate.py -- the validation pass; every finding names a file, a record, and a field.

Plan a dispatch from open comments

  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/request.py -- the file-backed request; the seam an editor hands this package.
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/planner.py -- groups open comments into units, mechanically or re-grouped by a model.
  • A units helper here renders each unit's prompt and its response validation.

Run the dispatch

  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/__init__.py -- the public API; one message names the missing shared-library remedy.
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/run.py -- the inline lane; runs each unit and writes the machine result.
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/background.py -- the staged lane; prepare, wave, status, and finalize a run.
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/state.py -- the authenticated durable plan a staged run reloads from.
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/worker_mount.py -- the worker protocol mount a staged worker runs under.
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/protocol.py -- turns a worker's terminal ambiguity into a durable question.
  • A small adapter builder here derives the worker-facing adapter from a plan.

Where the package stops

  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/editor/__init__.py -- a boundary in code: the browser surface is Databench's, and nothing here imports it.
  • yaml-data-editor-kit The plugin-level documentation and packaging for the YAML data editor kit, covering the dialect spec, architecture notes, dispatch binding, and editor research.
  • comments The anchor and comment model that stores guarded units of intent over a loaded corpus.
