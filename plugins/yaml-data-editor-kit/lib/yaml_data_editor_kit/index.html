The YAML data dialect that declares and validates corpus type shapes and plans and executes anchored-slice transformations through inline and background LLM dispatch.

This library defines a project-independent YAML data dialect and the engine that transforms data through it. The schema half declares type shapes and validates a corpus against them. The dispatch half plans work units from anchored comments and executes them through llm-kit, either inline or as staged background workers with durable, authenticated state. A small editor package marks the boundary: the web surface that reads and writes this data lives in Databench, not here.

Where to start

Open plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/loader.py to understand what the dialect accepts and how a profile is assembled. Open plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/run.py to trace how a transformation executes end to end.

Routes

  • Inline dispatch
    1. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/request.py - the YAML request names corpus, comment store, run dir, and driver
    2. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/loader.py loads the profile; plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/corpus.py reads the data files
    3. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/planner.py groups open instruction comments into work units
    4. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/run.py generates, validates, and applies each unit's result
  • Background dispatch
    1. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/background.py - prepare: plan units, write durable state, register in the execution store
    2. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/state.py - the immutable plan authenticated by a SHA-256 digest
    3. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/worker_mount.py - each worker rechecks slice freshness before claim, read, submit, or fail
    4. plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/background.py - poll status, then finalize the run

Schema dialect

  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/__init__.py - the public API: load_profile and validate_corpus are the two entry points
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/model.py - the dataclasses: TypeSpec, FieldSpec, Profile, ViewSpec, SourceSpec
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/loader.py - parses type/view/source YAML documents into a Profile; fail-closed on unknown keys
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/corpus.py - reads data files per source layout into Records; resolves globs and source coexistence
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/validate.py - checks every record against its type; every finding names file, record, and field
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/merge.py - the extensible-type merge algebra: parent-first chain resolution with cycle detection
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/adapter.py - reads a foreign schema-as-data declaration through a type's adapter mapping
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/schema/errors.py - ProfileError (raised) and Diagnostic (collected); two separate failure channels

Dispatch: planning

  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/__init__.py - the public API and the import guard that names the llm-kit remedy on missing dependency
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/request.py - the file seam: a YAML request with corpus path, comment store, run dir, driver, and optional selection
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/planner.py - groups open comments into mechanical or model-grouped work units; the agentic path re-groups through the configured LLM
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/units.py - renders the prompt, parses the response, and builds the validation spec for each unit shape

Dispatch: execution

  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/run.py - inline lane: load, plan, generate, apply, finalize in one process
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/background.py - staged lane: prepare, run wave via Claude CLI, poll status, finalize
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/state.py - the immutable DispatchPlan with SHA-256 digest; tamper detection on every read
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/worker_mount.py - per-worker entry: authenticate against the plan, recheck freshness, then claim, read, submit, or fail
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/protocol.py - encodes a worker's terminal question as a bounded failure and materializes it into the comment store
  • plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/dispatch/adapter.py - builds the RunAdapter whose unit identity and prompts come from a durable plan

Boundary

plugins/yaml-data-editor-kit/lib/yaml_data_editor_kit/editor/__init__.py is an empty package. The web editor that browses and writes this data lives in Databench; nothing in this directory imports it or vice versa.
