The plugin-level documentation and packaging for the YAML data editor kit, covering the dialect spec, architecture notes, dispatch binding, and editor research.

This is the documentation and packaging for the yaml-data-editor-kit plugin; the code is one level down. The plugin is a library, not a tool. It defines a project-independent YAML dialect for describing a data corpus and ships the Python side that plans and dispatches the work a consumer queues against that corpus. The organizing idea is the profile boundary: a consuming project writes its own profile in the dialect, and nothing here knows one of the project's nouns. That boundary is why the dialect spec, the dispatch binding, and the editor research can live here at all, and why the browser editor is owned elsewhere and meets this kit only at files on disk.

Where to start

Open plugins/yaml-data-editor-kit/docs/dialect.md first -- it is the normative spec for the dialect the whole kit exists to define, and it is written for someone authoring a profile. Pair it with plugins/yaml-data-editor-kit/docs/architecture.html when you need the package boundaries and what is implemented versus planned.

The plugin envelope

  • plugins/yaml-data-editor-kit/CLAUDE.md -- the plugin charter in agent-facing form: the profile boundary, the file seam, and the four packages. Open it when you are changing the boundaries or the agent guidance.
  • plugins/yaml-data-editor-kit/.claude-plugin/plugin.json -- the marketplace manifest: name, version, the bootstrap dependency, and the published flag. Open it to change what the plugin advertises.
  • plugins/yaml-data-editor-kit/bootstrap.json -- provisioning: the shared library, the content-pipeline-kit plugin it pulls in, and the venv import checks. Open it to change what the kit installs.
  • plugins/yaml-data-editor-kit/pyproject.toml -- the Python package: name, version, the pyyaml and openai dependencies, and the lib package discovery. Open it to change the build.

The dialect spec

  • plugins/yaml-data-editor-kit/docs/dialect.md -- the normative spec: the three document kinds, the field types, and the annotations. The center of the kit; open it to read or extend the language.
  • plugins/yaml-data-editor-kit/docs/dialect-gaps.md -- the amendment record: each gap found writing the first profile, marked APPLIED, RESOLVED, or UNAPPLIED against the spec. Open it to see why a construct exists.
