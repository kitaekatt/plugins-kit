How Claude handles presence

The presence-kit plugin sets how Claude behaves when you are here, when you step away, and when you hand work over. You opt in by installing it. Every behavior has an id and can be turned off.

You're here

Present

The default. Your own message puts Claude back here.

  • Decides how to build it, routing, checks, and in-scope fixes
  • Asks you the decisions you have kept for yourself, what the product is for, and unclear intent that would waste real work
  • Never holds the prompt with a foreground wait, so you can talk anytime
You stepped away

Afk

You type /presence-kit:afk, Claude sees you are leaving, or you send nothing of your own for 10 minutes. "Go" does not count.

  • Keeps working on everything that doesn't need you
  • Parks your questions for the recap instead of stopping
  • Keeps updates short: nobody is reading
  • Notifies you only when it needs your input
You handed it over

Autonomous

Only on an explicit hand-over, or /presence-kit:autonomous. It records the goal and implies afk.

  • Decides everything not gated; asks only what a gate requires
  • Each load-bearing call gets a line in the recap
  • Ends when you revoke it or the goal is done

The plugin

One plugin, three skills. Typing the full plugin:skill form is how you invoke them.

/presence-kit:afk

You are stepping away. Claude covers running jobs, parks questions, and ends with a recap.

/presence-kit:autonomous

Hand work over to finish without you. Claude decides instead of asking and recaps when the goal is done.

/presence-kit:recap

A recap now, or the one that fits the trigger. Bare /recap is a Claude Code built-in, so the plugin one needs the full name.

How afk starts and ends

Claude decides who sent a prompt. A hook line only suggests it.

Afk starts: you say so
You type /presence-kit:afk, or your message contains a departure word such as "afk" (departure_words). A hook sets you afk right then and tells Claude before it answers; saying it again while you are afk keeps you afk. Claude recognizing that you are leaving, without the word, is the backup. All of this is afk-on-departure.
A wrong guess
The hook matches the word and nothing else, so a message that only talks about "afk", or an automatic prompt that contains it, can set afk by mistake. Claude is told what the hook did. When you are not leaving, it undoes the change with state set present and tells you once in one line.
Afk starts: you go quiet
You send no message of your own for afk_quiet_minutes (default 10). The stop hook decides this (afk-on-quiet).
Not you
A scheduled task, an agent report, a task notification, or another session's message is not you.
Back
Your own message while away always makes you present, except the message that set or kept you afk. With recap-on-return on, Claude gives the return recap; the stop hook asks for it if it is missing. With it off, you are present again and no return recap runs.

A typical session

What you experience from start to finish.

  • You're working with ClaudeIt asks you only what's genuinely yours to decide and handles the rest.
  • You type /presence-kit:afk or say afk, and leaveOr you go quiet for 10 minutes. Claude covers every running job that is not an agent, then keeps going.
  • While you're goneUpdates stay short because nobody is reading them. A question for you gets parked, and Claude carries on with everything else.
  • Only if it needs youYou get a push notification when your input is needed. No other pings.
  • The work runs outIf nothing is left running, the turn ends with one recap. In autonomous mode, Claude either keeps working or, if the goal is done, writes the final recap.
  • You come back to a recapClaude greets you with what finished, what was decided for you, what is waiting on you, and what is still running. Nothing is dropped: the recap carries every result, decision, question and running job.

Recap fits its trigger

There is no one-size recap. Its shape follows what started it.

TriggerCoversContains
You askRecent turns, widened if thinWhat got done; decisions I need from you
You returnEverything since you leftFinished, decided for you, waiting on you, and still running if jobs remain
Return after a recap—Nothing new. The standing recap is not repeated
Afk endsEverything since you leftFinished, decided for you, waiting on you. Written to be read cold
Autonomous doneEverything since the hand-overOutcome against the goal, each load-bearing decision, waiting on you

After a recap, if your reply has no content, Claude asks the open decisions in one batch. One ending gives exactly one recap. A recap is recorded with recap-done, which is what the stop hook checks: recap-shaped prose without it satisfies nothing.

Waiting on background work

The same in every mode (waiting-guard). The stop hook reads the list of running background tasks.

An agent or workflow is running

Nothing extra needed. The terminal shows working by itself.

Agent→Terminal shows working
A shell, Codex CLI, or external job is running

Claude adds a Monitor for progress. It also adds a waiter agent.

Job+Monitor+Waiter agent
The last line says itWhile owned work runs or a session cron is pending, the turn ends with "Waiting on <what>".
You can always talkClaude never holds the main session with a foreground wait.
Stalls get caughtThe waiter reports a job that stops making progress.

The waiter agent runs on waiter_model (default "haiku"), watches one job, reports one line, and changes nothing. Its completion wakes Claude.

What the stop hook nudges about

When Claude tries to stop, the hook checks four things. It acts only in a session you are attending.

You are back
Claude must give the return recap first (recap-on-return).
A job needs cover
A non-agent job runs with no waiter agent covering it (waiting-guard).
Work is running
The last line must be "Waiting on <what>" (waiting-guard).
Away and nothing is running
End with one recap. In autonomous mode: keep working, or recap if the goal is done (ending-recap).
One nudgeEvery unmet condition goes into a single message, so the recap is never crowded out.
Three at mostAfter three nudges for one prompt, the hook lets Claude stop and shows you what was unresolved.
Listed in the recapUnresolved checks appear under "Waiting on you" in the next recap.

Who decides what

Being here or away changes how a question reaches you, not who answers it.

WhenClaude decidesYou decide
Any modeImplementation, routing, verification, in-scope fixes, git you already authorized, calls that are cheap to reverse—
PresentThe aboveDecisions you've claimed, what the product is for, and costly ambiguity about your intent
AfkThe above, and keeps going on independent workThe same questions, parked for the recap
AutonomousEverything not gated; each load-bearing call gets a line in the recapNothing beyond what a gate requires
User onlyNeverPermissions, auto mode, publication gates, and standing prohibitions hold in every mode

Where awesome-kit:orchestrate is installed, its consultation policy owns seat routing for a load-bearing call. presence-kit does not change that policy.

Configuration

A small JSON file. Turn behaviors off, or change three values. Nothing else is configurable.

{"behaviors": {"recap-on-return": false}, "values": {"afk_quiet_minutes": 15}}
BehaviorWhat it does (all on by default)
afk-on-departureA departure word in your message sets you afk, and Claude is told so it can undo a wrong match; Claude recognizing you are leaving enters afk too
afk-on-quietQuiet for afk_quiet_minutes enters afk
autonomous-on-handoverAn explicit hand-over enters autonomous
recap-on-returnYour first message after afk gets the return recap
waiting-guardThe waiting rule, checked at the stop
ending-recapAn away turn with nothing running ends with one recap (in autonomous mode: or keeps working until the goal is done)
terse-while-away, park-questions, notify-for-inputShort updates, questions wait for the recap, pings only when you're needed
ValueDefaultMeaning
afk_quiet_minutes10Minutes of quiet before afk
departure_words["afk"]Words that set you afk when they stand alone in your message, in any case (not inside a longer name such as afk-on-departure); the list is replaced, not extended
waiter_model"haiku"Model for the waiter agent

Files, lowest to highest. A later file wins, key by key; lists and single values replace. An absent file is skipped.

Shippeddefaults/presence-kit.json in the plugin
You~/.claude/config/presence-kit.json ($CLAUDE_CONFIG_DIR/config/presence-kit.json when CLAUDE_CONFIG_DIR is set)
Project<project>/.claude/presence-kit.json, committed to share

JSON has no comments, so a key that starts with $comment is ignored at every level. An invalid file is reported loudly and never falls back: presence behavior stays unavailable until you fix it. Your own /presence-kit:afk and /presence-kit:autonomous still work when their behavior is off.

What you type

Three ways to steer it.

/presence-kit:afk

Type it when you are leaving. Claude switches to afk.

/presence-kit:autonomous

Hand over fully. /loop, routines, claude -p, and --bg never start it.

any message

You're back. Claude gives the return recap, answers, and you are present again.
