• hue-kit The hue-kit Claude Code plugin that describes Philips Hue scenes as editable layer stacks and syncs them with a bridge, including documentation, examples, command shims, and domain references.

The hue-kit scripts that provide the scene CLI, solve layered meta-groups, and guard plugin bootstrap setup.

Everything in this directory is the runnable half of the hue-kit plugin: a command-line front end for reading and writing Hue scenes, a solver that computes the smallest shared set of light groups the home's scenes need, the bridge-analysis primitives that feed that solver, and a bootstrap guard that stops a script before it runs where the plugin's dependencies are missing. The CLI is the single entry point; the solver and the primitives are reached through it, and each script re-execs itself under the plugin's provisioned interpreter before importing anything. No state lives here. The working YAML files and the generated report are written to the plugin data directory, so after a scene changes this directory needs nothing but a re-run.

Where to start

Open hue_kit_cli.py first: its docstring lists every verb, and every other file here is reached through it or through the guard it imports.

Routes

  • Read the scenes: hue-kit report -> scene-layers.py -> scene-meta-groups.py. The CLI hands the verb to the solver, which loads the primitives for the bridge reads and prints each scene as a layer stack.
  • Diff the YAML against the bridge: hue-kit validate -> scene-layers.py with --validate-design. The CLI runs the solver's per-light design check, read-only.
  • Write the stacks back: hue-kit apply -> scene-layers.py. The solver backs up each scene, then pushes the YAML layer stacks to the bridge; dry-run by default, --yes to write.
  • Every script's preamble: re-exec under the plugin's venv -> import the shared libraries -> bootstrap_guard.py's require_bootstrap guard. The guard re-execs the process under the plugin's venv first, and exits with the install-the-bootstrap message if provisioning never happened.

Scene CLI

  • hue_kit_cli.py -- the scene CLI: every verb, bridge IP discovery with the cloud-then-mDNS fallback, key and working-file resolution, and the two runners that hand one-verb commands to the solver. Open it to change or add a verb.

Meta-group solver

  • scene-layers.py -- the layered meta-group solver: it derives the smallest family of light groups that bakes every scene as an ordered layer stack, bakes each scene to verify the answer, and carries the write and validate paths behind the CLI's verbs. Re-run it whenever scenes are added or restyled.

Bridge primitives

  • scene-meta-groups.py -- the shared library the solver imports as smg: read-only CLIP v2 bridge reads, per-light signatures and clustering, CIE-xy and mirek to sRGB and HSL color math, zone-derived light groups, and the one HTML report renderer (layered_report) every hue-kit report goes through.

Bootstrap guard

  • bootstrap_guard.py -- stdlib-only, and it never imports bootstrap_lib: it reads the per-plugin bootstrap log to tell whether provisioning happened, carries the canonical error message (exit code 3), and re-execs the process under the plugin's venv so shared-library imports resolve. Vendored byte-for-byte to each plugin; a drift test keeps the copies in step, so a change here must be mirrored.
