The hue-kit Claude Code plugin that describes Philips Hue scenes as editable layer stacks and syncs them with a bridge, including documentation, examples, command shims, and domain references.

hue-kit describes a Philips Hue home's scenes as an ordered stack of layers and keeps that description in sync with a bridge in both directions. A scene is a default of OFF plus layers; each layer paints one named light group - a meta-group - a color and brightness, and the topmost layer covering a light wins, so over-painted lower layers make complement groups unnecessary. A solver certifies the smallest group vocabulary that can express every scene and emits the family that best fits the home's zones. The bridge is the source of truth, the working files are two editable YAML documents, and the human-facing view is a self-contained HTML report.

Where to start

Start with README.md: the human quickstart with install, bridge pairing, and the full verb table. If you came for the model rather than the commands, open skills/hue-domain/references/scene-layers.md instead; it is the full spec of layers, groups, and the sync operations.

Routes

  • First run: hue-kit discover → hue-kit pair → hue-kit start. Find the bridge, mint the application key, then let start build the YAML, render the report, and open it.
  • Setup by hand (what start automates): hue-kit report → hue-kit groups → hue-kit export → hue-kit render.
  • Restyle a scene from a conversation: edit the design YAML → hue-kit validate → hue-kit apply (dry run) → hue-kit apply --yes → hue-kit render. Everything is read-only against the bridge except apply --yes, and the report is the mandatory last step: a change not shown in it is a change not judged.

Plugin packaging

  • .claude-plugin/plugin.json - the manifest Claude Code installs from: name, version, keywords, and the dependency on the bootstrap plugin. Open it when install metadata is involved.
  • pyproject.toml - the host-side dependencies (requests, pyyaml, urllib3, zeroconf) that bootstrap syncs into the plugin venv; no package is built here.
  • bootstrap.json - the session-start contract: the minimum bootstrap version the call shape needs, the uv tool it installs, and the venv imports it verifies.
  • custom_bootstrap.py - the session-start check for an application key; when none is set it registers a deferred pairing nudge instead of failing every session, because minting a key needs a button press on the bridge.

Command shims

  • bin/hue-kit - the POSIX launcher that makes the hue-kit command work from any shell, because Claude Code puts a plugin's bin directory on PATH. It needs any Python interpreter only: the CLI re-execs itself into the bootstrap venv.
  • bin/hue-kit.cmd - the Windows equivalent, written to dodge the Store python alias.

Documentation

  • README.md - the human quickstart: the pitch, install, pointing the tool at a bridge, the verb table, and the environment-variable overrides.
  • CLAUDE.md - agent-facing guidance: the default flow, the verdict states, and the safety rules the agent follows while driving the CLI. Open it to tune how the agent behaves, not to learn the model.

The domain skill

  • skills/hue-domain/SKILL.md - the domain skill loaded for Hue work: the vocabulary, the behavioral guardrails, the per-verb routing, and the default flow the agent runs on a bare invocation.
  • skills/hue-domain/references/scene-layers.md - the operating reference: the layered model, the solver, the two config files, every sync verb, and template-name maintenance.
  • skills/hue-domain/references/hue-bridge-basics.md - CLIP v2 fundamentals for any bridge: discovery and pairing, the entity model, why scenes are definitions rather than live state, and xy-authoritative color.
  • skills/hue-domain/references/hue-beyond-scenes.md - bridge facts just outside the scene surface: the event stream's missing keepalive, the bridge-wide REST rate cap, silent Zigbee group misses, and light renames. Read it when a task touches runtime behavior.

Worked example

  • examples/scene-groups.yaml - a group registry for a 42-light home: a 6-group certified-minimum family defined as zone unions, with template names for each layer-stack sequence.
  • examples/scene-designs.yaml - the same home's 12 scenes as layer stacks, with authoritative xy color and readable hsl annotations.
  • examples/index.html - the rendered report: brightness-scaled swatches and layer stacks for every scene, with the config and source embedded in one file. The quickest view of what the plugin produces.

Treat the example as a worked reference, not as configuration: hue-kit init copies these three files into the working directory so a user's own bridge data replaces them.
