The task-system implementation: task lifecycle and discovery, the model-answers engine, programmatic export, and manager operations.

This is the Python package behind the task-kit CLI verbs. Four job groups define its shape: task lifecycle and discovery, the model-answers engine, programmatic export, and manager operations. The answers engine is the largest area, spanning a pass runner, a model-dispatch chain, a record store, and the CLI that drives them. Each verb module is a thin shell over a domain module, so the verb file states the contract and the domain module carries the behavior. The package imports llm-kit lazily, so every verb works without a model until one actually answers.

Where to start

Open plugins/task-kit/skills/task/scripts/task_system/discovery.py for the task-enumeration algorithm that export, listing, and the answers engine all read through. For the answers subsystem, plugins/task-kit/skills/task/scripts/task_system/answer_engine.py is the pass lifecycle.

Routes

  • Run an answers pass
    1. plugins/task-kit/skills/task/scripts/task_system/answers_cli.py drives the engine pass
    2. plugins/task-kit/skills/task/scripts/task_system/answer_engine.py prepares, answers, and commits per repository
    3. plugins/task-kit/skills/task/scripts/task_system/answer_chain.py dispatches each question through llm-kit with cost-class gating
  • Export task facts
    1. plugins/task-kit/skills/task/scripts/task_system/export_cli.py parses the verb and builds the envelope
    2. plugins/task-kit/skills/task/scripts/task_system/export.py reads task folders through the domain modules and assembles the JSON payload
    3. plugins/task-kit/skills/task/scripts/task_system/discovery.py supplies the task enumeration
  • Negotiate a manager mutation
    1. plugins/task-kit/skills/task/scripts/task_system/manage.py validates the action, checks the content revision, and acquires the lock
    2. plugins/task-kit/skills/task/scripts/task_system/authoring.py applies the plan.md edit and proves the result in memory before any byte is written

Task discovery and listing

  • plugins/task-kit/skills/task/scripts/task_system/__init__.py package docstring; names the design contract and the step progression of shipped verbs.
  • plugins/task-kit/skills/task/scripts/task_system/discovery.py the spec section-8 algorithm: folder crawl plus reference scan, canonicalize, dedupe, classify, project to records. Open when a task is missing from list output.
  • plugins/task-kit/skills/task/scripts/task_system/listing.py the shared projection for list and review: TaskView, status sections, project groups, and summary fingerprinting.

Task lifecycle verbs

  • plugins/task-kit/skills/task/scripts/task_system/init.py creates a task folder with scaffolding; the invariant is that the output always validates as an active task or the folder is removed.
  • plugins/task-kit/skills/task/scripts/task_system/location_ops.py archive, delete, and move. Commits to VCS before removal; parks the folder when version control will not carry it.
  • plugins/task-kit/skills/task/scripts/task_system/authoring.py pure plan.md edits: adds an item and its section, proves the result in memory, and refuses before writing anything.

Model-answers engine

  • plugins/task-kit/skills/task/scripts/task_system/answer_engine.py one pass per repository in three phases (prepare, answer, commit); honours stop and deadline; never holds the lock across a model call.
  • plugins/task-kit/skills/task/scripts/task_system/answer_chain.py dispatches a question through llm-kit with two-phase cost-class gating, persistent exclusion of failed entries, and strict answer validation (JSON, ASCII, schema, grounding).
  • plugins/task-kit/skills/task/scripts/task_system/answer_scripts.py deterministic script answerers (activity, task commits) computed on read and never stored.
  • plugins/task-kit/skills/task/scripts/task_system/answer_store.py YAML record files, ownership by machine fingerprint, and the deterministic choice rule among competing records.
  • plugins/task-kit/skills/task/scripts/task_system/answers_cli.py the task-kit answers verb: refresh, status, prune, protocols. One JSON document per outcome.
  • plugins/task-kit/skills/task/scripts/task_system/answers_config.py two-layer configuration (shipped defaults, fleet override) for the model preference list and effort.
  • plugins/task-kit/skills/task/scripts/task_system/answers_types.py frozen dataclasses (Question, InputBundle, Answerer, Catalog, RepoLog, ScriptContext) that the rest of the subsystem codes against.

Programmatic export

  • plugins/task-kit/skills/task/scripts/task_system/export.py builds JSON payloads of task facts for external consumers; reads through discovery, validation, items, and sessions modules.
  • plugins/task-kit/skills/task/scripts/task_system/export_cli.py the task-kit export verb; every outcome writes exactly one JSON document to stdout.

Manager operations

  • plugins/task-kit/skills/task/scripts/task_system/manage.py negotiated mutations (task-create, item-add, item-complete, session-dismiss) with four-file revision checks and per-repository locking.

Machine and process identity

  • plugins/task-kit/skills/task/scripts/task_system/machine.py host id, SHA-256 fingerprint of the OS machine id, and OS instance; the ownership keys for answer records and session files.
  • plugins/task-kit/skills/task/scripts/task_system/datadir.py resolves the bootstrap data directory from the venv this process runs in; refuses a redirected data tree that does not match.
  • plugins/task-kit/skills/task/scripts/task_system/harness.py identifies the calling Claude Code session: session id, live ancestor PID check, and transcript lookup.
  • plugins/task-kit/skills/task/scripts/task_system/legacy_stop.py stops a dashboard server started by an earlier task-kit version; verifies identity before signalling, refuses on foreign processes.
