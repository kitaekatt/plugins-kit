The task-system implementation: task lifecycle and discovery, the model-answers engine, programmatic export, and manager operations.

The task_system package is the Python runtime behind every task-kit CLI verb. It implements the answers pipeline that dispatches structured questions to an LLM, validates returned JSON against per-question schemas, and commits results as per-machine YAML records. The remaining modules handle task lifecycle operations, discovery and listing, JSON export, and identity plumbing. Together they form the subsystem that task.py dispatches into when a user runs any task-kit command.

What this package does

This package is the implementation behind every task-kit verb. The largest subsystem is the answers pipeline: it dispatches structured questions to an LLM, validates the returned JSON against a per-question schema, and commits the result as a per-machine YAML record. The remaining files split into lifecycle verbs (creation, archival, relocation, plan.md editing), discovery and listing, JSON export, and identity plumbing (machine fingerprint, data directory, harness session). A set of supporting internals handles schemas, path resolution, validation, session tracking, and git operations.

Where to start

Open plugins/task-kit/skills/task/scripts/task_system/__init__.py for the spec reference, then follow imports into the subsystem you need. For the answers workflow, plugins/task-kit/skills/task/scripts/task_system/answers_cli.py is the command-line entry that wires config, chain, and engine together.

Routes

  • Trace an answer end-to-end
    1. plugins/task-kit/skills/task/scripts/task_system/answers_cli.py -> plugins/task-kit/skills/task/scripts/task_system/answer_engine.py -> plugins/task-kit/skills/task/scripts/task_system/answer_chain.py -> plugins/task-kit/skills/task/scripts/task_system/answer_store.py
    2. CLI verb -> one pass (skip, prepare, answer, commit) -> model dispatch with cost-class phases -> record written and committed
  • Create then archive a task
    1. plugins/task-kit/skills/task/scripts/task_system/init.py -> plugins/task-kit/skills/task/scripts/task_system/location_ops.py
    2. Scaffold a valid active task folder, then archive it (git commit + remove, or park when VCS will not carry it)
  • Export task facts as JSON
    1. plugins/task-kit/skills/task/scripts/task_system/export.py -> plugins/task-kit/skills/task/scripts/task_system/export_cli.py
    2. Build the payload from domain readers, then serialize one JSON document to stdout

Answers pipeline

  • plugins/task-kit/skills/task/scripts/task_system/answers_cli.py -- CLI entry: refresh, status, prune, protocols verbs
  • plugins/task-kit/skills/task/scripts/task_system/answer_engine.py -- One pass over a repo: skip, prepare, answer, commit phases
  • plugins/task-kit/skills/task/scripts/task_system/answer_chain.py -- Model dispatch with cost-class phases; llm-kit imported lazily
  • plugins/task-kit/skills/task/scripts/task_system/answer_store.py -- Record layout, ownership by machine, choice among records, coverage
  • plugins/task-kit/skills/task/scripts/task_system/answer_scripts.py -- Deterministic script answers (activity, task_commits); never stored
  • plugins/task-kit/skills/task/scripts/task_system/answers_config.py -- Shipped defaults and fleet config layer
  • plugins/task-kit/skills/task/scripts/task_system/answers_types.py -- Frozen data types: Question, Catalog, RepoLog, ScriptContext

Task lifecycle and discovery

  • plugins/task-kit/skills/task/scripts/task_system/init.py -- Create a task folder with scaffolding; validates or removes on failure
  • plugins/task-kit/skills/task/scripts/task_system/location_ops.py -- Archive, delete, move; handles git and non-git VCS paths
  • plugins/task-kit/skills/task/scripts/task_system/discovery.py -- The section-8 algorithm: folder crawl plus reference scan
  • plugins/task-kit/skills/task/scripts/task_system/listing.py -- Shared projection for list and review output
  • plugins/task-kit/skills/task/scripts/task_system/authoring.py -- Pure plan.md text edits; verifies in memory before any write
  • plugins/task-kit/skills/task/scripts/task_system/manage.py -- Negotiated task-domain operations for an external manager

Export

  • plugins/task-kit/skills/task/scripts/task_system/export.py -- Task facts as JSON documents for a consumer program
  • plugins/task-kit/skills/task/scripts/task_system/export_cli.py -- The task-kit export command line, envelope, and exit codes

Identity and plumbing

  • plugins/task-kit/skills/task/scripts/task_system/machine.py -- Host id, 16-hex fingerprint, OS instance
  • plugins/task-kit/skills/task/scripts/task_system/datadir.py -- Bootstrap data directory resolved from the venv
  • plugins/task-kit/skills/task/scripts/task_system/harness.py -- Claude Code session identity, process verification, transcript lookup
  • plugins/task-kit/skills/task/scripts/task_system/legacy_stop.py -- Stop a legacy dashboard server (sunset after one minor)

Supporting internals

  • 27 additional modules covering schemas, path resolution, validation, session tracking, mutation primitives, plan-section parsing, task-item reading, git operations, and related plumbing.
