The task skill: data model, CLI verbs, operational protocols, design rationale, and the answers question catalog.

This is the task skill of the task-kit plugin: the data model, the sixteen CLI verbs, and the operating protocols for tracking work as folders. A task is a folder whose task.yaml record is the source of truth; the references embedded in documents are inert pointers, and every operation names its task by ref. State, discovery, and durability all derive from where a folder lives -- ephemeral and machine-local under tmp, version-controlled under dev/tasks -- so no master list is ever stored. The material splits into the dispatch surface, one reference per protocol, the design rationale, and the question catalog the answers engine works over. The Python implementation behind the verbs has its own page; everything around it is here.

Where to start

Open plugins/task-kit/skills/task/SKILL.md first: it carries the data model in short form, the exact venv invocation, and the route table that sends each capability to its reference. Read plugins/task-kit/skills/task/references/core-contracts.md next when a finding or a model detail needs expansion.

Routes

  • Work a task
    1. plugins/task-kit/skills/task/scripts/task.py work <ref> -- any error or warning blocks; on pass the session is registered and the initialization block is emitted.
    2. plugins/task-kit/skills/task/references/work-and-hand-off.md -- invoke every emitted Skill line in printed order, then start the first action in the same turn.
  • Hand a task off
    1. plugins/task-kit/skills/task/references/work-and-hand-off.md -- rotate the folder and run update until findings are clean, then self-verify it cold.
    2. plugins/task-kit/skills/task/scripts/task.py sessions release <ref> -- commit and push the task state first, then release the registration.
    3. End the turn with the two-line baton; only a user-invoked hand-off reaches it.
  • Triage the backlog
    1. plugins/task-kit/skills/task/references/task-triage-protocol.md -- list everything open and deferred, then run a read-only audit per task, oldest first.
    2. Present one ruling at a time and apply it with archive, close, defer, update, merge, or a reviewed keep.
  • Refresh the answers
    1. plugins/task-kit/skills/task/questions/catalog.yaml and plugins/task-kit/skills/task/defaults/answers.yaml set the question list and the model chain.
    2. plugins/task-kit/skills/task/scripts/task.py answers refresh -- answer the pending questions per repository, committing only this machine's answer files.
    3. plugins/task-kit/skills/task/references/task-export-protocol.md -- the normative contract for the JSON documents a consumer reads.

The CLI

  • plugins/task-kit/skills/task/scripts/task.py -- the front door to the sixteen verbs; the implementation package it imports has its own page.
  • plugins/task-kit/skills/task/scripts/bootstrap_guard.py -- the vendored, stdlib-only guard: it detects a missing bootstrap provision and re-execs the script into the plugin's venv.
  • plugins/task-kit/skills/task/scripts/task_session_start.py -- the SessionStart hook entry: it restamps registrations on resume, re-keys them on clear, then publishes the changed files.
  • Run every verb from the project root or pass --root; sitting inside a task folder breaks ref resolution.
