Multi-agent code review for local git changes: partitions a diff into chunks, fans out parallel reviewer and validator subagents, and renders confirmed findings as markdown.

The git-code-review skill is a multi-agent pipeline that reviews local git changes. It partitions a diff into chunks, launches parallel reviewer subagents per role and chunk, validates each flagged issue with an independent agent, and renders confirmed findings as markdown. The default mode runs in the background so the calling agent keeps working while a runner subagent executes the full procedure. The skill also integrates with md-domain for specialist Markdown auditing and supports path-scoped pre-submit reminders authored in the project instruction file.

Where to start

Start with plugins/git-kit/skills/git-code-review/SKILL.md -- the background_review technique is the main thread for most sessions and needs no reference. Open plugins/git-kit/skills/git-code-review/references/full-review.md only when running --inline or debugging the runner.

Routes

  • Background review (default)
    1. plugins/git-kit/skills/git-code-review/SKILL.md -- pick target, freeze the snapshot with snapshot_review.py
    2. Launch one background runner; it follows plugins/git-kit/skills/git-code-review/references/full-review.md in runner mode
    3. Present findings, record declines, apply accepted fixes, review deltas
  • Inline review
    1. plugins/git-kit/skills/git-code-review/SKILL.md with --inline -- runs plugins/git-kit/skills/git-code-review/references/full-review.md steps 0-9 in the foreground
  • Resolve review profiles
    1. plugins/git-kit/skills/git-code-review/references/configuration.md -- three-layer merge of reviewer rosters, per-entry model-and-effort declarations, and validator assignments

Skill contract

  • plugins/git-kit/skills/git-code-review/SKILL.md -- the technique definition: triggers, scope, the background_review procedure, and its checklist. Read this first in every session.

Review execution

  • plugins/git-kit/skills/git-code-review/references/full-review.md -- the full multi-agent procedure (steps 0-9) the runner and inline paths follow: profile resolution, diff preparation, reviewer fan-out, validator dispatch, submit-gate discharge, and markdown rendering.

Profile and model configuration

  • plugins/git-kit/skills/git-code-review/references/configuration.md -- how reviewer rosters, model entries with per-entry effort, and validator models are resolved from three config layers (shipped, user, project) at review time.

Subject-lens Markdown audit

  • plugins/git-kit/skills/git-code-review/references/md-domain-review.md -- how claimed **/*.md files are routed to md-domain detect lanes (top-level instruction file, skill definitions, skill references, project docs) with triviality gating and version-skew fallbacks.

Declined-findings ledger

  • plugins/git-kit/skills/git-code-review/references/declined-ledger.md -- the durable advisory memory that collapses previously-declined findings on re-run, keyed by a normalized fingerprint rather than line numbers or wording.

Submit-gate authoring

  • plugins/git-kit/skills/git-code-review/references/submit-gates.md -- the author-facing guide for writing path-scoped pre-push reminder blocks that the review detects and discharges.
