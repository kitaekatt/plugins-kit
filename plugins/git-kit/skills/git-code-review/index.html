Multi-agent code review for local git changes: partitions a diff into chunks, fans out parallel reviewer and validator subagents, and renders confirmed findings as markdown.

A multi-agent code review of local git changes: the review infers a diff range from workspace state, splits the diff into on-disk chunks of at most 1 MB, and runs one reviewer subagent per role and per chunk, all in parallel across the branch. Each flagged issue is validated by an independent subagent before it can surface, and the confirmed findings render as a markdown report; the diff chunks and bundle stay as transient scratch, while declined findings persist in a small durable ledger. The skill is one long generated contract beside four reference documents, each carrying the operational detail of one named mechanism: reviewer profile configuration, the ledger, the Markdown subject-lens pass, and submit-gate authoring. Every file here is machine-generated from a single upstream generator: to change the review behavior, edit the generator and rerun it rather than the file. The review covers the local working copy and refs only; Perforce CLs and remote PRs by URL are out of scope.

Where to start

plugins/git-kit/skills/git-code-review/SKILL.md is the file to open first: its numbered steps, 0 through 9, name every mechanism the review runs, and each step points at the reference document that carries that mechanism's operational detail.

If a review stops at profile resolution, or you want to change a reviewer roster or an effort level, open plugins/git-kit/skills/git-code-review/references/configuration.md instead.

Routes

  • Run a pre-push review
    1. Profile resolution resolves the merged profile table; a configuration finding here stops the review before the diff is prepared.
    2. Diff preparation fetches the diff, splits it into chunks on disk, and reports the range, the changed files, the submit gates, and any untracked or unstaged files you can fold in before the reviewers spawn.
    3. Reviewer subagents run once per role and chunk in parallel (inline, or through the Workflow tool when the lane count tops six), and an independent validator re-checks each finding before it surfaces.
    4. Confirmed findings render as markdown; the findings the author declines are written back to the declined ledger so a re-run against the same change renders them collapsed.
  • Fix a profile configuration error
    1. Run the configuration check; it lists every incomplete entry (layer, file, offending record) and exits without starting a review.
    2. Repair the named layer: the shipped defaults, the per-user file, or the per-project file, following the merge rules in plugins/git-kit/skills/git-code-review/references/configuration.md.
    3. Rerun the check until it is clean, then start the review again.
  • Trace a Markdown finding
    1. When skills-kit's md-domain skill is available in the session, the diff preparation step claims every changed Markdown file out of the generic reviewer fan-out.
    2. md-domain's detect lanes then audit the claimed files (one lane for agent-guidance docs, one for skill contracts and their references, one for project docs); the routing, the triviality gate, and the version-skew fallbacks are in plugins/git-kit/skills/git-code-review/references/md-domain-review.md.
    3. A typo-sized change is skipped by the mechanical triviality gate and reported as checked without an audit, so a small edit does not burn a full pass.
  • Author a submit gate
    1. Add a gate block to an agent-guidance file in a directory you want gated, using the format and the scope-path semantics in plugins/git-kit/skills/git-code-review/references/submit-gates.md.
    2. The next review whose range touches the scope surfaces the gate verbatim and records one verdict per gate: met, not applicable, not met, or needs the user.
    3. A not-met verdict is a finding, so the report does not present the change as clean until it is discharged.
