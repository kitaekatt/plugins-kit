• workflow-kit Workflow Kit plugin that adds a declarative .workflow.yaml compiler plus script and OpenRouter node strategies to the native Workflow tool

Workflow Kit library that validates workflow YAML and compiles it to Claude Code Workflow tool scripts

This is the compiler core of the workflow-kit plugin. A human authors a workflow as YAML; this library validates it into a typed document and compiles that document to the JavaScript the Claude Code Workflow tool executes, built from agent(), parallel(), and pipeline() calls plus the node-strategy calls for shell commands and OpenRouter model calls. The library never runs a workflow itself: it emits a script, and the plugin's skill hands that script to the tool. The files split by stage of that pipeline, so the directory reads as a short chain -- public surface, validation, emission -- rather than a pile of utilities.

Where to start

Open __init__.py first: its docstring names the four public exports and states the load-then-compile model in one paragraph, and every other file here hangs off those two calls. If you arrived chasing a failure, jump to the Contents group for the stage where it happened.

Routes

  • Compile a document: loader.py reads the YAML and hands the raw mapping to WorkflowDoc.parse in model.py; compiler.py then walks the validated document while expr.py compiles each {{ ... }} into a live expression in the emitted script.
  • Resolve a model declaration: model.py parses each model: field through declarations.py; agent steps compile to the first Claude core id in declaration order, and openrouter steps pass their declaration to the node runner unchanged.

Public surface and error type

  • __init__.py -- the package front door: the four exports (load_workflow, compile_doc, WorkflowDoc, WorkflowError) and the load-then-compile model. Open it to remind yourself what the rest of the plugin may call.
  • errors.py -- the single WorkflowError every validation, parse, and compile failure raises, with a message that names where in the document the problem is. Open it when catching errors or checking what a failure message can say.

YAML to a validated document

  • loader.py -- reads a .workflow.yaml path and hands the parsed mapping to the model; the only place file-not-found and malformed-YAML errors are raised. Open it to see how a path becomes a document.
  • model.py -- the typed model and the whole grammar: the four step kinds (agent, pipeline, script, openrouter), fan-out and pipeline shapes, reserved names, and unknown-key rejection at every level. The file to open when a field is rejected or you want to know what a step may contain.

Document to the emitted script

  • compiler.py -- emits the Workflow tool script: the meta block, the schema constants, the inputs normalization, one statement per step, and the inlined node-strategy preamble whenever a script: or openrouter: step is present. The main file when the output looks wrong. The wkScript and wkOpenRouter calls it emits are executed by the plugin's executor rather than this library, so tracing a real run means going up one page.
  • expr.py -- the {{ ... }} expression mini-language, compiled to live JavaScript instead of rendered at compile time, with a Scope that tracks which step results, items, and inputs are in reach. Open it to see which references are legal and what an unknown one does.
  • declarations.py -- model-declaration parsing and compile-time routing: agent steps take the first Claude core id in declaration order, and a declaration with no core id is a compile error that itemises each declared id. It relies on the bootstrap plugin's model-declaration helper, and its error messages name the repair.
