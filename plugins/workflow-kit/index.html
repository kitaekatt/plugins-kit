Workflow Kit plugin that adds a declarative .workflow.yaml compiler plus script and OpenRouter node strategies to the native Workflow tool

This plugin layers declarative workflow authoring and two cheap node strategies on top of Claude Code's native Workflow tool and never reimplements execution. A human authors a durable workflow as a YAML file; deterministic Python validates it and compiles it to a native script that only the native tool runs. Hand-written scripts get the same power through node strategies: a deterministic shell command, or a non-Claude model call, run by one small haiku agent that returns only file metadata, so payloads travel on disk and bypass model context. The layout follows that split: a skill that indexes the format docs, two runner scripts, one executor agent, and a matched example set.

Where to start

Start with skills/workflow-kit/SKILL.md: it indexes the reference docs by task and carries the plugin-venv python path and the exact compile, validate, and run commands. For the shape before the rules, open examples/review-changes.workflow.yaml instead.

Routes

  • Compile and run a workflow: read skills/workflow-kit/references/workflow-yaml.md, compile with scripts/compile_workflow.py using -o, then hand the compiled path and args to the native Workflow tool.
  • Validate only: run scripts/compile_workflow.py with --validate-only; exit 0 means OK, exit 1 prints the located error.
  • Wire a node strategy by hand: read skills/workflow-kit/references/node-strategies.md, paste skills/workflow-kit/references/preamble.js into the native script, and let its helper run scripts/openrouter_run.py under the plugin venv python.

The skill index

  • skills/workflow-kit/SKILL.md - the task index for the plugin: coverage, the plugin-venv python path, and the exact commands. Open it first when a task lands.

The workflow format and node docs

  • skills/workflow-kit/references/workflow-yaml.md - the declarative YAML format (v1), the compile, validate, run, and scaffold procedures, and the reserved inputs node steps expect. Open it when authoring or debugging a workflow.
  • skills/workflow-kit/references/contract.md - the node contract: payloads write to $OUT and only exit code, size, and hash come back, so routing rides the small status, never the file body. Open it when placing a step's output.
  • skills/workflow-kit/references/node-strategies.md - the script and openrouter command templates, the model-declaration rules, and when a node strategy is the wrong tool. Open it when adding a deterministic or non-Claude step.
  • skills/workflow-kit/references/preamble.js - the helpers you paste into a hand-written native script to build the node calls, inlined because such scripts cannot import. Open it when wiring nodes outside the compiler.

The compiler and the node runner

  • scripts/compile_workflow.py - the CLI that validates a declarative workflow and emits the native script, or validates only. Open it when a compile error needs reading.
  • scripts/openrouter_run.py - the runner behind every openrouter node: one non-Claude model call through the llm-scripting-kit declaration API, reply written to $OUT with a small status file beside it. Open it when a model call fails.

The library both scripts import for the real validation and compilation lives in the sibling workflow_kit_lib directory, which has its own page; go there for the format rules themselves.

The node executor

  • agents/workflow-kit-agent.md - the haiku agent that runs a node's single shell command verbatim, never reads the output file, and returns only its metadata. Open it when a node's behaviour is in question.

Worked examples

  • examples/node-strategies.workflow.yaml - the declarative twin of the hand-written example below: a script node and an openrouter node feed one reasoning node. Open it to see the shape before authoring your own.
  • examples/node-strategies.example.js - the same workflow hand-written as a native script with the preamble inlined. Open it to see what the compiler generates.
  • examples/review-changes.workflow.yaml - a multi-step review that pipelines three dimensions and fans out over findings in parallel. The reference for schemas, pipelines, and fan-out.
  • examples/scripts/wordcount.py - the tiny deterministic script the example nodes run, stdlib only. A minimal script-strategy payload to imitate.

Packaging and provisioning

  • .claude-plugin/plugin.json - the marketplace manifest: name, version, description, keywords, and the bootstrap dependency. How the plugin is published.
  • bootstrap.json - the provisioning edges: requires bootstrap 0.129.0, auto-installs the llm-scripting-kit plugin, and declares the shared imports linked onto the plugin venv. Open it when the venv or a shared import is missing.
  • pyproject.toml - the Python package metadata: version, the pyyaml and openai dependencies, and the package layout. Open it when a dependency question comes up.
  • README.md - the human-facing summary of what the plugin does and why payloads bypass model context. Hand it to someone new.
  • .gitignore - keeps compiled workflow scripts out of version control, since they regenerate from the YAML. Open it when a stray generated file shows up.
