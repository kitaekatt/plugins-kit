The job-kit package that runs heterogeneous agent jobs, records durable runs in SQLite, and manages endpoint selection and worktree isolation.

This is the Python package behind the job-kit command line. A jobs file declares a set of heterogeneous agent jobs, each with a prompt, a models declaration, and a command-shaped acceptance contract. The package runs those jobs through a worker pool, routes each one to the first usable endpoint, records every attempt in a SQLite ledger, and can give each attempt its own detached git worktree. Because state is durable in the ledger and the worktree root, a run can be interrupted, inspected, and resumed later. One shared library from the llm-scripting-kit plugin is the completion seam everything here calls, and the package guards that import so a broken environment fails with a named fix instead of a bare import error.

Where to start

Open cli.py first: its four subcommands, JSON snapshots, and documented exit codes say what a caller can do from the outside, and each subcommand names the function to follow next.

Routes

  • Run a jobs file: cli.py -> run.py -> select.py -> store.py. The parsed file enters the runner's pool, selection takes the first usable endpoint for each attempt, and the ledger records the attempt and its acceptance.
  • Resume an interrupted run: cli.py -> run.py -> store.py. Resume reads the durable snapshot and re-runs the non-terminal jobs; a job in a terminal state refuses every later attempt.
  • Reclaim attempt worktrees: cli.py -> workspace.py -> store.py. The garbage collector reads the ledger's workspace state to decide which worktrees are eligible.

Driving the package

  • __init__.py -- the package facade: re-exports the public names and guards the llm-scripting-kit import so a missing or too-old shared library fails with a named fix.
  • cli.py -- the command line: the run, status, resume, and gc subcommands with JSON snapshots and four documented exit codes.

Job definitions

  • model.py -- the YAML shape and the records: Job, Prompt, Contract, WorkspaceSpec, and the job and run states. Open it when a jobs-file key is rejected or a field's shape is unclear.

Execution

  • run.py -- the runner: a worker pool over the completion seam, halt classification, and contract execution with timeout. The heart of a run and the largest file here.
  • select.py -- endpoint selection: probes the shared library for the symbols it needs, then takes the first usable entry of the pace-ordered declaration. Its error floor lists every declared entry and its disposition.

Durable state

  • store.py -- the SQLite ledger: schema migrations, per-connection WAL with busy-timeout scaling, and the terminal-state guard. Open it when the ledger shape or resume behavior is in question.
  • workspace.py -- worktree isolation and garbage collection: captures the base ref at run start, creates one detached worktree per attempt, and reclaims eligible worktrees.
